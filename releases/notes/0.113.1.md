# Winter 0.113.1

## Sessions on a GPT model stay on the provider that was chosen for them

A session that Winter placed on your Codex subscription could, on its next turn, be run
through a stored OpenAI API key instead — and then fail with "model `openai/gpt-5.6-terra`
declares no reasoning effort vocabulary". This hit anyone who migrated from Norma with both a
Codex login and an OpenAI key, and it broke the assistant conversation and any chat on Terra.

The daemon now honours the provider the router decided for the session whenever that
provider holds a credential. Nothing changes for installs with a single key.

Coming next: provider-qualified model tags (`codex-oauth/gpt-5.6-terra` vs
`openai/gpt-5.6-terra`) so a model on two providers is never ambiguous again, and complete
reasoning-effort vocabularies for the OpenAI catalog rows.
