# Winter 0.117.0

## Winter models and Claude share one setup

- **One home for both runtimes.** Skills, agents, commands, output styles, plugins, MCP servers
  and settings now live in `~/.winter/sdk`, in Claude Code's own format, and every session reads
  them the same way whether it runs a Winter model or Claude. Your own skills and a trusted
  project's skills now reach sessions.
- **Your existing setup moves over by itself.** The first launch migrates `~/.winter` into the new
  layout, keeps backups under `~/.winter/migration`, and leaves links at the old paths. A home in
  a custom location migrates with `winter migrate --sdk-home`, which also offers `--status`,
  `--resume` and `--rollback`.
- **Both runtimes read one project folder**, the project's `.winter/`, and only once you trust the project. Claude
  sessions never read a repository's `.claude/`, `CLAUDE.md` or `.mcp.json`. A linked git
  worktree loads its own `.winter/`, and trust follows the repository it belongs to.
- **Plugins use Claude Code's format.** `winter plugin install <folder>` installs from a local
  marketplace, and a plugin's skills and hooks work on both runtimes. Winter-only extras live in
  `winter-plugin.json`.
- **MCP servers work at all three scopes:** `winter mcp` adds them at local, project or user scope, and a session's MCP tools
  are offered to the model from its first turn. A session may take up to 2 seconds longer to
  start its first turn while configured MCP servers connect, the same as Claude Code.

## Claude sessions

- **The model you pick is the model that runs.** Every Claude session used to run Claude's
  default model whatever was selected; the chosen model and effort now reach it, and a session
  refuses to start if Claude reports a different model.
- **Shell commands return their output.** In a project without a `.claude` folder, a sandboxed
  command could end the turn before the model saw what it printed.
- **Switching from Claude to another model works after parallel tool calls.** The first reply on
  the new model used to be refused by the provider.

## Security

- The sandbox's protections hold for projects and homes whose path contains `[`, `]`, `*` or `?`.
- Sandboxed commands can no longer create or change a project's `.winter/` skills, rules,
  commands, output styles or agents, at any depth, and commands that leave the sandbox cannot
  reach Winter's own state through the paths it gives sessions.
- A project's rules can no longer pull in files from outside the project, and a repository can no
  longer choose the Claude session's permission mode or model.

## Models

- `deepseek/deepseek-reasoner` is no longer in the catalog. A session that used it asks you to pick
  another model.
- Claude models with a dotted version (for example `anthropic/claude-haiku-4.5`) now reach
  Anthropic under the name its API accepts.
