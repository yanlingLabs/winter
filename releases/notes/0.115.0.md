# Winter 0.115.0

## A new look for the Mac app

The window is redrawn in the ChatGPT app's shape: a translucent sidebar that shows the desktop
through it and fades at its edges, a centred transcript that runs from the top of the window to
the bottom beneath a see-through composer, and one quiet type scale throughout.

- The composer's model button reads the model's short name ("5.6 Sol", "Fable 5.1"). Clicking it
  opens a small panel with the models in the current family, their providers and prices, an
  **Other models** card with every family, and an **Effort** list.
- Switching to a model that cannot take the effort you had chosen now clears it, instead of the
  next turn being refused.
- The Chats and Code lists, the Library (skills, plugins, hooks, MCP servers and agents), paired
  devices and updates all share one glass panel style.
- Updates are checked and downloaded inside the app, with release notes and the installed versions
  of Winter, its runtimes and Chromium.

## Settings

Settings is now a page of its own, laid out like ChatGPT's, with a searchable sidebar.

- **Roles** chooses the model and reasoning effort for each job Winter runs: new sessions,
  Dispatch, dreaming, the purge, chat titles, the page reader, the command reviewer and the
  advisor. A role whose model is failing (usage limits, no credits) shows a short note instead of
  failing silently.
- **Providers** lists your keys and sign-ins, with a search over every provider you can add.
- **Plugins** opens the Library at plugins, skills, hooks, MCP servers or agents.

## Dispatch

- The Dispatch thread has its own backdrop: a field of particles that leans away from the pointer,
  and sends a pulse outward from the composer while Dispatch is working.
- The work panel toggle now works on Dispatch too, and lists the sessions it is running.
- The Dispatch composer shows only the approval mode; its model is chosen in Settings.

## Web tools follow Claude Code

- Sessions use **WebFetch** (reads a page and answers a question about it) and **WebSearch**, in
  Claude Code's own shapes.
- Chat and Dispatch answer through **Search**, which returns a written answer with its sources. On
  the Mac and the CLI it falls back to WebSearch when no Exa key is stored; the iPhone's own chat
  still needs the Exa key. Adding or removing the Exa key takes effect on the next turn.
- Dangerous domains are now a hard block in every mode, Code included, and the block reaches Claude
  models' own web tools too.
- Fetching a private or local address asks first in Code, and is refused in Chat and Dispatch.
- The Brave web-search key is retired: a stored one can be removed but no longer added.
- The **Research** role is now the model that digests fetched pages; its fallback role is retired.

## Fixes

- Changing a running session's approval mode now takes effect immediately on Claude models too,
  and a refused change says so beside the picker.
- Empty chats that only ever had a browser tab open are cleaned up after a day.
- A chat whose first reply failed still gets a title.
- MCP servers can be enabled and disabled from settings, and a disabled server stays stopped.
- A skill can be turned off, and agents defined in your home folder reach every session.
- Stopping a turn now really stops a running foreground shell command.
- A session's cost now includes the subagents it runs, which were never priced before — so it can
  read higher than it used to.
