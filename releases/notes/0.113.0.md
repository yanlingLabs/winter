# Winter 0.113.0

## One conversation across model families

A session can now move between Claude, GPT and open models like DeepSeek and GLM and keep the
same conversation, in both directions. Pick a different model mid-session and Winter carries
your messages, the assistant's replies and its tool calls to the new model.

- Moving away from Claude, GPT or Gemini to a **different family** asks once before it happens,
  because those models keep private reasoning that can't follow them. Confirm and the move
  goes ahead; the conversation itself is never lost.
- Moving between models of the **same family** (Sonnet → Opus, one GPT to another) and between
  open models with visible reasoning (DeepSeek → GLM) happens silently.
- A session with no turns yet never asks.
- Reasoning that can travel does: an open model's visible reasoning and a summary of Claude's
  thinking are carried along and labelled as coming from the earlier model.
- If the new model fails to start, the move is refused and the session stays exactly where it was.
- Cross-runtime moves are on by default for Code sessions (`runtimes.handoff.crossRuntime`).

## Every provider, your keys

Any provider in Winter's catalog that takes an API key — DeepSeek, Z.ai (GLM), OpenRouter,
Google, xAI and the rest — can now be used, and its key managed from wherever you are:

- **Mac app** — a Credentials list in the Providers pane: add, replace or remove a key per
  provider. The Anthropic API key can be entered here too.
- **iPhone app** — a "Mac Credentials" section in Settings manages the keys stored on your Mac.
- **Terminal** — `winter credentials` lists providers, `winter credentials set <provider>`
  prompts for a key (never typed on the command line), `winter credentials remove <provider>`
  deletes it. `winter logout --openai` removes the OpenAI key.

Keys live only in the macOS Keychain and never appear in logs, replies or session files. A key
you add or remove takes effect on the next turn of any running session — no restart. Starting a
session on a provider that has no key tells you exactly which key is missing and where to add
it, instead of failing mid-turn. `settings.providers.<provider>.baseUrl` points a provider at a
self-hosted or proxied endpoint.

## Fixes

- Moving a session from Winter's runtime to the Claude runtime no longer stalls for thirty
  seconds before giving up.
- The first reply after moving a session to a different runtime is no longer lost.
- A session whose move to the Claude runtime failed can be used again immediately, instead of
  being stuck until Winter restarts.
- Switching a session to a different provider on the same runtime now really switches; before,
  the next turn could quietly go to the old provider.
- Error messages about a refused model change or session start no longer show Winter's
  internal reasons.
