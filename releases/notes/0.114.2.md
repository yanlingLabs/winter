# Winter 0.114.2

## The assistant conversation works on any default model

If your default model is not a Codex or OpenAI one (DeepSeek, Claude, …), the assistant
conversation and the other background pins (dreaming, cleaning, research) fell back to a placeholder
in 0.114.1. A new assistant session refused with a message; an existing one resumed a child with no
model at all and failed with "a bare model id needs a provider".

The pins now fall back to your own default model. The daemon's internal features that need a Codex
or OpenAI provider (titles, review, dreaming, cleaning, research) still stay off on other providers,
with one log line saying so; the assistant conversation itself runs on whatever you chose.

Also: when Winter refuses a request before sending it, the error now says so ("Winter refused the
request before sending it") instead of "the provider is unavailable or overloaded".
