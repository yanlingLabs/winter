# Winter 0.118.0

## Every model runs on Winter's own runtime

- **Claude runs on Winter's runtime too.** Winter no longer launches Anthropic's `claude` program:
  Claude, GPT, Grok and every other model now share one runtime, one set of tools, one hook
  system and one approval flow.
- **Your Claude sessions carry over.** A session that ran on the old Claude runtime moves across
  the first time you open it, with its history intact. If one can't move, it says why and names
  the `winter doctor --repair adopt-legacy-session` command that fixes it.
- **Chat and dispatch start faster.** They now run inside Winter itself instead of starting a
  separate program for every session. Code sessions still run in their own process.
- **Console login works with Winter's runtime.** Claude models on an Anthropic Console account
  run in chat and code sessions. If your default model is a Console model, Winter's background
  jobs (titles, the shell-command reviewer, memory dreaming and cleanup) now run on it too.
- **Winter's background jobs can use Claude.** A Claude-only setup now gets titles and the
  shell-command safety reviewer.

## Switching models

- **Switching models keeps the conversation.** A switch to another model family sends the new
  model the whole conversation as it is, as long as it fits that model's context window. If it
  doesn't fit, the model you are leaving writes the summary first, and Winter tells you before it
  does.
- **Switching back picks up where you left off.** Each model's own reasoning is kept, so returning
  to a model gives it its earlier thinking back.
- **Fewer confirmation prompts.** Winter now asks before a switch only when something can't be
  carried over, such as images going to a model that can't read them.

## Faster, cheaper turns

- **Prompt caching holds across the whole session.** Changing the effort level, loading a tool
  mid-session, connecting an MCP server late or compacting the conversation no longer throws away
  the cache on Claude and OpenAI models.
- **Codex sessions now use prompt caching.** They were missing it entirely before.
- **Effort changes take effect per message** on Claude Opus 5, Opus 5.5, Fable 5.1 and the GPT-6
  models, without resetting the cache.

## Claude in code sessions

- **Long tool loops are more reliable.** Claude's thinking, text and tool calls are replayed in the
  exact order they were produced.
- **A conversation that outgrows the context window compacts and carries on** instead of ending the
  turn with an error.
- **Web search works on Claude Opus 5.5 and Fable 5.1.**

## Tools, hooks and MCP

- **Grok models use xAI's Responses API**, so their reasoning carries from turn to turn. Grok 4.20
  Multi-Agent is available.
- **MCP updated** to the current MCP protocol library. Remote servers use the newest protocol
  version when they support it, and fall back to the older one when they don't.
- **Hooks do everything Claude Code's do.** Regex matchers, exit code 2 to block, extra context for
  the model, blocking prompts and stopping a turn all work, and plugin hooks written for Claude
  Code run as they are. Winter's own safety checks now block a call if they fail.

## Fixes

- A session whose working folder was deleted now says so and names the folder, instead of failing
  with a generic error.
- Warnings about a session's continuity are now shown in the app and the terminal.
