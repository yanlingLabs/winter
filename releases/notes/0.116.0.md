# Winter 0.116.0

## Code sessions behave like Claude Code

- **Your tools are found.** Sessions now see Homebrew and everything else on your shell's PATH
  (`node`, `npx`, `gh`, `ffmpeg`…) even when Winter was opened from the Dock or restarted by an
  update. Before, those sessions only saw the system's bare PATH.
- **Claude models work in Code mode again.** The installed app never loaded Anthropic's runtime:
  the daemon ran without JavaScript JIT, which also made it several times slower. Both are fixed.
- **Computer use keeps working.** Every action more than 15 seconds after the first one was
  refused as "expired"; it no longer is.
- **Plugin skills can be used.** A session can now invoke an installed plugin's skills, on Winter
  and Claude models alike. Skills can run shell commands, so a plugin's skills load only once you
  enable the plugin (and grant its `exec` consent if it asks for one); `winter skills` and the
  Library say why a skill is not available yet. Your own and project-level skills do not reach
  sessions yet.
- **Bypass can be switched on and off in a running session** instead of being refused.
- **"Allow … everywhere" and "Allow … in this project" stick.** Saved rules now reach every new
  session on both runtimes, and "in this project" works in any folder, not only trusted ones.
- **Commands that leave the sandbox follow Claude Code's rules.** A saved rule that matches
  allows them, bypass runs them, and anything else asks. Writes to Winter's own settings,
  permissions, plugins and runtime files are refused however the command is spelled, even in
  bypass, and under Auto a command that leaves the sandbox runs only when the command reviewer has
  looked at it knowing it runs unsandboxed.
- **Sending a message while an approval is waiting** closes that approval instead of leaving it
  on screen, and the transcript shows the turns in order.
- **Token counts are back** for every model, including subscription and unpriced ones.
- **The advisor works** when it is on a different provider than the session.

## MCP servers

- New `winter mcp add`, `add-json`, `remove`, `get` and `list`, with the same arguments and flags
  as `claude mcp` (`-s user|project`, `-t stdio|http|sse`, `-e KEY=value`, `-H "Name: value"`).
- A project's `.mcp.json` no longer loses all of its servers when one entry is an http or sse
  server or is malformed; every valid server is used and the bad one is named in the log.
- `~/.winter/mcp.json` has never been read. `winter doctor` now says so if you have one, and
  where the servers belong (`settings.json` → `mcpServers`).

## Models

- DeepSeek and other reasoning models no longer show their own reasoning as text in a reply.
- A model is always checked against its own provider's details; some DeepSeek chats were refused
  because another provider's entry was consulted.
- Sessions are told that sandboxed commands have no network, and when to ask to run outside it.

## Background jobs

- Chat titles and the purge no longer time out when their effort is set to "none": that now uses
  the model's lowest effort instead of the provider's default. A failed purge judgment waits 30
  minutes before trying again.

## Security

- A cloned repository's `.winter` folder can no longer run hooks or load skills in Claude
  sessions without your say.
- New write fences for Winter's own state, a symlink-safe store for "in this project" approvals,
  and a forged `.git` file can no longer borrow another project's approvals.
