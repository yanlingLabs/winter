# Winter 0.124.0

## The Dispatch pill

- The 4-finger tap, the hotkey and the menu's summon item now bring up a Dispatch pill at the
  bottom of the screen, just above the Dock, instead of the orb. The same gesture puts it away.
- It grows as you type and can open to full screen with the whole conversation. While Dispatch
  works, its tools stream out of the pill, with the websites it reads shown by their own icons.
- Approvals and questions float above the pill as cards.
- An unsent draft is kept when you put the pill away and cleared after 15 minutes. Change that in
  Settings → Dispatch.

## Commands in the pill

- Type `/` for a menu of commands, each with a short description. The closest match is marked in
  blue. ↑ and ↓ move the mark, Enter completes the command and Enter again runs it, and a click runs
  it at once. A fully typed command turns blue.
- `/compact` summarizes the conversation now. A small pill shows how long it has been running.
- `/permissions` turns the pill into the permission modes. Pick one with a click, or with the arrow
  keys and Enter; × or Esc goes back. `/permissions auto`, `/permissions accept edits` and the
  others set the mode directly, with a menu of modes as you type.
- `/spawn` is listed but not available yet. It will open a Cowork window.

## Dispatch starts sessions again

- Dispatch can start code sessions for you again, several at once. Each one shows as a small pill
  above the main pill. Click it to open the session in its own window, or stop it from there.
- A session Dispatch started brings its approvals and questions to Dispatch, and Dispatch hears
  back when it finishes ("Update from your sessions").
- Session windows share the pill's look. They open on the Space you are on, show over full-screen
  apps, and stack above the pill with the newest at the bottom. A window you move stays where you
  put it.
- Dispatch can find past sessions by date ("yesterday", "last week"), by a file they changed, or
  by words in their title and first message.

## Sessions can message each other

- SendMessage sends a message to another code session, and resumes it if it has finished.
- A message to a session that is still working joins its current turn after the next tool call,
  instead of waiting for the turn to end.
- TaskStop stops another session's running turn and drops the messages queued behind it.

## Faster tool runs

- Tools that only read run at the same time: reading and searching files, web lookups, subagents
  and read-only shell commands. Each result shows as soon as it is ready.
- Computer and Browser each do one thing at a time, but run beside other tools.
- Tool pills sit side by side and say what they are doing, then what they did.
- MCP tools load the first time the model needs them, which keeps every request smaller.

## The thinking pill

- A model's reasoning shows live as a pill in the conversation, titled with what it is doing: the
  provider's own heading when it gives one, otherwise worked out from the text ("Reading the
  files"). Click it to read the reasoning.

## Computer use and screenshots

- Computer use is on by default. To turn it off, set `computerUse.enabled` to false in
  `settings.json`.
- Screenshots from Computer and Browser now reach the model as images. Before, the model was told
  an image was attached but never saw it.
- Dispatch's instructions mention Computer only when it can use it.

## Compaction

- `/compact` works in every session, including `/compact <focus>` in the terminal app.
- Every compaction now shows in the conversation with how large it was, and a failed one is shown
  too.
- After a compaction the model is told where the full transcript is, so it can look up exact
  details from before.

## Models

- GPT-6.1 Sol, on OpenAI and on ChatGPT sign-in. The GPT family's "sol" choice now means 6.1.
- ChatGPT sign-in models use their full 872,000-token context window, so long sessions compact far
  less often. Before, they compacted at about 250,000 tokens.
- When a provider fails mid-reply, the error shows the provider's own message, with anything that
  looks like a key removed.

## Fixes

- A very long session (over 4 MB of history) opens again. Before, the app kept reconnecting to it
  and showed a working pill that never stopped.
- A message sent while a session restarts is retried instead of failing.
- Nothing a session started keeps running after Winter's background service stops.

This release runs on Winter agent SDK 0.0.53 and runtime SDK 0.0.16.
