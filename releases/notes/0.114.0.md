# Winter 0.114.0

## A model is now "provider/model", never just "model"

The same model reached through two providers was one name with a hidden coin-flip behind it.
`gpt-5.6-terra` could mean your Codex subscription or your OpenAI API key, and Winter picked
one for you. It is now two distinct models: `codex-oauth/gpt-5.6-terra` and
`openai/gpt-5.6-terra`. The same holds everywhere: `anthropic/claude-sonnet-5` versus
`console/claude-sonnet-5`, `deepseek/deepseek-reasoner` versus `openrouter/deepseek-reasoner`.

- **The picker is grouped by provider.** Under each provider you see that provider's models by
  their usual names (Terra, Sol, Fable…). Pick the provider you mean; Winter never chooses one.
- **Badges and status lines show the model name.** The provider is shown as a secondary label or
  tooltip, not glued into every title.
- **Your existing settings and sessions migrate once, on first launch.** A stored bare model
  becomes the tag for the provider you had configured (`codex-oauth` stays Codex, an
  `openai-compatible` endpoint becomes `openai/…` with its base URL kept under
  `providers.openai.baseUrl`). Claude models follow your Console login when one exists. A backup
  is written to `settings.json.bak-pre-ws20`.
- **The assistant conversation and background jobs** (dreaming, cleaning, research) run on
  provider-qualified pins that default to your configured provider. They can be changed under
  `pins` in settings; they are never hard-coded to a provider.
- **Anthropic Console is its own provider.** The `runtimes.official.auth` setting is gone: an
  `anthropic/…` model uses your API key, a `console/…` model uses the Console profile from
  `winter login --anthropic-console`.
- **The CLI:** `winter model` lists models grouped by provider and accepts the full tag;
  `winter model codex-oauth/gpt-5.6-terra`.

## Reasoning effort on OpenAI models

The catalog now carries the measured effort vocabulary for `gpt-5.6`, `gpt-5.6-sol`,
`gpt-5.6-terra` and `gpt-5.6-luna` on both the OpenAI API and Codex: low, medium, high, xhigh
and max. The "declares no reasoning effort vocabulary" refusal that 0.113.1 worked around is gone.

## Under the hood

- Agent SDK 0.0.13 (catalog: `console` provider, Console twins of every Claude row, the effort
  vocabularies) and router 0.0.8 (a request always names its provider; a bare model id and a
  provider that disagrees with the tag are both refused with a typed reason).
- The Mac app writes the advisor model through the daemon (`settings.setAdvisorModel`) instead
  of editing `settings.json` directly.
- **iPhone users: update the iOS app before relying on on-device chat.** This release changes the
  protocol's model fields to tags. An iOS build on the previous kit stores the daemon's default
  model verbatim and sends it to the Codex API, which rejects it. The fix ships in the next
  iOS build (kit `v-tags-kit1`); Mac-mediated sessions are unaffected.
- A default model outside Codex and OpenAI (for example `anthropic/claude-sonnet-5`) is
  accepted, but the daemon's own background features that run on its internal provider
  (titles, review, dreaming, cleaning, research) stay off until the default names Codex or
  OpenAI. One log line says so.
