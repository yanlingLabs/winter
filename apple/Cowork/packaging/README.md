# Native Cowork packaging prerequisite

This source-build recipe packages the native controller/Node-API addon and the
backend-neutral network component with their dynamic dependency closure. It
does not enable Cowork, launch a VM, sign with a production identity, publish an
asset, or alter the app build. Every invocation uses a new ignored `out/build-*`
directory and isolated Swift scratch directories. Never use these development
paths as runtime discovery or overwrite a library already loaded by a daemon.

SwiftPM also uses private cache/configuration/security directories, local
manifest caching, and disabled netrc/Keychain credential search. Git reads no
user/global configuration and cannot prompt for credentials. Clang module and
Bun transpiler caches stay in this invocation's output. Bun smoke uses explicit
empty configuration and disables environment-file autoloading.
The config argument uses `--config=PATH`; separate arguments can exit without
running the script on Bun 1.3.14. Every runtime smoke also requires its typed
JSON completion receipt, so a silent successful exit cannot pass verification.

## Reproduce

Use macOS 26, Swift 6.2+, existing Clang, Python 3.12+, Meson, Ninja, pkg-config,
Bun and Node-API headers. The recipe installs nothing globally. Existing
Homebrew **build tools and headers** are acceptable; Homebrew library binaries
and pkg-config dependency search directories are not build inputs. Configure
scripts also use the platform's make/install/sed and compiler tools; their
versions are part of the build environment, not a promise of bitwise reproducibility.

```sh
python3 -m unittest discover -s apple/Cowork/packaging -p 'test_*.py'
python3 apple/Cowork/packaging/build.py --jobs 4 \
  --node-headers /path/to/existing/node/include/node
# Optional: verified local source cache; mismatching archives fail closed.
python3 apple/Cowork/packaging/build.py --jobs 4 \
  --source-cache /path/to/downloaded/source/archives
# Build/test network component alone, without compiling controller dependencies:
python3 apple/Cowork/packaging/build.py --network-only --jobs 4
# Stage/reuse verified dependencies while controller/network sources change:
python3 apple/Cowork/packaging/build.py --dependencies-only --jobs 4
python3 apple/Cowork/packaging/build.py --jobs 4 \
  --dependency-bundle apple/Cowork/packaging/out/build-DEPS/bundle
python3 apple/Cowork/packaging/closure.py apple/Cowork/packaging/out/build-UNIQUE/bundle/lib
```

Build jobs are limited to four. Source downloads have timeouts, build commands
have a 15-minute bound, and relocated runtime smoke commands have a 30-second
bound. The recipe checks for 8 GiB free disk space before building. GNU Automake
rejects source paths containing spaces, so a unique temporary symlink supplies
a safe logical pathname; its target and all generated bytes remain in ignored
`out/`. The alias is removed at the end, including failed builds. Saved command
logs contain this invocation's paths; rerun the recipe for a fresh build.

The dependency stage supplies explicit Apple SDK-only pkg-config metadata for
libffi and zlib while building GLib's additional upstream targets. The libffi
metadata records Apple's SDK ABI version (from its `.tbd`), rather than claiming
an upstream release version. These are system libraries and are not bundled;
only the GLib/libintl/PCRE2 runtime closure is retained. An optional dependency
bundle is accepted only with matching pins and verified material hashes, then
copied into a fresh private prefix. That cache is a local build convenience,
not an authenticated distribution channel. Native/network inputs are copied
only when the Swift stage begins; their individual source hashes are recorded.
Both pkg-config path variables name the private metadata, including SwiftPM's
internal parser. Cached dylibs receive temporary build-prefix install IDs only
in their fresh copies, then the final bundle is relocated and checked again.

The native stage defaults to `--native-profile verified-eof`: it runs the
snapshot's fixed Containerization preparer, verifies the committed upstream
archive/patch/full-tree pins, and builds from that fixed local source path.
An archive already in the development package is only a cache and is verified
again. The complete original archive, patched tree, patch, notices and pinned
profile are retained in `source/containerization-profile`; the manifest records
the profile identity. `--native-profile upstream` is available for comparison
builds, whose real VM launch remains blocked. Ambient profile environment
variables cannot select a different source. Swift uses the canonical snapshot
path so the manifest's source-alias refusal still applies.

`dependencies.json` pins complete source archives, exact versions, SHA256 and
the checksum evidence authority. GLib's checksum comes from GNOME's published
checksum file; PCRE2's comes from the upstream GitHub release asset digest.
gettext's checksum matches the GNU download and the recorded Homebrew formula
checksum; it is **not** a verified GNU publisher signature. No signing-key trust
claim is implied. Sources are fetched from upstream, checked before extraction,
and retained verbatim in `bundle/source/`.

GLib 2.90.0, libintl from gettext 1.0, and PCRE2 10.49 are built as shared
libraries into the isolated prefix. Only the reachable dylib closure is shipped.
No LGPL static archive is linked into Winter. libslirp's patched C sources are
compiled into the network component; its upstream version/revision and patch
record remain in the retained source. Native Swift package resolved revisions,
their complete checkout sources, Node-API headers, the local package source
snapshot, build recipe, configure logs, build options and command logs are
retained. All upstream source archives remain complete, including individual
notices beyond the top-level licenses.

The dependency stage's relocated C smoke asserts exact GLib/libintl/PCRE2
runtime versions, exercises a GLib regex through PCRE2, and calls gettext under
the C locale. It strips loader search environments and makes no network call.

For libslirp, the package records the exact clean upstream Git commit/tree,
retains a complete upstream `git archive`, hashes every vendored file and
generates `winter-libslirp.patch`. Applying that patch to upstream `src/`,
`LICENSE` and `COPYRIGHT` is checked to reconstruct the exact vendored tree,
including generated headers and local forwarding files. Archive SHA256 is
locally computed; this is not a publisher signature claim. To regenerate this
read-only provenance independently, choose a new destination:

```sh
python3 apple/Cowork/packaging/libslirp_provenance.py \
  --destination apple/Cowork/packaging/out/libslirp-provenance-UNIQUE
```

## Closure and smoke evidence

The recipe follows only dependencies from its own prefix. Each bundled dylib's
install ID and non-system load commands use `@loader_path/<filename>`; versioned
SONAMEs and applicable dylib symlink aliases are retained. Non-system build
runpaths are removed; Apple system runpaths remain. The checker examines every
architecture in every bundled Mach-O, requires each relative target to remain
inside the bundle and contain that architecture, and rejects unresolved
`@rpath`, missing targets, path traversal, and absolute non-system paths.
System dependencies under `/usr/lib` and `/System/Library` are provided by the
target macOS, including its Swift runtime. This is a macOS 26 closure, not an
older-system compatibility promise or a universal-architecture artifact.

The source package network tests use synthetic policy and ephemeral local
socket fixtures. The additional C smoke loads the **relocated packaged network
dylib**, creates/destroys a synthetic endpoint, rejects a loopback tuple, sends
an unsupported local frame, and checks current/stale policy replacement ACKs
with zero outbound attempts. The controller addon and typed-client smokes load
the **relocated packaged native dylib** with the fake backend and verify the
production-blocked factory. Injected `DYLD_*`, pkg-config, compiler/library
search and GLib module environments are stripped. No real VM, host-pressure
test, Winter home, daemon, app, Keychain or credential is used.

Mach-O edits are followed by **ad-hoc test signing only**. `manifest.json`
records hashes, all closure load commands by architecture, dylib aliases,
toolchain, source pins, command lines and source/build material hashes. It
explicitly marks `productionReady: false`. Its hash inventory describes an
artifact; it is not authenticated host admission or a release signature.

## Notices and replacement material

GLib and the used libintl runtime identify LGPL-2.1-or-later terms; PCRE2 retains
BSD and individual notices; patched libslirp retains its upstream notices.
`bundle/notices/` extracts license/copyright material and `bundle/source/`
retains corresponding complete upstream archives and the exact local sources.
The full gettext archive contains additional tools with their own terms; only
its libintl shared runtime is in the runtime closure.

Recipients can unpack those exact archives, change library sources and rebuild
the shared libraries with the supplied recipe/options, retaining the same
install IDs and exported ABI. They can replace the colocated shared dylib files
and ad-hoc sign their own local test bundle for the supplied smoke. The design
uses a shared-library mechanism rather than absorbing LGPL code into Winter.
This material and mechanism support review of replacement/relinking obligations;
they are not a legal determination of distribution compliance.

Primary references: [GLib release checksum](https://download.gnome.org/sources/glib/2.90/glib-2.90.0.sha256sum),
[GLib license documentation](https://docs.gtk.org/glib/),
[GNU gettext sources](https://ftp.gnu.org/gnu/gettext/),
[PCRE2 release](https://github.com/PCRE2Project/pcre2/releases/tag/pcre2-10.49),
[LGPL 2.1 sections 4 and 6](https://www.gnu.org/licenses/old-licenses/lgpl-2.1.html).

## Remaining production gates

The app/daemon must embed and authenticate the exact packaged closure, sign all
native artifacts consistently with the production hardened runtime, and pass
compiled-Bun load/lifecycle tests under that actual signing topology. The
distribution's library validation, signatures and update policy must preserve
a workable library replacement/relinking path; the current ad-hoc smoke does
not settle that requirement. Production source/notices delivery, artifact
provenance attestation, reproducible CI/toolchain pinning, all supported
architectures, notarization and release integration remain open. No downloaded
dependency signature verification or bitwise reproducibility is claimed.

Actual VM authority/admission, durable ownership, guest/tool confinement,
resolver-policy integration and end-to-end network tests remain independent
gates. Active-work RAM return is also still a blocking VM feasibility gate.
