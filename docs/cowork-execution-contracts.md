# Cowork execution and integration contracts

Status: specification, 2026-10-11. This companion records the execution boundaries and integration decisions supporting the [Cowork specification](cowork-spec.md). These mechanisms are not implemented or validated. The independent review and its disposition are recorded in the [review ledger](research/2026-10-11-cowork-spec-review.md). Accepted product choices remain unchanged; the concrete mechanisms here are implementation requirements and proposed defaults.

## Authority and Linux execution boundary

The VM is the boundary between a workspace and the Mac; it is not sufficient protection for Winter's own control state inside that workspace. A shared UID, a private filename, model guidance, tool schemas and PreToolUse path checks alone cannot constrain arbitrary Bash. The host remains authoritative for identities, grants, trust, policies, approvals, provider/Git access, schedules and cross-session routing.

Use a protected supervisor and conversation runtimes, plus separate confined tool processes. The supervisor/runtime binaries, their imports, run-home configuration and control sockets are not writable or accessible as executable control surfaces to tools. Conversation SDK stores remain real guest directories with their SDK ownership/lease rules; omit them from general tool mount views. Only the owning trusted runtime and recovery service may write a conversation's transcript/metadata/provider state. Provide bounded transcript/output tools when an agent needs to inspect subagent results. Tools must not rewrite another conversation's saved authority or their own resume snapshot. Host-owned current policy and a host-authenticated saved authority/lineage record constrain restoration; guest snapshot fields cannot mint or increase permissions.

Bash, Workflow, hooks, stdio MCP, LSP servers, plugin programs, skill scripts, package-install hooks, builds and tests execute on the tool side. Give each conversation's tool processes a separate identity/process namespace; share authorized data through a workspace group or equivalent mapping. The same project files, memory and chosen worktrees remain concurrently writable. This is control-state and task-ownership protection, not per-file locking or confidentiality between agents deliberately sharing project data. Read/Edit/Write and other ordinary file tools execute through a helper inside the calling agent's effective tool compartment, with the same identity, namespaces and restrictions as its Bash invocation. The protected runtime never performs arbitrary model-directed filesystem operations with its own broader access. Use admitted rooted descriptors and constrained path resolution; pass no runtime/store/socket or unrestricted filesystem handles. Apply this to Glob/Grep, notebook/image tools and model-directed diff reads too. The approved host instruction-write service is an explicit separate operation, not a broader file-helper view. Test symlink/rename races, ancestor replacement, stale descriptors and narrowed subagent views.

The initial Linux confinement design uses distinct identities, mount/PID isolation, restricted capabilities, `no_new_privs`, syscall filtering and an enforced filesystem view. Filesystem mediation such as Landlock may supplement it if the pinned kernel supports the required ABI; no single primitive or Containerization default is assumed to implement the contract. Tool code gets neither guest-supervisor root nor privileged mount/ptrace access. Any user-namespace root used for installation remains confined to tool-owned storage. Unsupported confinement is a refusal, never plain unsandboxed Bash. [Linux Landlock](https://docs.kernel.org/userspace-api/landlock.html), [no_new_privs](https://docs.kernel.org/userspace-api/no_new_privs.html)

Protect the directory skeleton and ancestors as well as file contents: `/workspace/.winter` cannot be renamed/replaced by tools. Memory and scratch are separately writable subtrees; SDK stores/configuration and the shared instruction alias are protected. The supervisor creates mountpoints and aliases during source preparation; general tool writes are not needed for that setup. Shared workspace WINTER.md is exposed read-only to tools. A content-bound approved write goes through the host instruction owner and refreshes context; direct user editing does not require agent approval. Never temporarily make the enclosing directory writable. Existing repository WINTER.md editing semantics remain ordinary.

Sanitize inherited descriptors, `/proc` visibility, Unix sockets, launch environment and dynamic library/module lookup. Trusted executables must not be resolved through tool-writable PATH, NODE_PATH, package overlays, bunfig, dotenv or repository configuration. Host-source admission must exclude Winter's own authority/credential/control storage, including overlapping roots and aliases; refuse grants whose required exclusions cannot be enforced. Test symlink/hard-link aliases, rename attacks and inherited handles, not only nominal paths.

## Host storage authority, fences and migration

Canonical Workspace, Project, Source, trust, publication-policy and Delegation records live in new versioned tables in `<WINTER_HOME>/runtimes/runtime-state.db`, with its normal protected SQLite sidecars. `cowork/workspaces/<id>/manifest.json` is a versioned storage/export descriptor, not a second authority store: record workspace/volume identity, relative owned storage locations, image/runtime digests and checkpoint/export generation. A manifest or imported export can never grant access, trust a source or change policy. Validate it against the host database and owned storage roots before attaching anything; a mismatch is recovery-required. Schema upgrades preserve authority, and unsupported downgrades refuse rather than recreate empty permissive state.

Extend the existing single host-fence definition to include every participating Winter home's Cowork tree and the fixed coordination directory. Derive the Mac shell sandbox denial, Write/Edit/Notebook/path rules and escape floor from that definition; do not maintain separate drifting lists. Raw host-agent writes, rename/replacement, deletion and chmod of these stores are denied under every policy, including auto/accept-edits/bypass. Raw host Read/Glob/Grep and sandboxed-shell reads of manifests, authority/control records and volume files are also denied; approved metadata/artifact/export services provide bounded views. Apply read fences separately from write fences, while preserving authorized reads of shared content. Approved user/host broker operations are separate from agent file tools. Include other dev/custom homes, and reject or exclude control storage from selected source roots. Owner-only file modes alone do not constrain same-user host agents. [Current fence composition](../packages/core/src/runtime-sdk/home-fence.ts#L32), [sandbox source list](../packages/core/src/runtime-sdk/mode-options.ts#L915)

For escape matching, distinguish nested classes: the whole Cowork tree is write-fenced; path-anchored manifest, volume and authority/control paths are denied on any mention, while `shared/**` remains write-fenced so authorized reads are not swallowed by a blanket any-mention parent match. Use explicit precedence for narrower control entries; do not ban every unrelated file named `manifest.json`. Protect ancestor operations and aliases that could replace/move a fenced root, not only direct descendants. Maintain the control-storage deny below ordinary permission policy on every host execution route; a sandbox escape must not remove it. A route unable to preserve that denial must refuse, not rely solely on command-string matching. Add adversarial tests for scripts/computed paths, alternate homes, symlinks/hard links and ancestor rename. [Current prefix handling](../packages/core/src/runtime-sdk/home-fence.ts#L50), [current path comparison](../packages/core/src/runtime-sdk/control-plane.ts#L160)

Migration B / `winter migrate` may copy the whole Cowork storage tree and canonical DB only through a coordinated quiescent migration of the source and destination homes. Check both homes' daemon/admission/workspace ownership, stop confirmed guests, checkpoint or use the SQLite backup API, and preserve IDs, volume bytes, shared files, dirty work and policy records. Bind the canonical DB snapshot, volumes and shared files to one migration generation. Stopped guests do not freeze direct user writes to host-backed data: take a consistent snapshot or establish quiescence, otherwise retry/refuse. Preserve valid user symlink content under explicit safe copy semantics or refuse visibly; never silently discard it. Cowork-aware classification preserves arbitrary shared artifacts even when named index.db or ending in .db-wal/.db-shm. Skip only identified disposable sockets/handles/process claims and reproducible caches, plus SQLite sidecars after obtaining a valid DB snapshot. Do not reuse blanket filename skips or treat omission of WAL/SHM as a consistent database backup. Keep a crash-safe migration journal and apply the same checks to resume/rollback and automatic boot migration. Revalidate folder/bookmark access at the destination; never transfer invalid OS authority by assumption. [Migration B classification](../packages/core/src/migration/migrate-b.ts#L246), [CLI migration entry](../packages/cli/src/commands/migrate.ts)

Migration C explicitly excludes Cowork topology from host-cwd canonicalization, transcript re-keying and backend-root rewrite queries. `winter migrate-project` must never rename/re-key the Cowork control tree, disk contents, workspace IDs or SDK store identities; it applies only to explicit project content in its owning filesystem. Refresh instruction/executable-trust revisions afterward; migrated source allow rules remain bounded requests/restrictions, never host authority. Whole-home relocation changes host storage descriptors through the coordinator, not guest `/workspace` paths or logical identities. The per-user admission ledger stays outside home migration; owners re-register under fresh process/instance identity. Live/stale-uncertain ownership refuses migration. [Migration C re-key selection](../packages/core/src/migration/migrate-c.ts#L408), [backend-root rewrite](../packages/core/src/migration/migrate-c.ts#L641)

The [host data and protocol contract](cowork-host-protocol.md) specifies canonical records and the local/remote operations that can change them. No raw file import or synced session event is an authority-writing substitute for those methods.

## Approval policies

Cowork supports `plan`, `dont-ask`, `ask`, `accept-edits`, `auto` and `bypass`, with `auto` as the ordinary starting policy. The Project has a grant/capability ceiling and a default policy; each conversation records its own policy. Effective authority intersects current Project grants, conversation restrictions, operation-specific approvals and saved schedule/delegation bounds. These policies are not a linear privilege ranking.

The following defaults apply after hard denials and explicit applicable rules:

| Policy | Admitted reads | Ordinary workspace edits | Other admitted guest actions | Shared workspace instruction edit |
| --- | --- | --- | --- | --- |
| `plan` | Allow | Deny | Planning/read operations only | Deny |
| `dont-ask` | Allow | Only if already authorized without a prompt | Deny anything needing a prompt | Deny |
| `ask` | Allow | Ask unless already authorized | Ask unless already authorized | Ask |
| `accept-edits` | Allow | Allow the bounded edit class | Ask unless already authorized | Ask |
| `auto` | Allow | Allow | Normal mutation class allowed; Bash review below; Workflow still asks | Ask |
| `bypass` | Allow | Allow | Skip ordinary prompts within grants | Ask |

Enforce `plan` below command classification: its tool execution receives read-only source and Project-memory mounts, separately scoped disposable/planning scratch, and no mutating broker authority. A read helper or command indirection cannot inherit a writable view merely because the command was classified read-only. Runtime transcript bookkeeping remains writable to the protected runtime. This is a per-conversation execution view, not a lock on other Project conversations.

Each tool launch also applies the calling subagent's current restrictions. Sharing a conversation identity does not let a narrower child inherit a broader mount or broker view from its parent. Same-Project peer messages still execute under the recipient's explicitly recorded policy; an individual plan conversation is not a workspace-wide read-only switch.

Unknown tool classes are not silently admitted. Explicit deny, protected runtime state, source/egress constraints and host capability boundaries apply under every policy. `bypass` never disables Linux control-state confinement or grants access to the Mac. Cowork rejects `dangerouslyDisableSandbox` when it would remove mandatory confinement; there is no guest Bash fallback to host Bash. A future restricted guest escape tier would require its own specification.

Run the Cowork host policy check for every tool before execution; do not let the SDK's optional blanket sandboxed-Bash auto-allow replace this matrix. This is an explicit Cowork integration requirement, not a change to existing Code sessions. Existing SDK evaluation can allow sandboxed Bash under several modes, so merely adding a `gate.ts` case is insufficient. [SDK evaluator](https://github.com/yanlingLabs/winter-agent-sdk/blob/27f1c43e8383582ce73e544237bcfa6fb3721db3/packages/runtime/src/permissions/evaluator.ts#L1916)

Preserve Winter's existing `auto` reviewer semantics for ordinary confined Bash: recognized read-only/user-allowed commands may skip model review; unsafe review denies; a transient reviewer failure asks. An absent/disabled reviewer or no runnable reviewer model permits an otherwise admitted confined command, as Code does; `auto` does not promise every action received model review. Do not reuse Mac-specific `open` exemptions as host actions in Linux. Winter `auto` maps to SDK `default`; do not enable a second SDK classifier accidentally. Workflow asks under auto and ordinary prompt policies unless already appropriately authorized, denies under plan or unresolved dont-ask, and follows bypass's ordinary no-prompt behavior within grants. [Policy mapping](../packages/core/src/runtime-sdk/mode-options.ts#L67), [Bash review](../packages/core/src/runtime-sdk/hooks.ts#L1324), [tool gate](../packages/core/src/agent/gate.ts)

Give connectors an explicit Cowork row in the existing connector system:

| Connector setting/class | Decision within current grants |
| --- | --- |
| Explicit deny | Deny in every policy |
| Explicit ask | Ask even under bypass; deny under dont-ask and for plan-mode mutation |
| Explicit allow | Allow except plan-mode mutation |
| Unset, classified read-only | Allow |
| Unset mutation/unknown effect | plan/dont-ask deny; ask/accept-edits ask; auto/bypass allow |

Classification belongs to the admitted server/action and its canonical host record. Server read-only annotations are classification metadata, not a security proof or a grant; plan-mode connector use relies on the admitted service honoring its read-only contract, since Winter cannot prove a remote server has no side effects. Existing connector rules must be applied explicitly rather than letting the new mode inherit the current generic non-Code fallback. [Current connector matrix](../packages/core/src/agent/mcp/connector-permissions.ts#L198)

Approval cards belong to the target conversation and identify its workspace, operation, source revision and requesting agent. Authorized user clients answer them; a peer agent cannot impersonate the user. A scheduled/unattended turn retains its policy: a required approval becomes visible blocked work, or a typed denial/timeout according to the call's policy. Never silently switch to auto/bypass because nobody is watching. Pending live approval callbacks keep occupancy; cancellation expires the card and requires a fresh valid request on retry. Delegated Dispatch work may relay the target's card to the user, but relay itself grants no approval. Policy changes and cold resume revalidate all bounds.

When narrowing a policy or hard capability ceiling, first close affected admission and cancel/drain processes holding older writable handles or broker capabilities. Switching into plan requires replacing the old execution view before it becomes effective. Show a pending transition until affected work is stopped and the new view installed; a task cannot keep broad authority behind a UI that already says plan. Use workspace restart where a share/grant revocation cannot be enforced per process. Changes to completed external effects cannot be undone by this transition.

## Session messaging and creation boundaries

Activity participation is not messaging authority. Add a host-owned caller/target/workspace check before all SendMessage, ListAgents/ListSessions, TaskStop, transcript/output lookup and spawn routes, including SDK aliases and resumed children. Derive the caller from the authenticated runtime channel, not tool arguments.

| Direction/action | Default contract |
| --- | --- |
| Cowork to same-Project Cowork SendMessage | Allowed, attributed as an agent message, delivered under the recipient's current policy |
| Cowork list/discovery | Own descendants and same-Project Cowork peers; no unrelated or host-session metadata |
| Cowork TaskStop | Own tasks/descendants; Project membership alone does not authorize stopping a sibling top-level conversation |
| Cowork to host Code/Dispatch send/list/stop/spawn | Denied, including guessed IDs and indirect aliases |
| Cowork to another workspace/Project | Denied unless a specific host-owned delegation grant exists |
| Host Code/Dispatch to Cowork | Requires a user-authorized delegation bound to sender, workspace/target and allowed operations |
| User client to Cowork | Normal authenticated user creation/control path, subject to source selection and current grants |

Messages and returned results do not confer authority on their recipient. In particular, a guest cannot use a host bypass session as an unrestricted host tool. Keep the deliberately broader existing host Code-to-Code behavior unchanged. Same-Project peers remain able to coordinate work as selected by the user. [Existing activity-based routing](../packages/core/src/agent/session-messaging.ts#L179), [existing host Code decision](../packages/core/src/agent/gate.ts#L47)

Specify Dispatch `SpawnSession(type=cowork)` as an explicit new creation path: it must name an existing authorized workspace, hold delegation authority, check source readiness and declare the conversation policy within the Project ceiling. It cannot infer folder grants from a `dir` string, clone a workspace implicitly or copy Dispatch bypass into the child. Until those checks and the Cowork topology exist, return unsupported. The ordinary Cowork creation UI/API can create a new standalone workspace from explicit user-selected sources. [Current refusal](../packages/core/src/agent/dispatch-children.ts#L327)

## Guest router, file channel and immutable runtime

Cowork is a third launch topology beside a Mac runtime child and embedded chat/dispatch Worker. A protected guest supervisor hosts the portable router/build/reconciliation components needed to resolve guest roots, materialize real guest run homes and restore SDK state. This is not a second complete daemon: the Mac remains owner of UI events, approvals, schedules, credentials and global routing. The host query/transport facet uses authenticated logical lifecycle and streaming messages to the guest component.

Current run-home objects are process-authenticated and path-validated locally. A serialized guest object must not bypass the host router's WeakSet/authenticity and local-file checks. Genuine run homes are built/applied inside the guest component; introduce a remote transport contract rather than relaxing the existing local contract. The host supplies signed/current source, trust and policy inputs; guest configuration is a read-only projection. [Run-home authenticity](https://github.com/yanlingLabs/winter-runtime-sdk/blob/c5424202619cc8df2c8d18b832bfc52ad6fa35f7/src/run-home/build.ts#L62), [local application checks](https://github.com/yanlingLabs/winter-runtime-sdk/blob/c5424202619cc8df2c8d18b832bfc52ad6fa35f7/src/run-home/apply.ts#L50), [current topology selection](../packages/core/src/runtime-sdk/create.ts#L391)

Supply Linux ARM64 Winter, the guest supervisor/router components and their dependencies from a host-verified, read-only runtime image outside the writable environment layer. Verify digest, protocol and `REQUIRED_WINTER_AGENT_SDK` compatibility before loading durable state. Carry the actual runtime version/features through the host handle, including queued-input folding. Mismatch is a recoverable refusal, not a Mac fallback or a new session identity. Package installations cannot replace or shadow these entrypoints. Linux packaging and Linux Workflow confinement are explicit prerequisites; today's Darwin artifact/sandbox paths are not compatible by renaming them. [Runtime pin](../packages/core/src/runtime-sdk/versions.ts), [queued-input folding](../packages/core/src/runtime-sdk/winter-session.ts#L607), [SDK platform resolution](https://github.com/yanlingLabs/winter-agent-sdk/blob/27f1c43e8383582ce73e544237bcfa6fb3721db3/packages/sdk/src/transport.ts#L45), [Workflow sandbox](https://github.com/yanlingLabs/winter-agent-sdk/blob/27f1c43e8383582ce73e544237bcfa6fb3721db3/packages/runtime/src/workflows/sandbox.ts)

Provide a versioned authenticated file channel for list/stat/read/ranged-read, bounded image upload and explicit export. Each operation binds workspace/session, stable location ID, relative path and current incarnation/source revision. Resolve guest filesystem paths in the guest and apply traversal/symlink/size limits; the host separately validates its own grants and any translated Mac access. Guest paths are never passed directly to privileged Mac filesystem APIs. Report missing, unavailable, stale, revoked, oversized and incomplete distinctly.

| Existing host reader/producer | Cowork execution point |
| --- | --- |
| Root discovery, instruction imports and run-home materialization | Protected guest router; source identities/trust supplied by host |
| Cwd availability and path fences | Guest filesystem check plus host grant check; no host stat of `/workspace/...` |
| Before/after file diffs | Guest captures bounded snapshots/diffs for authenticated call; host stores events, not a full mirror |
| LSP/diagnostics | Confined Linux guest language server and guest path resolver |
| Bash edited-file inference and session_files | Guest filesystem facts; host index stores location identity and guest cwd, preserving inference uncertainty |
| Composer images | Host validates upload, transfers bounded bytes, obtains guest-readable path/identity; never send host temp path as guest input |
| Project memory/Dreamer | Host-backed memory location plus explicit workspace/session binding; extend eligibility deliberately |
| File browser and exports | Direct host-backed shared files while stopped; guest-only repos/scratch require file channel and visible wake when necessary |

Source pointers: [run-home inputs](../packages/core/src/runtime-sdk/run-home-input.ts#L52), [diff hooks](../packages/core/src/runtime-sdk/hooks.ts#L1421), [path resolution](../packages/core/src/agent/paths.ts#L147), [cwd admission](../packages/core/src/runtime-sdk/session-driver.ts#L158), [file index](../packages/core/src/sessions/store.ts#L580), [Bash inference](../packages/core/src/sessions/bash-edits.ts#L260), [image staging](../packages/core/src/agent/stage-image.ts#L182), [Dreamer](../packages/core/src/agent/dreamer.ts#L212), [LSP diagnostics](../packages/core/src/agent/lsp/auto-diagnostics.ts#L135).

Do not mount a live writable ext4 volume a second time on the Mac or promise ordinary host filesystem access to its contents. Host-backed guidance/memory/outputs and host transcripts are readable while the VM is off. Other guest-only data requires wake or an explicit consistent export. Upload/export only requested bytes; no whole-workspace synchronization loop.

Host-backed shared files remain untrusted content. All host consumers, including memory/Dreamer and artifact readers, must check the actual backing root and reject guest-authored symlink/traversal escapes; a convenient Mac path is not admission to arbitrary host files or execution. Cold restoration validates every recorded backing directory before mounting. Missing expected memory/output/instruction storage yields unavailable/recovery state, never a new empty replacement or writes into a bare guest mountpoint.

## Trust and extensions

Host trust is keyed by workspace/source identity, stable repository identity or validated folder grant, and applicable configuration revision. New guest clones and newly selected folders begin without executable-configuration trust. Selecting a source admits confined plain WINTER.md guidance; it does not enable repository hooks, plugins, MCP processes or permission settings. This explicitly splits plain instruction admission from executable trust, unlike today's single `trustedProjectRoot` gate. Preserve Code's filename/import/order behavior while adding that split for Cowork. Trust changes are user-controlled host records, never guest-edited `trust.json`.

Selecting a source admits its applicable instruction content; it does not establish that this content is trustworthy. Malicious guidance can influence actions already allowed by the workspace, including reading another shared source and sending data over admitted outbound connections. Filesystem confinement and withholding executable-configuration trust do not prevent this prompt-injection risk. Record this consequence of the selected automatic-loading behavior without claiming the user separately approved the risk. Show admitted guidance provenance in the UI: source identity, original/imported guest paths, content revision/digest and refresh status. Attribute additions and changes on active turns and cold restoration; provenance helps inspection but is not prevention.

Record and expose the admitted executable configuration/version. New or materially changed executable configuration is not silently admitted because a repository was once trusted; apply current trust policy at refresh/resume. Treat project permission settings as restrictions or requests, never authority exceeding host grants. Discover instruction/configuration files inside the guest, but obtain authority from the host. [Current trust](../packages/core/src/agent/trust.ts), [project settings](../packages/core/src/project-settings.ts), [instruction construction](https://github.com/yanlingLabs/winter-runtime-sdk/blob/c5424202619cc8df2c8d18b832bfc52ad6fa35f7/src/run-home/instructions.ts#L251)

| Surface | Execution and admission |
| --- | --- |
| User/project/plugin stdio MCP | Linux-compatible command in the tool compartment, bounded environment and task ownership; project config needs executable trust |
| HTTP/SSE MCP with OAuth/secret headers | Host proxy owns credential injection, OAuth registration/refresh and network destination; guest receives MCP protocol/results, no reusable tokens |
| Skills and agent definitions | Approved content exposed as read-only resources; scripts run as tool code; compatibility reported explicitly |
| Plugins and hooks | Linux-compatible executable pieces run as confined tool processes, never imported into trusted runtime; no inherited Mac environment or automatic host launch |
| LSP | Guest Linux servers and paths; host-specific toolchains require an explicit host capability |
| Office, browser, computer use, Xcode | Separate host capabilities with current grants and validated location/artifact references; unavailable by default without that capability |
| Unsupported/macOS-only extension | Visible unavailable reason; no silent Mac execution or weakened sandbox |

Build the Cowork `winter__<key>` server/tool surface from this allowlist and its grants; do not reuse Code's whole list. Pure local file tools can execute in the guest; a Mac-native Office tool must use an explicitly admitted host path/export. The seeded Mac computer-use skill is not guest-native and must be omitted or supplied only with an authorized host capability. Guest stdio cancellation, MCP reconnection and hook descendants count as workspace occupancy.

## Provider and Git gateways

Provider credential callbacks currently return usable credential material. Cowork instead needs a new host-provider transport: keep the agent loop/history/tool execution in the guest, send a bounded versioned provider turn request to the daemon, and execute existing provider-runtime adapters there with host-held credentials. Return the normalized event stream and required opaque continuation state to the owning guest runtime. Reuse the existing request/event contracts where possible; this is SDK/router integration work, not simply a `baseUrl` setting or generic header-injection promise. [Current credential transfer](../packages/core/src/runtime-sdk/host-credentials.ts#L175), [provider bridge types](https://github.com/yanlingLabs/winter-agent-sdk/blob/27f1c43e8383582ce73e544237bcfa6fb3721db3/packages/runtime/src/provider/bridge.ts#L28)

Host resolution binds provider/model/account/destination to the admitted session. Preserve Console bearer/beta-header handling, Codex OAuth single-flight refresh, provider-specific signing/auth and endpoint policy. Cover subagent models, advisor, WebFetch digest and Exa search as separate authorized routes; ordinary page fetching still obeys network policy. Unsupported provider/auth combinations are unavailable until their transport is implemented. Never return credentials as a fallback. Test streaming, cancellation, refresh races, retries before committed output, no blind replay after partial output, redacted errors and native-state continuity. Guest-supplied URLs/headers cannot select an arbitrary credential destination. [Provider auth](https://github.com/yanlingLabs/winter-agent-sdk/blob/27f1c43e8383582ce73e544237bcfa6fb3721db3/packages/provider-runtime/src/adapters/anthropic/messages.ts#L1488), [host credential routes](../packages/core/src/runtime-sdk/host-credentials.ts#L108)

GitHub connection is new product work; the audited host auth code has no existing selected-repository GitHub connection satisfying this contract. Add account/repository selection, least-privilege token storage in the host Keychain, refresh/revocation and API metadata. GitHub repository-scoped permissions do not themselves enforce Winter's feature-ref policy. [GitHub installation token scope](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app)

Use a host-owned Git smart-HTTP gateway for admitted clone/fetch/push operations. For push, parse and validate every receive-pack ref update, including multi-ref operations, deletion and non-fast-forward changes; forward credentials only after checking the canonical repository, current branch/ruleset metadata, source revision and saved operation authority. Read operations, private cloning, redirects and submodule/LFS destinations each need their own admitted scope. No reusable Git token or unrestricted credential helper is passed to guest Git. A thin tunnel that merely injects a token is insufficient. Deny unknown/unverifiable ref policy rather than guessing from a branch name; remote GitHub protections remain additional enforcement. This gateway is a required implementation component, with protocol and destination tests before automatic push is exposed.

Feature-ref enforcement covers publication using Winter-held Git credentials. It cannot constrain independent credentials or authenticated channels present in granted files or otherwise supplied to guest tools. With ordinary outbound Internet, do not claim universal prevention of pushes through that independent authority. This is a limit of enforcement, not permission for an agent to evade the user's publication instructions.

Generate the completion obligation from the host's current publication policy in runtime context on every relevant turn/resume, with policy/source revision. The editable shared WINTER.md contains optional working guidance and may narrow the requested behavior; deleting its seeded text does not delete the generated default. The UI describes the configured default, subject to task-specific instructions and current permissions. Policy changes do not rewrite user guidance or require migrating old seed paragraphs.

## Network and mounted-folder behavior

Enforce network policy outside agent-controlled Linux. The baseline is an embedded host-owned userspace network endpoint attached through a validated VZ file-handle network device; a required host proxy may handle supported application protocols, but there is no parallel direct NAT/bridge bypass. Containerization integration and throughput are gate-1 work. Run this packet stack in native code on dedicated queues/threads, never on Bun's JavaScript event loop. Use bounded queues and backpressure for both packets and JS event delivery. The network endpoint, VM controller and provider transport share the daemon's process/crash domain; threads do not make them fault-isolated. Gate 1 measures aggregate daemon CPU/memory, event-loop delay and UI/approval/provider tail latency under concurrent guest traffic, streams and lifecycle work, not just packet throughput. Saturation must not disable enforcement. Guest environment proxy variables alone are not enforcement. Apple NAT describes routing, not a host/LAN grant boundary. [VZ file-handle attachment](https://developer.apple.com/documentation/virtualization/vzfilehandlenetworkdeviceattachment), [VZ NAT](https://developer.apple.com/documentation/virtualization/vznatnetworkdeviceattachment)

Permit ordinary outbound Internet within workspace policy; deny host/LAN/private/link-local destinations until a specific grant exists. Check resolved addresses, redirects and actual connection destinations, including IPv6, gateway aliases, alternate DNS and rebinding. Broker traffic uses its authenticated channel separately; a local model endpoint gets a scoped host service grant, not general host networking. Unsupported network protocols fail visibly. No unrequested inbound listener exposure. Host enforcement tests cover raw sockets, UDP/QUIC, IPv6, direct IP, DNS alternatives, proxy bypass and revocation.

A Winter folder grant is separate from macOS permission for the signed app/daemon/controller. Validate actual picker/bookmark/TCC handoff and the service performing access; maintain required access for the share lifetime and revalidate after restart. Do not assume UI consent transfers across executable identities or request Full Disk Access by default. Protected, iCloud, removable and network locations need explicit acceptance tests; revoked/missing access blocks the source without losing its identity or data. [Apple file privacy](https://support.apple.com/guide/security/controlling-app-access-to-files-secddd1d86a6/web), [bookmark scoping](https://developer.apple.com/documentation/foundation/nsurl/bookmarkdata%28options%3Aincludingresourcevaluesforkeys%3Arelativeto%3A%29)

Mounted folders retain host filesystem behavior, not an ext4 compatibility promise. Test case sensitivity, Unicode names, executable bits, ownership, symlinks/hard links, atomic rename, file watching, Git locks and simultaneous Mac/guest access, plus many-small-file performance. Report limitations; do not automatically normalize filenames or rewrite Git metadata. [APFS semantics](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/APFS_Guide/FAQ/FAQ.html)

Keep Linux and Mac native dependencies/build products separate. Prefer persistent guest cache/build locations keyed by OS/architecture/toolchain where supported. Runtime guidance must warn that project-local `node_modules`, `.venv`, `.build` and native outputs in a direct mount affect the Mac checkout. Do not silently overwrite/reuse Mac native dependencies. Where a tool requires conflicting in-tree artifacts, the agent chooses an explicit supported workflow, such as a worktree. No invisible per-file overlay or routine project copy is promised.

The same host folder may be explicitly granted to multiple workspaces and to Code sessions. Explain the overlap: files and filesystem-mediated communication are then shared across those grants, and one workspace's removal does not revoke another's independent access. This accepts normal concurrent editing without weakening exclusive ownership of each VM disk. No implicit union of grants, credential authority or session visibility follows from sharing a directory.

## Daemon lifetime, sleep, resource coordination and retention

Embedded VM control follows the owning daemon. Plan for all owned guests to lose their live runtime on daemon exit; do not promise adoption of a VZ object by a replacement process. Verify actual guest/backing-service termination in the signed feasibility slice, and never treat controller PID death alone as proof that writable volumes are safe to reattach. The current Mac app supervisor stops its daemon on app quit; closing a conversation view is different from explicitly quitting the application. Explicit Quit warns when Cowork work is active, occupancy is unknown, or enabled Cowork schedules exist, names the affected workspaces/conversations, and explains that this daemon's Cowork work stops and scheduled execution requires a running daemon. Offer cancel/keep running or quit-and-stop; do not imply quitting one profile stops independently owned daemons. The 30-second budget below bounds graceful drain, not proven VM termination. [App supervisor](../apple/Winter/Sources/App/DaemonSupervisor.swift#L47)

For intentional quit/restart/update: close admission and new schedule claims after beginShutdown, cancel or drain task-owned work, flush guest state/events and stop guests while broker/store services required for draining remain available. Then close stores and release ownership. Start with a documented 30-second graceful shutdown budget; on expiry mark unfinished calls uncertain, persist the recovery marker and request forced termination, retaining disk ownership until termination is established. Scheduled automatic updates defer while Cowork occupancy is nonzero or unknown; an explicit user restart can interrupt work under this bounded shutdown contract. Never claim a timed-out flush succeeded. [Daemon stop order](../packages/core/src/daemon.ts#L3047), [updater gate](../apple/Winter/Sources/App/UpdaterCoordinator.swift)

On a crash, recover durable state and reconcile uncertain effects; do not replay publication or other external side effects blindly. Exercise SIGKILL, fast relaunch, stale Apple service cleanup, stream loss, disk-full and restart-during-drain. The old-guest ownership proof remains mandatory before another incarnation attaches the disks.

System sleep closes new admission and attempts a bounded checkpoint without promising completion before forced sleep. Display sleep alone is not VM shutdown. On wake, reconcile incarnation, transport health, current grants, network state, timers and task ownership. Resume a healthy live guest when verified; cold-recover a failed one only after termination is established. Reconnect expired provider/broker streams without blind replay; coalesce missed schedules using their recorded occurrence policy. No default sleep-prevention assertion is required. [Apple sleep notifications and limits](https://developer.apple.com/library/archive/qa/qa1340/_index.html)

Automatic resource admission coordinates participating daemons for the logged-in user, including dev/dist/custom homes, through an atomic host admission ledger and owner records; it is not just a private counter in each daemon. Production coordination lives at `~/Library/Application Support/Winter/Coordination/cowork-admission.sqlite`, outside all supported Winter homes; a home may not contain or overlap that coordination directory. Protect the directory and SQLite sidecars with owner-only permissions and the host control-storage fences. Records bind daemon identity, canonical home identity, PID, process start time, OS boot identity, instance nonce, heartbeat and reservation state. Reclaim stale admission only after validating owner death/identity mismatch; an expired heartbeat alone is not proof. Unknown ownership blocks/requires recovery. Admission reclamation never substitutes for guest termination/disk-lease proof. Observe total host pressure, including other users/apps/VMs, and avoid optimistic admission if coordination is unavailable. This requires no per-workspace host controller process. Test competing boots, owner crashes and stale records separately from VM disk leases. Do not claim control of every VM on the machine.

Tests and injected-secret harnesses default to a fake backend and receive a separate temporary coordination path and owner namespace before initialization. They never read, lock, mutate or fall back to the real per-user ledger, even with a custom WINTER_HOME. Explicit real-VM tests still use their injected ledger and are never proof of production multi-daemon coordination unless that isolated scenario is exercised. Real VM tests require explicit opt-in and disposable homes/sources, never the live Winter home or real credentials. Custom-home/dev VM use is explicit opt-in, with process-owned temporary image cleanup after confirmed guest termination. Production VM creation follows authenticated user workspace actions, not merely daemon startup.

Apply an automatic disk-pressure guard to every backing filesystem, including host-backed memory/outputs, selected writable host sources and sparse environment/data disk backing. Begin with a tunable 5 GiB free-space reserve; monitor allocated shared-data growth, actual available space and OS pressure across participating workspaces. At the threshold, refuse new write-producing work, publish `resource_blocked`, and cancel/halt active writers; enforce a read-only view/share or stop affected guests if needed. Never delete memory, outputs, dirty repos or selected host files automatically to regain space. This is a reactive pressure guard, not a hard quota: concurrent/in-flight writes and unrelated host activity can overshoot. Preserve durable data and recovery evidence when possible; checkpoint/marker writes may fail, and emergency stop cannot promise every in-flight byte survives. This visible persistence-protection interruption is an exception to routine idle-only stopping, not eviction to start another VM. Gate readiness on measured response/overshoot and viable reserve margin under multi-guest, large/sparse/many-small-file and host-write stress, including stale handles or failed read-only transitions. If adequate protection cannot be shown, require quota-capable backing before exposing unrestricted shared writes. Resume only after pressure and uncertain operations are revalidated.

Deleting a standalone conversation does not silently destroy its workspace. Detach/archive its workspace for explicit later deletion/export; show retained dirty repos, data and disk usage. Empty-session reapers, runtime retention and model-driven session cleanup may not delete Cowork volumes or shared Project data. Workspace deletion is a separate explicit destructive operation after stop/ownership checks; selected Mac folders and their prior edits are never deleted by it.

Keep mutable volumes, host-shared workspace files and manifests eligible for normal backup by default. Do not silently exclude the only durable SDK state. Provide a consistent export of stopped/checkpointed volumes plus manifest, shared-file snapshot and required image/runtime digests, bound to one recorded export generation, then prove dirty-work and parent/subagent restoration. Stopping the guest does not freeze direct user writes to host-backed files: obtain a consistent filesystem snapshot or establish quiescence for capture; retry/refuse the export if consistency cannot be established. Live copies are crash-consistent at best unless coordinated; selected external Mac folders have their own backups and are not rolled back with the guest. Exclude only reproducible caches after reacquisition is proven. Measure sparse-image transfer/storage on supported backup destinations; neither whole-image recopy nor efficient changed-block backup is established by this research. [Apple Time Machine overview](https://support.apple.com/en-gb/104984)
