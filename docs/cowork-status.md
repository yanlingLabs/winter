# Cowork implementation map

As of 2026-10-15, Winter cannot create or run a supported Cowork session. Code, Chat, and Dispatch are the implemented daemon modes: `SessionModeSchema` in [methods.ts](../packages/protocol/src/methods.ts) is still `code`, `dispatch` and `chat`, and the runtime SDK's `RunMode` still excludes Cowork. Cowork has host-side workspace infrastructure, Mac screens for workspaces, shared guidance and schedules ([later status](#later-status-2026-10-15)), visible UI placeholders for the composer and Dispatch `/spawn`, reserved names, and reusable infrastructure. A reserved predicate or a passing synthetic test does not make it a working product mode.


The 2026-10-12 accepted native-host policy preserves ordinary Code/tool execution without a persistent outer floor or first-activation restart debt. Core file checks and the existing single Bash sandbox protect registered paths; approved escapes keep their normal approval behavior with static write-shaped Cowork integrity checks. Activation refreshes Code incarnations/run homes while preserving queued messages and logical identity, and uses acknowledged live updates for Chat/Dispatch with the independently accepted SDK v1 nine-family context contract, preserving ongoing turns. Protected cold startup waits for its matching Worker acknowledgment. The installed SDK pin remains unchanged and lacks the contract; that version still requires existing embedded Workers to close and refuses protected Chat/Dispatch. Explicit owned-worker/bridge floors and host credential protection remain requirements; separate per-workspace encryption is deferred for the first version. Private images are plaintext, protected offline by FileVault only when enabled, and readable by same-user processes or approved escaped commands, which run as the user; these changes do not pass the production Cowork gate.

This map covers the Winter host and its sibling agent SDK, runtime SDK, and iOS repositories. It describes source behavior; the unavailable Cowork mode has no end-to-end execution to validate. Outstanding work is tracked in [Follow-ups](../follow_up.md#cowork).

The 2026-10-11 [workspace metadata API slice](cowork-workspace-api.md) adds canonical host RPC reads/mutations and isolated daemon fixture coverage. Production Cowork creation/execution and client availability remain blocked; the historical infrastructure map below is retained.

The [implementation ledger](cowork-implementation.md) tracks subsequent native VM, RAM return, protected-store, key-broker, host-output and CLI work, including their remaining gates. The tables below describe the original source audit, not the latest implementation branch inventory. Two rows whose text became false are corrected in place and marked *(updated 2026-10-15)*.

## Later status (2026-10-15)

The 2026-10-12 text above and the tables below remain the audit record, except where a row is marked updated.

- **Still true: no Cowork session can be created.** `SessionModeSchema` ([methods.ts](../packages/protocol/src/methods.ts)) is `code`, `dispatch`, `chat`. The runtime SDK's `RunMode` is `code`, `dispatch`, `chat` on its `main`.
- **The Mac surface is no longer only a landing page.** [PR #39](https://github.com/yanlingLabs/winter/pull/39) (merged 2026-10-15 into `cowork/output-integration`) adds a shared-guidance editor and a schedules view to the workspace screen. With a management connection the Cowork sidebar destination opens that screen (`CoworkWorkspaceView`, [ShellSidebar](../apple/Winter/Sources/AppShell/ShellSidebar.swift)): the workspace list, the guidance editor and the schedules list. [CoworkPlaceholder](../apple/Winter/Sources/AppShell/CoworkPlaceholder.swift) is now only the fallback when the shell has no management connection. Workspace *creation* and the composer send are still disabled: the daemon reports `provisioning: false` and `execution: false` ([service.ts](../packages/core/src/cowork/service.ts)), and the New-chat page refuses to send in Cowork mode. Creating schedules is not in #39.
- **The host now has more than metadata.** Winter PRs #29-#39 merged into `cowork/output-integration` after the audit: guest query composition, current-context planning and resolution, shared-guidance get/update, host schedules, a durable workspace outbox with local watch leases, bounded output reads and the Mac views. The [implementation ledger](cowork-implementation.md#later-status-2026-10-15) lists them one by one.
- **The agent SDK now has Cowork guest-runtime work, not none.** `winter-agent-sdk` has 23 merged PRs; the search `gh pr list --repo yanlingLabs/winter-agent-sdk --state merged --search cowork` matches six of them (#1, #3, #8, #14, #20, #24), and the others (for example #4, #5, #7) are guest-runtime PRs on the same lane. Confined-guest query startup still refuses on its `main`.
- **The runtime SDK** has 16 merged PRs (#1-#16: guest transport, plain-guidance admission, structured instruction reads and source-only reader tooling). Its `RunMode` still excludes Cowork.
- **Still open:** supported creation, the Cowork prompt and tool surface, the composer send, folder and approval chips, session windows, Dispatch `/spawn`, and any iOS surface (the iOS app is unchanged since 2026-10-10).

## What still blocks a functional mode

1. **Session identity and creation.** The [create schema](../packages/protocol/src/methods.ts), [session event schema](../packages/protocol/src/events.ts), [store](../packages/core/src/sessions/store.ts), and [daemon runtime type](../packages/core/src/runtime-sdk/create.ts) support only Code, Dispatch, and Chat. Dispatch separately refuses its reserved Cowork argument.
2. **Runtime and capabilities.** The [tool registry](../packages/core/src/agent/tools/registry.ts), [capability table](../packages/core/src/runtime-sdk/mode-options.ts), and runtime SDK have no Cowork mode. Its prompts, tools, permissions, and execution topology still need an explicit product contract.
3. **Connected surfaces.** The Mac composer controls and `/spawn` callback are placeholders. iOS also remains a placeholder, and the remote gate excludes a Cowork-shaped row. UI availability flags alone cannot close these gaps.
4. **Real execution coverage.** Tests for reserved predicates, injected database rows, and callback closures establish those helpers' behavior only. A functional mode needs tests through supported create, send, tools, resume, and its chosen client surfaces.

## Reading existing references correctly

- **Supported product modes and permission modes are different axes.** The SDK's older reference adapters expose permission-mode values where future product-mode metadata was anticipated. The current host messaging contract has a separate host-supplied product-mode string; neither implements Cowork.
- **There is no supported Cowork fallback.** The old `engine.ts` is gone. Current [session-driver](../packages/core/src/runtime-sdk/session-driver.ts) and [handoff](../packages/core/src/runtime-sdk/handoff.ts) helpers map an unknown raw mode to Code, while supported creation rejects Cowork. Old comments predicting a Chat fallback are obsolete; the Code fallback is not a way to enable Cowork.
- **Tool deferral is not roadmap deferral.** `deferred` in tool registration means schema loading through ToolSearch. It does not indicate that the tool or Cowork is waiting to be implemented.
- **References to an external product's Cowork are comparisons.** Mentions of that product in comparison notes or old vendor metadata do not describe a shipped Winter feature. Dated research and release notes remain historical records.
