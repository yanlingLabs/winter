**Protocol and data/control separation.** `src/devices/src/virtio/console/runtime_port_control.rs:32–50` validates exactly eight owned bytes before indexing, uses explicit little-endian conversion, and admits only the specified phase/ID/event/value tuples. DEVICE_READY uses BAD_ID and value 1; the response PORT_ADD uses reserved value 0. PORT_READY produces host PORT_OPEN value 1. Only the guest PORT_OPEN value 1 transitions to Open, and only its value 0 transitions from Open to Closed. Unknown IDs, events, values, duplicate or out-of-phase messages fail. There is no console designation, name parsing, variable-length payload, additional port, hotplug or reopen path.

`runtime_port.rs:275–325` first validates an incoming control frame, completes its generation-checked used ACK, and only then applies its transition and publishes its response. A response waiting for control RX prevents another control-TX capture, keeping the pending state bounded. A turn handles at most one control-TX head and one control-RX head. An eight-byte frame, one pending transition response and one response slot do not expose guest-backed data to the parser or host I/O. Guest close is acknowledged and then returns Stopped; the actual thread wrapper turns an unsolicited stop into the terminal access failure. Close is therefore whole-worker recovery, not a graceful reconnect contract.

`runtime_port.rs:327–407` services control before the data lane and does not capture data until the Open phase. Host reads/writes operate only on owned vectors using the inherited private nonblocking socket. One bounded write/read attempt per turn and polling of the Stop descriptor plus all four queue kicks (`:408–467`) keep a full data socket from parking the thread inside a data readiness wait. The native backpressure regression at `:1681–1737` actually fills that socket, leaves a data TX unacknowledged, submits control close, and observes its control ACK and thread completion. The ordinary 20 ms retry is a service mechanism, not a hard real-time scheduling guarantee.

The local primary Linux source at `spikes/cowork-hvf/out/stream-hvc-source/virtio_console.c:1810–1859` agrees with the four queues and their ordering for MULTIPORT/max_ports=1; `:1991–2055` supplies the successful DEVICE_READY path; `:1401–1420` leaves the port generic and sends PORT_READY; and `:1020–1068` supplies its guest-open message. This was a source cross-check, not execution of that kernel driver or proof that the separately pinned guest binary is source-identical. In particular, `:539–566` still spins in `__send_control_msg` until an ACK or broken queue. Asynchronous generic data does not make open, close or bootstrap control calls cancellable.

**Descriptor validation and memory ownership.** `runtime_port.rs:117–211` uses the shared checked-pop/whole-chain validation, checks direction even on zero-length descriptors, checks each nonempty span inside a single memory region, rejects overflowing totals, and limits TX data to 64 KiB and RX reported capacity to 1 MiB. Control TX must total exactly eight bytes; control RX must report at least eight but allocates only eight. Data RX allocates at most 16 KiB. It pins every full reported nonempty span, including unused RX capacity. Malformed NEXT, cycles, indirect/unknown flags, invalid heads, nonready queues, whole ring spans and producer-distance checks come from `src/devices/src/virtio/queue.rs:1146–1203`; they are not replaced by an unchecked generic-port walker.

The ring and request ownership is explicit: four ring pins are acquired in `runtime_port.rs:51–95`; each request retains its pin in Frame; and copying plus used completion occur under the fresh lease operation at `:216–254`. Host socket operations have no RAM lease or guest pointer. `src/devices/src/reclaim_access.rs:126–136,193–245,299–343` lets an already-admitted bounded copy finish and publish its pins while freeze waits for its lease to drop; new admission then remains closed until resume. Pending control/data buffers retain pins through freeze. Stale generations cannot perform a new copy/ACK. Native control freeze and stale tests (`runtime_port.rs:1600–1644,1768–1812`) exercise those paths.

The builder retains one shared Access budget of two devices, 32 pins and 8 MiB (`src/vmm/src/builder.rs:961–966`), registers this port as device 1, and chooses it instead of the HVC variant (`:1007–1020`). Preparation independently confirmed the inherited HVC, stream socket, access, RAW block, trace and event/lifecycle helper sources are byte-identical to the previous frozen candidate. That correspondence preserves the source baseline; it does not transfer the previous HVC run's live result to the generic port.

**Activation, reset, Stop and teardown.** `runtime_port.rs:633–651` requires both advertised features, rejects duplicate/pending activation, and validates all four ready queues before starting the worker. The concrete MMIO branch at `src/devices/src/virtio/mmio.rs:331–337` handles BadActivate by stopping access and marking FAILED without unwinding through the device mutex. The two actual MMIO regressions configure status 1/3/11 before queue registers, then DRIVER_OK; they cover nonready and ready/cross-region refusal and assert terminal notification, no poison, no activation and no retained pins.

`runtime_port.rs:529–584,657–670` keeps an old worker, its rings, requests, memory and socket aliases alive until actual thread completion/join. Reset requests Stop, retires the generation, and can stage all four new ring owners while waiting for that old owner. The new worker begins with a fresh handshake. The VMM tick clones device references while holding the VMM mutex and releases that mutex before device lifecycle work (`src/vmm/src/lib.rs:479–483`); the existing main-loop finite lifecycle retry remains at `src/libkrun/src/lib.rs:3108–3116`.

Retirement fences guest-memory operations, not every already-started owned-byte socket operation. Reset can therefore consume/deliver some already-started bytes without an old-generation used ACK, as already documented. It provides no exactly-once delivery, replay rejection or authenticated boot-generation boundary. `GuardedPort::drop` requests Stop and drops its JoinHandle (`runtime_port.rs:673–680`), so it does not itself prove a reusable in-process destructor join. Normal VMM Stop still calls `_exit` after exit observers (`src/vmm/src/lib.rs:387–401`). Worker termination/reaping and bounded external recovery must be proved at the enclosing process boundary.

**Closed factory and endpoint custody.** `src/libkrun/src/lib.rs:3273–3303` checks context existence, RAW/reclaim opt-in and duplicate/mutually exclusive stream creation before making the socketpair. Only the opposite peer is published via `into_raw_fd`; the device endpoint stays in context state and internal duplicates remain encapsulated. The old caller-FD setter remains a refusal. `src/devices/src/stream_io.rs:17–82` owns both FDs immediately, normalizes them to FD ≥ 3/CLOEXEC, configures the private end nonblocking with SO_NOSIGPIPE, and closes newly created endpoints on failure. Public per-call nonblocking/SIGPIPE flags remain additional defenses. The C API does not accept or authenticate a workspace, runtime packet or credential request.

CLOEXEC is not fork confinement, and private Rust fields are not a hostile-same-process boundary. The purpose-built worker must already deny fork/exec before factory use and must not fork afterward. This review preserves that existing launch contract; it does not claim the library or native unit tests enforce production worker containment. Separate per-workspace encryption and key delivery remain deferred under the approved v1 storage decision and are not acceptance requirements for this nonsecret transport source.
