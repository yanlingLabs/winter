**Destructive authority is consumed before handoff.** `packages/core/src/cowork/volumes.ts:334` refuses caller transactions and absent filesystem authority. It performs descriptor/backup preflight, then reauthorizes and rereads current owner/canonical rows under a top-level IMMEDIATE transaction. Both targets must be ready or genuinely unformatted/eligible, and no local writable handle may be outstanding. The transaction binds both exact volume/creation/identity/geometry/UUID targets plus owner/incarnation/lease/runtime digest to one random operation nonce, consumes format eligibility and persists formatting/probing state. The plan is returned only after transaction completion; the crash checkpoint is after commit. Subsequent preparation refuses an in-flight or recovery-required state rather than recreating a format request.

An ordinary writable `open` on an unformatted volume burns eligibility and records recovery-required before returning its fd (`volumes.ts:319`). Failed transaction completion closes the pending descriptor without publishing it. New plan rows alone mint initial UUID/eligibility. Ready volumes can receive only probe-existing work; stop/release never restores format eligibility. Failures narrow availability while preserving the existing canonical disk owner; actual release still requires the original stop-authority path. These rules prevent the implemented controller from automatically reformatting exposed, migrated, ambiguous or previously prepared volumes.

**A matching JSON receipt cannot authorize itself.** `volume-filesystem.ts` validates closed scalar/object shapes, exact ordered distinct targets, bounded geometry and UUIDs. Confirmation rebinds the stored plan to current canonical rows and matching formatting/probing actions. It requires current authorization, exact receipt equality for every target/observation, and positive mandatory `verifyReceipt` proof before atomically recording both volumes ready. Missing authority refuses; no guest-ready boolean/PID/metadata-only fallback exists. `filesystemsReady` rechecks current ownership, matching journals, file identity/exclusion and authority; a new owner must probe using a fresh nonce. Native verifier callbacks remain trusted, unimplemented integration responsibilities. Because these checks run inside the writer transaction, the eventual adapter must perform bounded non-effectful verification there, not start or wait for formatting processes.

**Migration preserves data and fails closed.** Schema 10 rebuilds only the volume table, preserving volume/creation/file/owner/stop identities and allocating no new files. Existing v9 rows become recovery-required with null UUID and zero eligibility: allocation history is not asserted to prove virgin contents. The migration is committed with its schema version through the existing transaction machinery. Empty-only rollback still refuses populated Cowork authority and does not discard backing data. Malformed journal/ready-without-receipt states refuse; no automatic adoption, UUID rewrite, repair or image recreation is introduced.

The fixture receiver's authenticator is an exact-plan test object, not production native authentication.

`bootstrap.py:138` refuses non-Linux before authentication/helpers; authenticates and validates the closed plan and both pinned regular RW/non-append single-link owner/mode/size/identity descriptors before consuming the operation.
