## Decisions (each a default the coordinator confirms or overrules)

- **Where the proof lives.** CDHash plus pin hashes in a manifest under `Contents/Resources`, not a file inside `Helpers/WinterCowork` (a non-code file there would be sealed or rejected as code). `-dvvv` is needed for CDHash; `-dvv` omits it.
- **What "image pins" means today.** No image ships in the app yet, so the gate binds the bundle to the checkout's pin files (the worker's libkrun pins and the guest artifact `pins.json`) by hash. When an image is embedded, its digest joins the manifest.
- **The release chooses explicitly (coordinator ruling).** `release.ts` takes the libkrun inputs (`COWORK_LIBKRUN_INCLUDE` + `COWORK_LIBKRUN_ARCHIVE`) or `COWORK_NATIVE=omit`; neither, one input alone, both, or any other value fails before anything is built. Omit is loud (it prints), total (the phase skips and strips, nothing is built or gated, both hardening pins skipped) and asserted (the release requires `Helpers/WinterCowork` and `cowork-native-pins.json` to be ABSENT). A Debug build, or a Release xcodebuild with no `dist/cowork-native`, still builds and embeds nothing; exactly one input is an error. `sparkle-feed-gate.ts` passes the omit.
- **Dev pair location** `dist/Helpers/WinterCowork` follows from the environment's `dirname(executable)/../Helpers/WinterCowork`.
- **CI** runs `verify:cowork-native` (about 25 s: one `swift build`). Say the word to drop it.

## Dev builds and the team id

The launcher compiles in the team `37N77U9RSZ` and checks its worker against it; the daemon expects the same team on the launcher. A dev build signed with another team, or ad hoc, therefore fails closed (by design). `dev:cowork-native` signs with the team identity (`WINTER_DEV_SIGN_IDENTITY` overrides) and allows ad hoc only into a scratch `--out`.
