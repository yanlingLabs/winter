# Workspace descriptor handoff draft

This is an unintegrated fixture primitive, not production launch authority or a completed two-disk worker. It receives one fixed versioned datagram and exactly two SCM_RIGHTS descriptors, applies CLOEXEC, and preserves caller-owned channel handles. The native pair API must independently validate inode/ownership/geometry and reject aliases. The envelope's metadata is not authentication. Installation of the worker sandbox must precede receiving handles; neither this helper nor its tests establish that ordering yet.

Local C tests compiled with `-std=c11 -Wall -Wextra -Werror` against the actual reviewed candidate header. Seven cases cover a valid pair, missing/single/extra descriptors, twenty extra descriptors, bad version and oversized payload. Nonterminal refusals preserve descriptor count and the sender's original descriptor. No library start, signed worker, VM, filesystem format, live home or credentials are involved.

A smaller receive-buffer experiment exposed a macOS-specific cleanup hazard: receiving twenty descriptors into a sixteen-descriptor ancillary buffer left three installed descriptors that were not reported in the parsable control message. The original assertion failed (descriptor count 6 to 9). The helper therefore treats `MSG_CTRUNC` as a terminal result (-2); the future worker must exit immediately, without acknowledging handoff or releasing canonical ownership. Closing only the visible descriptor list is insufficient. The regression uses a reduced capacity and verifies the receiver process exits with its explicit terminal status. Production capacity is 256; that size reduces truncation likelihood but is not a correctness assumption.

Both normal-capacity and reduced-capacity subprocess tests pass. This is process cleanup evidence only, never native device drain or volume-release proof. Independent review and worker integration remain required. Existing fixture caches, raw evidence and prior candidates are unchanged.
