**Blocking finding — valid starts reject their own constructed disks.** Native `src/libkrun/src/lib.rs:2877–2881` rejects a workspace pair if `r.block.list` is nonempty. `krun_start_enter` invokes that validator at line 2931 with the initially empty list, then constructs and publishes the two admitted devices at lines 2968–2971. It invokes the same validator again at line 3085 immediately before identity changes/VMM allocation. That second check necessarily rejects the two correctly constructed devices with EINVAL. The context has already been removed from CTX_MAP, so this failure also consumes/drops the attempted context. This conclusion follows directly from the exact production call sequence; no start/VM call was needed to establish it.

The successful constructor test builds into a separate local variable and the profile-positive test only checks the preconstruction context, so neither exercises this transition. Fix validation to distinguish preconstruction admission from the normalized, internally constructed state and verify exactly the admitted pair/provenance at the latter boundary. Do not simply remove prebuilt/extra-device rejection. Add a no-VM regression that runs the actual preparation path through both validation phases: the valid pair must reach the final pre-VMM handoff, while prebuilt/extra/reordered/substituted or incompatible devices and metadata drift remain refusals. Failed preparation must retain correct descriptor cleanup. Freeze new patch/build hashes and re-review the correction before any worker/VM run.

**Other reviewed boundaries.** No additional blocker was found in the remaining new FD/storage code. `workspace_disks.rs:30` duplicates borrowed descriptors using F_DUPFD_CLOEXEC and immediately owns each result as File. Metadata/access validation rejects non-regular files, link count other than one, wrong current UID or exact0600 mode, append/read-only descriptors, expected dev/inode/size mismatch and invalid 16 MiB–256 GiB/aligned4096 capacities. The pair rejects same-inode aliases and revalidates both after intake. Partial intake/duplication failures release newly owned files without closing caller descriptors. Further block copies retain immutable expected metadata; there is no stored volume pathname or /dev/fd reopen.

The C ABI uses repr(C) with u64 device/inode/capacity and u32 UID/mode, matching the public 32-byte structure. Null pointers and unsupported context/profile states refuse before dereference. As a trusted unsafe C API, nonnull pointers still require valid aligned caller storage; this is not a hostile guest-message parser or daemon/workspace authority mechanism. Caller FDs must stay stable through the synchronous borrowed call. CLOEXEC does not substitute for the enclosing worker's no-fork policy.

`workspace_raw_storage.rs` avoids imago File conversion's construction-time alignment write probe. The pinned Raw open implementation only calls storage.size before wrapping it. The new storage owns its file, validates metadata before I/O, validates the whole vector's offset/length before transfer, handles short/EINTR/zero/error results, and refuses resize/growth and implicit open/create/relative-path fallback. The normal guest path retains the existing bounded block-bounce request limit. Full sync calls File::sync_all, matching the pinned imago full-sync branch; this is not power-loss/drive durability proof.
