# Guest packaging parser bounds correction

Parent packaging commit `cf1c3bfedacb50fe4af224853aaeb242171d6ee5`; same artifact worktree. Independent review found cached reads allocated before size/hash checking, index XZ expansion checked only after decompression, and uncapped control tar member/body parsing. This source correction changes no pinned package/runtime/helper/image bytes and launches nothing.

Cached package/index/key reads now open a no-follow/nonblocking/CLOEXEC descriptor, require a regular file, and compare descriptor size to the configured/declared bound before reading. Chunked reads retain a limit under file growth or network responses. XZ output is capped while decompression runs, with a 64 MiB decoder-memory limit; the package index parses incremental UTF-8 lines/records rather than allocating the complete expanded index. Limits are 128 MiB total expanded index, 128 KiB lines and 256 KiB paragraphs. The real authenticated main index contains a 75,649-byte line, so a trial 32 KiB cap was correctly rejected and adjusted explicitly; the security index maximum is 20,755 bytes.

Control metadata is decompressed through bounded readers before tar/PAX processing: 2 MiB total, 128 exposed entries and a 64 KiB regular control file. Headers are iterated, not collected through getmembers, and body reads are explicitly capped. The same streaming primitive caps package payload metadata/output at 1 GiB with 32,768 exposed entries; individual admitted payload bodies remain at most 128 MiB. No maintainer script or package executable runs.

**15 regression tests passed**. New small fixtures exercise size refusal before reading/hash, normal cache/index reads, XZ output/dictionary limits, index line/paragraph limits, control body/aggregate limits and valid control identity. Inputs are bytes/kilobytes, not stress allocations. Existing GPG-tamper, corrupt-deb, traversal, conflict, ELF/ar and packed metadata tests remain.

The real signed snapshot/index pipeline succeeds using the existing cached artifacts; its package lock remains `b0127b7a8f1fa2f8b2a06236cef26e1f1b297bacf9d70e800440df8747d93252`. All 84 actual control identities pass. Re-extraction with bounded readers produces 7257 package nodes whose type/mode/content hashes all match the frozen artifact's environment subtree. No image/runtime/helper rebuild or relabeling occurred. Previous failure/success artifacts and history remain retained; the final cpio/gzip identities are unchanged. `git diff --check` passes. This is a parser-bound correction, not VM or production readiness acceptance.
