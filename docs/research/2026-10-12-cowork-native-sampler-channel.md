# Dedicated native fixture host-sampler capture

Fixture source fix based on `1856a188`, isolated branch `cowork/native-telemetry`. The independent generic post-run review found the original normal request-665 ACK bytes interrupted by a complete C memory sample on shared stderr. The original captures, results, build receipts, hashes and two malformed lines remain unchanged. No reconstruction was added to the normal capture parser.

`generic_fixture_worker.c` now requires one extra inherited sampler descriptor. The supervisor creates its anonymous pipe inside the existing owned-child cleanup guard; the caller supplies neither a file path nor an arbitrary sampler descriptor. Popen admits exactly the control socket and sampler write endpoint with other descriptors closed. The worker verifies canonical numeric FD, distinct from stdio/control, anonymous-unlinked FIFO metadata, owner UID and write-only direction, then sets CLOEXEC and nonblocking mode before sandbox/library setup. Linked named FIFOs, files, sockets, read endpoints and duplicated stderr are refused. The descriptor is never passed to libkrun's stream factory, the guest environment or any guest device API.

`generic_sampler.h` formats the unchanged host_memory fields into a record below 512 bytes and writes it once to the dedicated pipe. EINTR before completion retries the same atomic record; short/error/EAGAIN writes fail rather than blocking or falling back to shared stderr. The fixture worker exits 78 if a sample cannot be captured, so it cannot quietly count dropped samples as evidence. This logging-failure exit is not a clean workload/effect guarantee. Rust telemetry remains on stderr. Accepted backend 0011 and the guest workload/kernel/initramfs sources are unchanged.

The new `generic_capture.py` keeps the frozen stream-v2 module untouched. It reuses the existing Limits and owned-child finish implementation and captures `stdout.log`, `stderr.log` and `sampler.log` independently with the same 32 MiB per-channel, 48 MiB total, 64 KiB line, 80,000 parsed-row, 64-queue-item and 16 KiB chunk bounds. No bound was raised for the third channel. Each reader uses nonblocking reads and a 50 ms stop poll. Byte limits, process kill/wait and reader joins remain finite and recorded. Sampler rows carry channel=sampler and the existing host monotonic observation timestamp; existing footprint auditing filters by kind, while native ACK rows remain on stderr.

Malformed JSON-bearing lines are counted by channel and preserved exactly in raw logs; they are not repaired or reassigned. Primary capture completion still describes pipe/lifecycle completion, not semantic validity of every line. The receipt's malformedJsonLines makes that distinction inspectable. An incomplete guest terminal-close line remains a partial receipt, not fabricated complete JSON.

Lifecycle cleanup closes both sampler endpoints when spawn/setup fails, closes the parent writer immediately after successful Popen, and closes capture streams after bounded readers have joined. If a custom/unjoined reader prevents safe closure, samplerClosed/ownersQuiescent remain false and disk/raw inspection stays refused. An uncertain child exit never becomes termination proof because the sampler FD closed. The existing socket/stream peer/oracle ownership cleanup remains in place.

Build/launcher bindings include the new header and capture module. A dedicated-inherited-pipe-v1 build marker is required before any launch; prior fixture artifacts/receipts cannot silently run with the new argc/channel contract. Source/header changes also prevent receipt-only reuse of an old worker. No full fixture build, signing, libkrun worker launch or VM was performed in this slice. A new reviewed fixture build/receipt and separately authorized run are still needed for a clean live aggregate.

## No-VM validation

A small actual C helper uses the same descriptor admission and sample writer. Its two threads concurrently produce 20,000 host_memory records and 20,000 deliberately fragmented native trace records. The capture checks every JSON line and exact sequential sample/request identities, with zero malformed rows and no sampler bytes in stderr or trace bytes in sampler.log. This is actual native writer/capture concurrency, not a rerun of Rust/libkrun or a VM.

Additional tests cover exact CLOEXEC/nonblocking setup, wrong types/direction/aliases/named FIFOs, sample-pipe writes under macOS deny-default without extra file-path rights, original limit equality, per-channel/total/line/row overflow, preserved malformed bytes, partial reader startup, spawn/setup/cancellation cleanup, uncertain reaping, oracle joins and synthetic normal-runner aggregation. The macOS sandbox helper has no libkrun or VM code. Worker C syntax is checked against the existing pinned libkrun header with the actual warning/error flags. Python modules pass py_compile.

Validation: **40 focused no-VM tests passed** across sampler, generic lifecycle/discovery, block receipts, stream lifecycle and the synthetic normal-runner case. C worker `-fsyntax-only -Wall -Wextra -Werror` and Python py_compile pass. No fixture artifact was rebuilt and no original result/log was staged. This fixes fixture telemetry serialization; it does not change the original failed aggregate or pass Cowork's full production/resource gates.
