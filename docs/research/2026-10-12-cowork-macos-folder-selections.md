# Mac folder selections and capability projection

Base UI commit: `b0c2ca58a16aca5492c4e1ac30a82ccac91d1525`. Branch: `cowork/macos-selections`. This slice implements real Mac folder selection preparation through the daemon's existing `CoworkHostPorts.selection` adapter. It does not enable workspace provisioning, source mounting, GitHub authorization or Cowork execution. No DB/schema version change; schema-10/durable grant consumption remains root integration work.

## Boundary and implementation

New strict, local-only RPCs are `workspace.capabilities.get`, `workspace.selection.prepareFolder` and `workspace.selection.revoke`. They are excluded from paired allowlists; Gateway and daemon refusals are tested. Service role/principal checks reject plugin/runtime/paired callers before a preparation can be minted. Current local harness/admin authentication authorizes the operation; clientName and caller-provided principal fields never establish authority. A bookmark supplies location evidence, **not cryptographic evidence of a user gesture**. This does not claim signed Mac-client admission or same-user confidentiality.

The normal Mac picker produces an implicit URL bookmark and sends bounded bookmark bytes, access intent, safe label and request ID. No raw path/bookmark field is added to workspace creation/source-add requests. Explicit app-scoped security bookmarks are not presumed to delegate the app's sandbox scope to the daemon. CoreFoundation resolves without UI, mounting or implicit scope start, rejects stale/non-file URLs, and balances any successful explicit security-scope start with stop. A false scope-start result may mean an unsandboxed daemon needs no extension; actual directory traversal and effective read/search/write checks must still succeed. No scope delegation or TCC behavior is claimed from that false result.

The host checks current protected roots and ancestor/descendant/alias spellings. Default roots include participating Winter homes, the coordination directory and host SSH/AWS/GnuPG/Keychain directories. It walks the canonical directory with descriptor-relative no-follow/CLOEXEC opens, pins its device/inode, then re-resolves/reopens and checks again after intake before publishing. Every selection/grant lookup revalidates the bookmark, current protected-root registration, path, permissions and pinned identity. Relocation, missing/replaced directories and stale bookmarks fail closed; none silently becomes the same grant.

The returned projection contains only opaque selection ID, folder kind, label, access, prepared state and informational expiry. The host owns the distinct grant/root IDs, bookmark, scope and directory FD. Selections bind both authenticated local principal and issuing connection. A five-minute maximum **monotonic** lifetime limits preparations; wall-clock expiry is display only. Expiry, revocation, connection close and daemon/server stop close scope/FD and clear sensitive bookmark bytes. Closed registries cannot issue new grants. Bounds are 16 live preparations per principal/connection, 128 globally and 64 KiB decoded bookmark. Scoped request receipts are bounded at 4096 until disconnect, with refusal rather than eviction/re-granting: exact replay preserves ID/expiry, changed content conflicts, expired/revoked replay never grants again, and repeated same-scope revocation is harmless.

The default daemon composes `createMacCoworkHost` and supplies these selections directly through existing host ports, including the existing live folder-grant resolver. `requireProvisioning` remains the same fail-closed production refusal and creation ceiling remains absent. Capability projection reports folder preparation only; repository preparation, provisioning and execution are literally false. No source is marked ready and no disk/share is activated. Restart loses ephemeral preparations; it never adopts an old grant. A later durable consumer must bind and journal the admitted grant in coordinated schema-10 work and retain the actual native share admission boundary.

## Mac behavior and frozen UI-review corrections

The New Workspace flow can invoke the real native folder picker and display its authorized selection, while Create explicitly remains disabled with the storage/sharing-unavailable explanation. GitHub selection remains unavailable. Existing workspace source addition also stays disabled until provisioning is admitted. Metadata listing/detail/rename/remove/revoke remains functional. Older daemons lacking the capability RPC retain metadata access with all preparation/provisioning capabilities false.

Awaited picker/preparation work captures the initiating workspace/revision and a surface generation. Navigation, revision changes, Cancel/dismissal, a later creation sheet or disappearing surface invalidates it. Late receipts are released rather than appended/attached to a new target. An explicit-target model add also rejects changed workspace/revision before any source mutation RPC. Completed staged selections are revoked on dismissal. These checks do not rely only on global UI disabling. Removal/revocation copy now states immediate dependent-work blocking; guest detachment/restart acknowledgment completes cleanup later.

## Remaining acceptance limits

No live Winter app/home/credentials/Keychain, real selected-user folder, NSOpenPanel/TCC/VoiceOver smoke, VM, format, production share/worker, SDK pin/release or push was used. The real bookmark positive control uses only a disposable directory. Native CF resolution and current folder identity are preparation evidence, not share isolation or durable authority. The readonly intent is not guest enforcement until an admitted native share exists. Durable grant consumption/recovery, actual backend capability broadening, signed worker/share admission, GitHub host auth and conversation activation remain separate gates. The same-user race/confidentiality residual remains the accepted first-version model; this slice does not reintroduce encryption or a persistent Code sandbox.
