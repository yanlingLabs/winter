# RAW volume backup-lock correction: independent review

2026-10-12. **Scoped acceptance: no blocking defect found in `ca0d5316abfe7d0275115446f20c21c9dd88e82b..71d950b0740e4e9646f116cada21f77139f27740`.** This accepts the named backup-subprocess transaction correction and bounded sticky-marker decoding in the isolated `cowork/v1-raw-volumes` worktree. It does not accept production worker admission, native descriptor transfer/termination, relocation/recovery, guest formatting, disk-pressure policy or the full Cowork resource/security gate. This reviewer changed no implementation and launched no VM, native worker, app or daemon.

**Writer-lock boundary.** `packages/core/src/cowork/volumes.ts:153` now refuses entry to named exclusion/cross-check operations when `db.inTransaction` is true. Plan/claim/open/release reject caller-owned transactions before preflight. Their `openChecked` calls perform `tmutil` operations outside the transaction and retain actual descriptors; the subsequent IMMEDIATE callback reauthorizes, rereads canonical rows and repeats state/owner checks (`:192`, `:276`, `:304`, `:332`). `revalidateChecked` (`:171`) matches the pinned volume's creation/home/workspace/purpose binding, rewalks the recorded directory and named image identity, and checks the still-pinned fd against current identity/geometry and sticky metadata. A preflight snapshot alone cannot publish a new owner or fd. Creation repeats named identity and descriptor metadata checks inside its sizing/publication transaction (`:245`) without invoking the named backup adapter there.

The default transaction-time operation is `timeMachineVolumeBackup.verifyDescriptorExcluded` (`volume-backup.ts:27`), which calls only descriptor-based `fgetxattr` and bounded native decoding. No `spawnSync`, named tmutil operation or subprocess fallback exists in that path. The injected adapter is trusted host code: its documented cheap/no-spawn contract is not a sandbox against a malicious adapter. This review establishes the production default call graph and explicit central guard, not that arbitrary trusted callbacks can never spawn.

**Authority and cleanup.** Claim and release continue to update both volumes under one writer transaction. Open's local handle count is published only after transaction completion (`volumes.ts:315`); a callback or COMMIT failure closes the pending fd (`:311`). Preflight failures close descriptors already accumulated by `prepareChecked` (`:177`), while plan/claim/release close all pins in `finally`. Revalidation rejects persisted image replacement and changed sticky metadata. The new seam tests additionally change canonical owner after preflight, prove refusal and check EBADF on the pending descriptor. No PID liveness substitutes for native-stop authority. These are isolated seam tests, not proof against a hostile concurrent same-user process.

**CoreFoundation FFI.** `volume-fs.ts:24–32` matches the installed macOS SDK: CFIndex is signed long, CFTypeID/CFOptionFlags are unsigned long, CFStringEncoding is UInt32 and Boolean is unsigned char. The corresponding Bun FFI i64/u64/u32/u8 declarations are correct for this arm64-only path. The primary declarations were checked in CoreFoundation `CFBase.h:562–565`, `CFData.h:25`, `CFPropertyList.h:131`, `CFString.h:100,266,294`, and `MacTypes.h:311`. `CFDataCreate` receives a live Buffer and explicit bounded length; it creates an owned data object. Both the created plist and data object are released in `finally`, including null/invalid-root/type/length/conversion failures. Null error/format out-pointers do not transfer any additional owned object to this caller.

`isStickyBackupExclusion` (`volume-fs.ts:39`) admits only 40–256 byte bplist00 data before parsing. It verifies a CFString root before string-only calls, requires the exact 17-code-unit length, converts into an 18-byte zeroed UTF-8 buffer and compares the exact expected bytes. Embedded NULs, wrong roots/values, malformed lengths and unknown/XML encodings fail closed. `hasStickyBackupExclusion` (`:57`) reads only the checked vnode and never slices with a negative or oversized syscall result. Native parser internals remain the platform's responsibility; this is a bounded-input wrapper, not an independently verified CoreFoundation parser.
