## Production choices (each is a default the coordinator confirms or overrules)

| Choice | Pick | Why |
| --- | --- | --- |
| Installation id | A random `inst-<uuid>` in `cowork-installation-id` beside the ledger, created once (temp file plus `linkSync`, 0600), never overwritten | The ledger pins machine and installation id forever. A hardware or account derived id would change with an account rename or a restore; a file beside the ledger shares the ledger's lifetime, so the two cannot drift. Losing the file with the ledger intact is a refusal (the pin mismatches), not a quiet re-mint |
| Coordination directory | The ledger's own: `~/Library/Application Support/Winter/Coordination` (or the S6 override). Every path under it is refused if any component starts with `.winter` | Outside every Winter home, so a home wipe, copy or dev/dist swap neither loses nor forges receipts, journal or ledger |
| Launcher location | `Contents/Helpers/WinterCowork/{winter-cowork-launcher,winter-cowork-worker}` relative to `dirname(process.execPath)/..` | Next to `Contents/Resources/winter-core`; the requirement is `identifier "com.winter.cowork.launcher" and anchor apple generic and certificate leaf[subject.OU] = "<team>"`, checked dynamically on the live pid before any read or send |
| Home binding | A one-row table `cowork_home_binding` in the home database; volume identity is the `getattrlist` ATTR_VOL_UUID, not `st_dev` | `st_dev` is not stable across reboots or attach order. The table needs DOOR's migration 18 (DDL below); until it exists the store reports itself unavailable and the environment cannot be built |
| Receipt directory | `<coord>/cowork-receipts/<homeId>` (0700) | Passed to the launcher as `--receipt-dir`; per home so two homes never read each other's receipts |
| Journal directory | `<coord>/cowork-launch-journal/<homeId>` (0700) | Atomic temp, fsync, rename; a corrupt or foreign file reads as no entry (which the guard treats as NOT absent while a volume owner is held) |
| Budget | Half the physical memory, half the logical CPUs (at least 2), at most 2 guests | Accounting units chosen by the host; the pressure level and free-space reserve still gate admission |
| domainId | `winter-user-<euid>` | One admission domain per macOS user |
| Backup | `timeMachineVolumeBackup` | The existing exclusion port |
| `ownerRecover` | Left absent | The owner Recover surface is DOOR's UI; absent means refuse, so recovery keeps ownership |
| Provisioning sizes | 8 GiB data, 4 GiB environment, sparse | A starting default; both multiples of 4096 and inside the store's bounds |

## What each item became

1. Production environment: `cowork/host-env/{coordination,stores,guards,volume-identity,launcher-port,environment,provisioning}.ts` behind the seam above.
2. Keychain read timeout: `keyReadTimeoutMs` (default 5000) in `native-wiring.ts`. A timeout at boot means "no key" (Class B), at a start it refuses `receipt_key_unavailable`. A JS timer cannot interrupt a call that blocks the main thread; it bounds a promise that never settles (a prompt waiting for a person) and nothing else.
3. `hostBoot` and the ledger are one object: `hostBootFromProbes(probes)` reads the same `AdmissionProbes` the ledger holds; killed by mutation M3/M13.
4. Stop timeouts, pinned in `test/cowork/native-stop-timeouts.test.ts`: the host's wait is 65 s; the app escalates SIGTERM to SIGKILL at 5 s; the launchd job states no `ExitTimeOut` (default 20 s); the daemon's SIGTERM handler awaits `stop()` with no timer; the CLI waits on the daemon with no bound of its own. All are below 65 s, so the launcher's owner-loss drain (not the daemon's stop) carries the bound, and the launcher must survive the daemon's SIGKILL (S2/G2 gate). No Swift or launchd file is edited. If the owner wants the 65 s honored by the supervisor, that is an `ExitTimeOut` plus a longer app grace, decided separately.
5. `processAbsent` with a null journal entry: absent only when no volume names an owner; with an owner the journal was lost, so it is not shown. Also: no launcher identity, a differing scope, an inconsistent worker-less entry with an owner: not shown.
6. F2 (retained Class A needs a valid MAC and BOTH guard probes): already in integration from #71 and #74. This slice adds the real receipt store (the launcher's `DirectoryReceiptStore` format, with `retire`) and real guards, and proves the release path end to end through them (`host-env-assembly.test.ts`).
7. Host: runtime frames are routed to the run instead of dropped, `start(workspaceId, {conversations})` takes the caller's set, and the run carries `guestBootId`, `runtime(0)` (`send` chunked at 256 KiB under the 1 MiB budget, `onData`) and `ended`.
8. Offer and provisioning: `coworkGuestRuntimeOffer(verifiedImage)` (null unless protocol 1 and the confined posture), `CoworkProvisioningPort` with `coworkAllocateAuthority` (permits `allocate` only). The shapes are DOOR's section 7.6 and 7.7, declared locally until `cowork/session-ports.ts` merges; then it is an import swap.
