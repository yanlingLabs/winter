## Corrected lifetime and scope boundaries

At `f46f1627`, `guest-runtime.ts:107–121,181–185` requires both exact native/store proof and primary-consumer closure, or explicit fencing before any primary chunk was delivered. A consumer that has received a chunk retains admission until completion/return/throw. `:125–128` requires the map to still contain the exact captured lifetime for sends and relays; `:110–111` uses compare-and-delete. Stderr and pending input also pass the same lifetime check. Late old kill/error/ACK/iterator callbacks act on the original bound channel and cannot clear or redirect a replacement. The wrapper handles return/throw before the first next at `:168–178`.

The actual query regression confirms replacement refusal after native exit/proof, delivery of the original buffered permission/result under the held lifetime, and retry only after the query closes. A separate actual query test fences an abandoned unconsumed stream, starts a replacement only after exact proof, and confirms the old query invokes no permission callback/yields no frame; late old callbacks preserve the replacement. Active/unopened iterator cancellation, pending old input ACKs and return/throw cases pass independently.

Descriptor creation (`:68–85`) uses canonical binding/workspace/source, current host grants, effective capability intersection, policy and authenticated boot/session identity. Store/cwd paths use the accepted guest mount skeleton and stable logical conversation identity; arbitrary host cwd/env/spawn argv do not populate the descriptor. Captured epoch/home/boot/backend/binding/policy/instruction identities are immutable. Rechecks (`:87–89,125–128,188–192`) reject revoked sources, changed policy/identity/channel scope before queued sends or relays. Serialized input acknowledgments do not replay on loss. Output does not prefetch; decoded chunks/frame tails/input queue have explicit byte caps. Native upstream queue bounds remain an adapter obligation.

Exact conversation-store termination is kept separate from workspace-volume safety. PID, EOF, kill and a timeout cannot release native/store ownership. Failed opening attempts, absent/malformed/uncertain or mismatched evidence remain conservative recovery debt; this review credits no operational recovery without the future native recovery port.
