## Deterministic builder and extraction scope

The SDK correction uses one private random parent with deterministic `source` and `stage` children and a single finally cleanup. Build-time no-autoload flags and the separate neutral source copy remain in place. The pinned Linux Bun base is copied into stage before compilation, so stage is initially empty rather than permanently empty. Output basename remains fixed. The two independently retained complete artifacts corroborate reproducibility for these inputs. Root independently ran the reported old-builder failure/new 11-test pass; this reviewer did not duplicate the compilation run.

Archive member names reject absolute paths, parent traversal and NULs. Directory-parent insertion rejects symlink/non-directory ancestor conflicts. Symlink resolution is lexical and guest-rooted; absolute guest links never become host filesystem traversal. Hardlinks resolve only existing admitted regular bytes and become independent files. Regular executable bits are normalized without preserving setuid/setgid permissions. Maintainer scripts and distro programs are not executed.

The builder is **not uniformly streaming-bounded for arbitrary replacement input**: existing downloads are read with `read_bytes()` before size/hash refusal; Packages.xz uses full `lzma.decompress()` before checking the expanded limit; control tar enumeration/control reads lack an independent small cap. Payload member lengths are checked before their extracted regular-file read, and network reads are capped. Frozen cryptographic pins and the actual measured package sizes constrain the accepted input set, so these implementation limits do not invalidate the inspected artifacts. However, claims of generic bounded corrupt-cache/decompression handling should be narrowed or the reads/decompressors capped before allocation. No large or memory-pressure probe was performed.

Dependency layout is copied from already provisioned SDK dependencies rather than freshly installed. Final expected-output hashes refuse dependency-induced artifact drift, but a fully self-contained offline rebuild still requires those exact dependency inputs and tool versions. The pinned image is about 321 MiB expanded; gzip equality does not prove a small guest RAM floor or active reclaim behavior.

Evidence: `2026-10-12-cowork-guest-artifact-independent-verification.json` and `2026-10-12-cowork-guest-artifact-independent-tests.log` beside this report. Full signers, index sizes/digests, matching artifact hashes, helper bindings and no-follow results are retained without personal paths. No VM, Linux executable, app, formatter, init or privileged startup was run. The separate held native VM review was not retried and this report is not a launch receipt.
