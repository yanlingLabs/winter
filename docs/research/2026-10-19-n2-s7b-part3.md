# N2 S7B part 3: what the native host records and checks for the session door

Status: draft PR `cowork/n2-integration-b3`, stacked on b2 (#99), which merges b1 (#87). It also merges the open DOOR branches it is built against (#116, #118, and the contract revision 3 branch #115), so until those merge its diff shows them. Nothing here makes a Cowork session creatable or runnable: `session.create {mode:"cowork"}` still answers `unsupported_topology`, the activation seam is off, and no production composition supplies a provisioning port, a shares provider, a resume record or the new records.

## What was built

| Piece | Where | What it does |
| --- | --- | --- |
| Provisioning port, in the door's shape | `host-env/provisioning.ts` | Typed by `session-ports.ts` (the local declarations are gone). `provision` allocates both images, makes `shared/{guidance,memory,outputs}` (owned, 0700, no symlink), keeps the data volume's UUID (write-once) and pins the digests. A mismatching recorded UUID fails with `store_volume_mismatch` and pins nothing. |
| The port reaches the service | `native-wiring.ts` `provisioningPort()`, `daemon.ts` | A lazy proxy over the injected environment: absent without an environment (production). With no port in the environment it THROWS (uncertain, retried), never answers `failed`, which would conclude a never-booted creation for good. The daemon composes it only where `coworkNativePort` exists and calls `resumeProvisioning()` once at boot. |
| Guest boots | `native/guest-records.ts` (port), `host-env/guest-records.ts` (SQL), `native/host.ts`, `native/recovery.ts` | `recordHello` at the guest's `hello`; `recordEnd` only inside `recovery.release`, with the evidence kind that released the disks. A proof is never overwritten; a reused boot id is a conflict. |
| Store volume UUID | `native/host.ts` `checkStoreVolume` | Before the incarnation moves: a recorded UUID that is not the data volume's refuses (and marks a resuming store lost); a store expected over a never-formatted data volume is lost and the volume is not formatted. |
| Continuation on the wire and echo | `native/host.ts` `prepareSet`, `deliverConversations` | `request.resume` is put on the runtime record; `runtime_ready.continuations` must have one entry per host-query conversation, matching what was sent (`either` accepts either). The echo is exposed as `CoworkNativeRunning.continuations`. |
| Fault to lost mapping | same | `resume_store_missing` calls `request.storeLost("resume_store_missing")` once and fails the start; `fresh_store_not_empty` fails the start only. |
| Host-backed shares | same | `request.shares()` is asked before `begin`; each share is opened by an injected opener (canonical path, O_NOFOLLOW, O_DIRECTORY) and sent as one descriptor on the L1 `shares` line; after `mounted` the bootstrap `shares` goes out and `shares_mounted` is awaited; then `request.sharesMounted` gets each mounted folder source (a throw is `share_mount_failed`). Nothing supplies shares today (the libkrun folder server is the contract lane's). |
| Outputs directory | `host-env/guest-dirs.ts`, `native/host.ts` | `<home>/cowork/workspaces/<id>/shared/outputs/<sid>` is made before the set that names `/workspace/outputs/<sid>` is sent: idempotent, a symlink or file at any step refuses. See the decision below about "on data.ext4". |
| Plan view | `native/protocol.ts`, `native/guest-dirs.ts`, `native/host.ts` | `/workspace/plan/<sid>/<epoch>` is an admitted view of the conversation's own session; writable, once, under `plan` only; every other root stays read-only under plan. The host refuses an epoch lower than one already sent (in memory). The driver still passes no epoch and `planViewMounted` stays false. |
| `coordinate` tool class | `native/protocol.ts` | Fourth class, last in the order. |
| Restore claim (content-out #97 NEEDS) | `volumes.ts` | `beginRestore` (durable exclusive claim, stored as the volume owner so `claim`/`open`/`prepareFilesystems` refuse and a crash stays visible), `openForRestoreRead` (read-only, identity-pinned), `reidentifyRestored` (the old identity must be what the restorer believed, the file must be exactly the new one, size checked), `endRestore` (revalidates every image first). |
| Lazy-require probe | none new | `__host-code-adapter-probe` and its step in `verify:fd-receiver` were already in b1/b2 (#103's NEEDS). The pin in `host-code-broker.test.ts` passes (38). Not run: the compiled gate. |

## Decisions and residuals (for the owner / coordinator)

1. **"Outputs directory on data.ext4".** A macOS host cannot write into an ext4 image, and nothing in contract revision 3 lets it ask the guest to. In revision 3 the outputs location is the host-served outputs share, so the host makes the directory there. A guest-side creation on the data disk (revision 2 layout) would be PID 1's duty and needs an SDK change. Recommendation: accept the share-side creation; the plan view's epoch directory is the guest-side case and is specified as PID 1's job.
2. **Plan epoch monotonicity is in memory.** The durable epoch is DOOR's policy machine, which always passes the current one. A daemon restart forgets the host's own high-water mark. Recommendation: accept; a durable mark needs a column (DOOR).
3. **Fake guests now have unique boot ids and launcher confirmation ids** (the real ones are unique; the table demands it).
4. **Widened `GuestToolClass` / `session-ports.ts` toolClasses** with `coordinate` (two type unions in DOOR's files, nothing else). Listed under NEEDS so DOOR adopts it.
