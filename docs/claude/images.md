# Code-mode image and file attachments

*Read this before touching image or file attachments, `session.stageImage`, `session.send`/`steer`'s `images`/`files`, the Mac composer's inline chips, or the transcript's read-image thumbnails and file links. Paths are under `packages/core/src/` unless stated.*

## Contract

- The MODEL gets a PATH; `text` keeps `[Image #n]` and the stored `user_message` carries `images: [{n, path}]` (`packages/protocol/src/events.ts`: 1–20 entries, path ≤ 4096 chars).
- Paths are RAW (never downscaled/re-encoded/copied by default): the runtime's Read tool prepares images itself (`tools/image-prep`: ≤ `IMAGE_MAX_INPUT_BYTES` 64 MiB, 1568 px long edge).
- **Read picks its reader by the EXTENSION the model types** (`IMAGE_MIME` in its `tools/impl/read.ts`; lowercased `extname`, no symlink followed), never by content — any other extension reads as binary text. `IMAGE_FILE_EXTENSIONS` (`packages/protocol/src/methods.ts`, nine entries) must equal that table.
- `modelTextOf` (`sessions/model-text.ts`) is the ONE substitution site (`[Image #n]` and `[File #n]`, one pass): push + held queue (`runtime-sdk/winter-session.ts`), resume replay (`unconsumedUserMessages`), `runtime-sdk/import-legacy.ts`, the compactor. Everything else reads `text` as is.
- `IMAGE_PATH_GUIDANCE` (`agent/context.ts`, pushed by `ContextAssembler.assemble` whenever `basePromptOverride` is unset — never chat or a coordinator) is a static line (no session id or path, so the cached prefix never moves): a `winter-session-…/images/` path is a staged copy the model may move, any other is the user's file, read/copy only.

## Attaching

- Code sessions only: Mac `composerImageIntake` (a `ComposerAttachmentIntake`, `apple/Winter/Sources/FieldKit/FieldStateAdapter.swift`, fail-closed without a code row); TUI ctrl+v or a pasted path (`imagePathFromPaste`, `packages/cli/src/tui/images.ts`, listed extensions only). A row with `supportsImages: false` refuses at attach with exactly `The selected model doesn't support images`.
- **FILE**: the ORIGINAL absolute path when its name ends in `IMAGE_FILE_EXTENSIONS` AND its first 12 bytes are an image — never copied, staged or read further; > `IMAGE_FILE_MAX_BYTES` (64 MiB) → `IMAGE_FILE_TOO_LARGE_MESSAGE`; a non-image hands the paste back. Any OTHER image file on the Mac is read in the app and staged as DATA (`composerStagedImage`, `apple/Winter/Sources/Field/ComposerImages.swift`).
- **DATA** (clipboard): staged as RAW bytes at submit through `session.stageImage {sessionId, mediaType, dataBase64} → {path, imagesOnSend}` (a refusal sends nothing); only one over `STAGE_IMAGE_MAX_BYTES` is downscaled at attach, alone — `IMAGE_ATTACH_MAX_LONG_EDGE` 1568, PNG/JPEG kept, then JPEG 0.85 → 0.5, else `IMAGE_TOO_LARGE_MESSAGE`.
- Skew: `session.send`'s schema strips unknown keys. Send `images` only when every stage said `imagesOnSend: true` AND hello announced `features: ["image-original-paths"]` (`DAEMON_FEATURE_IMAGE_ORIGINAL_PATHS`, `WinterClient.supportsOriginalImagePaths`); else substitute the paths into the text — as a child view's `thread.send` always does.
- A refused send keeps the draft: TUI `DraftImages.snapshot`/`restore` hand the text back, a number reused meanwhile rewritten to a FRESH one; the Mac keeps the attachments and shows the daemon's sentence. On `image_file_unreadable` for a FILE the Mac (`composerSend`, with the drag's access) reads, stages and resends once per file.
- Live drill not yet run: a first drag from Desktop/Documents/Downloads may raise a TCC prompt — check which name it shows (Winter or `winter-core`) and that a denial falls back.

## Validation on send/steer

`checkedImageRefs` (`ipc/server.ts`) → `validateImageRefs` (`agent/stage-image.ts`), BEFORE any resume or append; no refusal echoes a path.

- Harness role only → `image_reference_invalid`; non-code → `image_session_not_code`; the CURRENT model must accept images (`assertModelAcceptsImages`: `image_input_unsupported` / `image_session_no_model` — a FILE's only door); `n` unique, in `text`, ≤ 20.
- Classified by SHAPE. **Staged** = directly in THIS session's `images/`, named `image_<k>.<ext>`: held to the staging rules (regular non-symlink file, root derived as staging derives it, spelled as its realpath); failing them is refused, never re-judged as original. **Original** = anything else: absolute; no `UNSAFE_PATH_CHARS` (controls, bidi) or edge whitespace — refused, never stripped (`image_reference_invalid`); extension judged AS SPELLED else `image_type_unsupported`; its realpath TARGET a regular file on an `O_NONBLOCK|O_NOFOLLOW` fd, stored as spelled; not in Read's read-deny set (`readDeniedByRuntime`, reusing `sandboxConfigFor`'s `denyRead` + `protectedReadDenial` — [tool-surface](./tool-surface.md); never the whole home, `<home>/outputs/…` works; skipped without `winterHome`, i.e. tests); 12 header bytes an image (`sniffImageMediaType`) else `image_type_unsupported`; ≤ 64 MiB else `image_too_large`. Unresolvable/unopenable → `image_file_unreadable` with `data.n`. Else `image_reference_invalid`.
- `sync.push` refuses a `user_message` with `images` (`ipc/sync.ts`).

## `session.stageImage` (`ipc/server.ts` → `agent/stage-image.ts`)

- LOCAL only, code only, the same model backstop. Length first: `STAGE_IMAGE_B64_MAX_LENGTH` (`NDJSON_MAX_LINE_BYTES` 8 MiB − `STAGE_IMAGE_LINE_HEADROOM_BYTES` 256 KiB) → `image_too_large` before decoding; decoded cap `STAGE_IMAGE_MAX_BYTES` = 6,094,848; bad base64 `image_data_invalid`; magic bytes decide (`STAGE_IMAGE_MEDIA_TYPES`) — unknown `image_type_unsupported`, declared mismatch `image_type_mismatch`; no pixel limit.
- Written UNCHANGED to `sessionTmpDir(sessionId)/images/image_<k>.<ext>`. The dir is a sandbox WRITABLE root the shell can swap, so: its own name is never resolved (root = `realpath(parent)` + basename); it and `images/` must be real directories; `O_CREAT|O_EXCL|O_NOFOLLOW` 0600; bytes only after a realpath + inode proof, else `image_stage_failed`; never logged.
- Swift budgets the ENCODED line (`JSONEncoder` escapes `/`): `WinterClient.request` uses `.withoutEscapingSlashes` and throws `RpcError` -6 past `maxRequestLineBytes`; `stageImage` refuses past `stageImageMaxBase64Length` before encoding.

## The Mac composer: inline chips (2026-10-13)

- An attachment is a CHIP IN THE TEXT, where the user put it: `ComposerAttachmentDraft` (`apple/Winter/Sources/Field/ComposerAttachments.swift`) holds the attachments beside `composerDraft`, and the draft String holds each chip as ONE private-use marker character (`composerAttachmentMarker`, U+E000 + id — one UTF-16 unit, like the U+FFFC the text view holds, so ranges agree). `CommandTextView.composerText` / `setComposerText` convert between the two; `ComposerTextView` compares the binding against `composerText`, never `string` (writing `string` wipes every chip).
- The storage holds U+FFFC with a `ComposerChipAttachment`; its `ComposerChipAttachmentCell` (TextKit 1 — the view is forced onto it in `makeNSView`) draws `AttachmentChipFace` (`Field/AttachmentChip.swift`) rasterised by `ImageRenderer` (`AttachmentChipImages`, cached per model/size/hover/appearance/art; a thumbnail or icon still loading draws its placeholder at the same size, then redraws). `AttachmentChipSize.inline(for: font)`: height = ascender − descender, bottom on the descender (`cellBaselineOffset`), so a line with chips is no taller. One face, one rasteriser, for the composer and the bubble; no other chip view exists.
- Behaviour: caret movement, Backspace/Delete and undo/redo are AppKit's (the chip is one character; undo restores the same attachment object — checked offscreen on TextKit 1, `isRichText = false`). A chip out of the text stays in the draft for undo (`prune`: the newest 32, dropped at send). Hover × (`attachmentChipInlineRemoveRect`, a tracking area, the cell's last drawn frame by character index) deletes the chip and the space after it, undoably. Copy/cut write the placeholders as `.string` plus `com.winter.composer.chips` (the draft token, the selection with markers, each placeholder); paste or a drop restores chips only into the same draft and only those it still holds, else the placeholder text. Paste/drop/"+" (`ComposerAttachPicker`, an `NSOpenPanel`) insert at the caret or the drop point (`characterIndexForInsertion`), spaced from the words either side. The "+" is dimmed and inert outside a code session, its reason on hover.
- At submit `resolveComposerAttachments` serialises the TEXT: each marker becomes its placeholder at its position, images and files each numbered from 1 by first appearance (`compare [Image #1] with [File #1]`); a chip in the text twice is one placeholder twice; a marker the draft no longer holds is dropped. Only what the text holds is sent; `composerSendSucceeded(sentAttachments:)` clears only those (a refused send keeps text and chips). A draft with chips in a NON-code session sends nothing — "Attachments work in Code sessions — this chat can't take them"; one whose chips are gone sends its text without markers. The older-daemon fallback substitutes images and files in ONE pass (`substituteComposerAttachmentTokens`), like `modelTextOf`.
- Intake: each file URL is an image when `composerImage(fromFile:)` takes it, else a FILE (regular file or directory); image data as before. A refused image (text-only model) leaves the notice; if NOTHING was attached from file URLs, AppKit types the paths.
- The bubble: the reducer copies `images`/`files` onto `Exchange.promptAttachments` (a folded steer's numbers are moved past the prompt's, `PromptAttachments.fold`); `promptDisplay` splits the prompt into prose segments (markdown, as any bubble) and lines holding a placeholder that HAS an entry, which `PromptInlineText` draws as one `Text` with each chip's image in place (`Text(Image(nsImage:))`, same baseline rule). A placeholder with no entry stays text. An unreadable image shows a photo glyph and "Image #n"; a staged copy is NAMED "Image #n".

## Transcript: images the model read, and file links (2026-10-13)

- A `read` of an image returns "[image]" — the bytes go to the model and never reach the session log. The reducer keeps the read's whole `file_path` (`ActivityItem.readPath`; the row's `detail` stops at 100 chars) and the tool row draws each image it read as a compact thumbnail (`toolCallReadImagePath`, `toolRunReadImages`): on the collapsed row (deduplicated across the turn, at most 12 with a note) and per call when open. A result with images and no path (a ComputerV2 screenshot) keeps the "Screenshot" chip.
- A reply's thumbnails (`TranscriptFileMentions.swift`) are images the reply NAMES that exist — minus those a read of the same turn already shows. Before this, those were the only pictures, which is why a turn that read seven images showed the two whose paths the linkifier happened to parse.
- Links: inline markdown recurses into bold/italic/strike (a code span inside `**…**` is a code span). Every path that resolves to an existing file or folder links: absolute, `~/`, trailing-`/` folders, code spans with spaces (absolute, or a bare file name), and relative names — resolved against the working directory plus the turn's directories (attachments, tool paths, folders and files the reply names absolutely: `TranscriptMentionResolver`, two stat passes off-main through `TranscriptFileExistenceCache`) and linked only when EXACTLY one path matches. A click (`transcriptFileLinkAction`): images, and any file in a session with a working directory, open in the panel; folders open in Finder; other files are revealed in Finder.

## Files: `[File #n]` + `files` (2026-10-13)

- Same contract as images: `text` keeps `[File #n]`, `user_message.files: [{n, path}]` (`UserMessageFileRef`, ≤ `USER_MESSAGE_FILES_MAX` 20, path ≤ 4096), the model is given the path (`modelTextOf`). Any type, folders too; nothing is read, copied or staged, and no model capability is needed.
- `checkedFileRefs` (`ipc/server.ts`) → `validateFileRefs` (`agent/stage-image.ts`), before any resume/append: harness role only (`file_reference_invalid`); code only (`file_session_not_code`); images + files TOGETHER ≤ `USER_MESSAGE_ATTACHMENTS_MAX` 20 (`file_reference_invalid`, "A message can carry at most 20 attachments" — 20 × 4096-char paths stays inside the 160 KiB per-event cap; the Mac refuses the same before staging); `n` unique, in `text`, ≤ 20; absolute, no `UNSAFE_PATH_CHARS` or edge whitespace; not in Read's read-deny set as spelled AND resolved; `realpath` resolves (else `file_unreadable`, `data.n`); `stat` a regular file or directory (never `open`, so a FIFO is refused unblocked). No refusal echoes a path.
- Skew: hello `features` adds `attachment-files` (`DAEMON_FEATURE_ATTACHMENT_FILES`, `WinterClient.supportsAttachmentFiles`); without it the Mac substitutes the paths into the text. `sync.push` refuses a `user_message` with `files`.
- Producers: `hub.send`, `WinterSession.appendUser` (send, steer, `holdForHandoff`), `LegSession.send/steer`'s 4th argument.

## The phone never gets a Mac path

- `phoneViewOf` (`sessions/history.ts`, both phone paths: `session.history` and the remote stream filter) cuts every `images` AND `files` entry to `{n, path: <basename>}` (`phoneAttachmentName`; a bare `/` reads `file`). The `path` KEY stays because the phone kit decodes `{n, path}` with `path` required; the log and the Mac keep the full path. Pinned by `test/ipc/session-send-files.test.ts` (no `/` reaches a remote client).
