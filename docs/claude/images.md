# Image and file attachments (Code and Dispatch)

*Read this before touching image or file attachments, `session.stageImage`, `session.send`/`steer`'s `images`/`files`, the Mac composer's inline chips (the Dispatch pill's included), or the transcript's read-image thumbnails and file links. Paths are under `packages/core/src/` unless stated.*

## Contract

- **Which sessions**: code and, since 2026-10-19, DISPATCH (its model has `Read` and `Bash`); never chat (no file tools). ONE predicate per side: daemon `sessionTakesAttachments(mode)` (`ipc/server.ts`, used by `session.stageImage`, `checkedImageRefs` and `checkedFileRefs`), Mac `composerImageInputEnabled(row:)` (`apple/Winter/Sources/Field/ComposerImages.swift`) — the same rule, so a draft the Mac lets through is never refused for its mode. The wire codes keep their names (`image_session_not_code`, `file_session_not_code`); the message is "images|files can only be added to code and dispatch sessions". Remote callers and the phone are unchanged: local only.
- The MODEL gets a PATH; `text` keeps `[Image #n]` and the stored `user_message` carries `images: [{n, path}]` (`packages/protocol/src/events.ts`: 1–20 entries, path ≤ 4096 chars).
- Paths are RAW (never downscaled/re-encoded/copied by default): the runtime's Read tool prepares images itself (`tools/image-prep`: ≤ `IMAGE_MAX_INPUT_BYTES` 64 MiB, 1568 px long edge).
- **Read picks its reader by the EXTENSION the model types** (`IMAGE_MIME` in its `tools/impl/read.ts`; lowercased `extname`, no symlink followed), never by content — any other extension reads as binary text. `IMAGE_FILE_EXTENSIONS` (`packages/protocol/src/methods.ts`, nine entries) must equal that table.
- `modelTextOf` (`sessions/model-text.ts`) is the ONE substitution site (`[Image #n]` and `[File #n]`, one pass): push + held queue (`runtime-sdk/winter-session.ts`), resume replay (`unconsumedUserMessages`), `runtime-sdk/import-legacy.ts`, the compactor. Everything else reads `text` as is.
- `IMAGE_PATH_GUIDANCE` (`agent/context.ts`) is a static line (no session id or path, so the cached prefix never moves): a `winter-session-…/images/` path is a staged copy the model may move, any other is the user's file, read/copy only. `ContextAssembler.assemble` adds it by default whenever `basePromptOverride` is unset (code, dispatch children); its `imagePathGuidance` input overrides that, and `winterSystemPromptFor` sets it for DISPATCH, whose base slot is swapped whole (`dispatchSystemPrompt`) — it lands after the dispatch base, before the date. Chat never gets it. The long-lived Dispatch session picks it up (one prefix change) at its next incarnation.
- **The model check** (`assertModelAcceptsImages`, `ipc/server.ts`) reads the model the session's driver SPAWNS: its own `model`, else — dispatch — the live `pinsFor(settings).dispatch` (`session.setModel` refuses a dispatch target), else the live default (`liveModel`). The Mac cannot know the pin (`sync.config` does not carry it), so its attach-time check passes a dispatch row with no model (`FieldStateAdapter.composerImageModel` = nil) and the daemon refuses at submit if it must.

## Attaching

- Code and dispatch sessions: Mac `composerImageIntake` (a `ComposerAttachmentIntake`, `apple/Winter/Sources/FieldKit/FieldStateAdapter.swift`, fail-closed without a code or dispatch row — the shell, detached windows, and the Dispatch pill below); TUI ctrl+v or a pasted path (`imagePathFromPaste`, `packages/cli/src/tui/images.ts`, listed extensions only; the TUI attaches only to code sessions). A row with `supportsImages: false` refuses at attach with exactly `The selected model doesn't support images`.
- **FILE**: the ORIGINAL absolute path when its name ends in `IMAGE_FILE_EXTENSIONS` AND its first 12 bytes are an image — never copied, staged or read further; > `IMAGE_FILE_MAX_BYTES` (64 MiB) → `IMAGE_FILE_TOO_LARGE_MESSAGE`; a non-image hands the paste back. Any OTHER image file on the Mac is read in the app and staged as DATA (`composerStagedImage`, `apple/Winter/Sources/Field/ComposerImages.swift`).
- **DATA** (clipboard): staged as RAW bytes at submit through `session.stageImage {sessionId, mediaType, dataBase64} → {path, imagesOnSend}` (a refusal sends nothing); only one over `STAGE_IMAGE_MAX_BYTES` is downscaled at attach, alone — `IMAGE_ATTACH_MAX_LONG_EDGE` 1568, PNG/JPEG kept, then JPEG 0.85 → 0.5, else `IMAGE_TOO_LARGE_MESSAGE`.
- Skew: `session.send`'s schema strips unknown keys. Send `images` only when every stage said `imagesOnSend: true` AND hello announced `features: ["image-original-paths"]` (`DAEMON_FEATURE_IMAGE_ORIGINAL_PATHS`, `WinterClient.supportsOriginalImagePaths`); else substitute the paths into the text — as a child view's `thread.send` always does.
- A refused send keeps the draft: TUI `DraftImages.snapshot`/`restore` hand the text back, a number reused meanwhile rewritten to a FRESH one; the Mac keeps the attachments and shows the daemon's sentence. On `image_file_unreadable` for a FILE the Mac (`composerSend`, with the drag's access) reads, stages and resends once per file.
- Live drill not yet run: a first drag from Desktop/Documents/Downloads may raise a TCC prompt — check which name it shows (Winter or `winter-core`) and that a denial falls back.

## Validation on send/steer

`checkedImageRefs` (`ipc/server.ts`) → `validateImageRefs` (`agent/stage-image.ts`), BEFORE any resume or append; no refusal echoes a path.

- Harness role only → `image_reference_invalid`; chat → `image_session_not_code`; the CURRENT model must accept images (`assertModelAcceptsImages`: `image_input_unsupported` / `image_session_no_model` — a FILE's only door); `n` unique, in `text`, ≤ 20.
- Classified by SHAPE. **Staged** = directly in THIS session's `images/`, named `image_<k>.<ext>`: held to the staging rules (regular non-symlink file, root derived as staging derives it, spelled as its realpath); failing them is refused, never re-judged as original. **Original** = anything else: absolute; no `UNSAFE_PATH_CHARS` (controls, bidi) or edge whitespace — refused, never stripped (`image_reference_invalid`); extension judged AS SPELLED else `image_type_unsupported`; its realpath TARGET a regular file on an `O_NONBLOCK|O_NOFOLLOW` fd, stored as spelled; not in Read's read-deny set (`readDeniedByRuntime`, reusing `sandboxConfigFor`'s `denyRead` + `protectedReadDenial` — [tool-surface](./tool-surface.md); never the whole home, `<home>/outputs/…` works; skipped without `winterHome`, i.e. tests); 12 header bytes an image (`sniffImageMediaType`) else `image_type_unsupported`; ≤ 64 MiB else `image_too_large`. Unresolvable/unopenable → `image_file_unreadable` with `data.n`. Else `image_reference_invalid`.
- `sync.push` refuses a `user_message` with `images` (`ipc/sync.ts`).

## `session.stageImage` (`ipc/server.ts` → `agent/stage-image.ts`)

- LOCAL only, code and dispatch only, the same model backstop. Length first: `STAGE_IMAGE_B64_MAX_LENGTH` (`NDJSON_MAX_LINE_BYTES` 8 MiB − `STAGE_IMAGE_LINE_HEADROOM_BYTES` 256 KiB) → `image_too_large` before decoding; decoded cap `STAGE_IMAGE_MAX_BYTES` = 6,094,848; bad base64 `image_data_invalid`; magic bytes decide (`STAGE_IMAGE_MEDIA_TYPES`) — unknown `image_type_unsupported`, declared mismatch `image_type_mismatch`; no pixel limit.
- Written UNCHANGED to `sessionTmpDir(sessionId)/images/image_<k>.<ext>`. The dir is a sandbox WRITABLE root the shell can swap, so: its own name is never resolved (root = `realpath(parent)` + basename); it and `images/` must be real directories; `O_CREAT|O_EXCL|O_NOFOLLOW` 0600; bytes only after a realpath + inode proof, else `image_stage_failed`; never logged.
- **Cleanup (2026-10-19)**: nothing else ever removes a session's temp folder, and Dispatch is ONE session that lives for months, so each stage first lets go of the session's stale staged copies (`pruneStagedImages`, `agent/stage-image.ts`; every session that stages, code too): each `image_<k>.<ext>` REGULAR file directly in `images/` whose mtime is older than `STAGED_IMAGE_RETENTION_MS` (14 days), unless a `user_message` in the last 4 MiB of the session's log names it (`stagedPathsNamedBy` over `store.readTail`, consumed or still owed — a superset of what a resume re-pushes; a staged ref is stored as its realpath, the spelling the prune lists). `keep` is read only when there is a candidate; a `keep` that throws, or no `keep`, removes nothing; the prune never throws into the stage and never logs a path. The new file's number is taken BEFORE the prune, so numbers keep climbing and a pruned name is never reused. Right before EACH `unlink`: both folders re-`lstat`ed as the same real directories (dev + inode) they were when listed, the candidate re-`lstat`ed as the same regular file, and its `realpath` exactly `<images>/<name>` — else skipped (a moved folder stops the prune). A symlink planted in `images/` is never followed. **Residual**: a swap of the session folder or `images/` landing between those re-checks and the `unlink` itself (a few system calls) could aim that one `unlink` at a same-named, two-week-old file elsewhere; Node has no `unlinkat`.
- Swift budgets the ENCODED line (`JSONEncoder` escapes `/`): `WinterClient.request` uses `.withoutEscapingSlashes` and throws `RpcError` -6 past `maxRequestLineBytes`; `stageImage` refuses past `stageImageMaxBase64Length` before encoding.

## The Mac composer: inline chips (2026-10-13)

- An attachment is a CHIP IN THE TEXT, where the user put it: `ComposerAttachmentDraft` (`apple/Winter/Sources/Field/ComposerAttachments.swift`) holds the attachments beside `composerDraft`, and the draft String holds each chip as ONE private-use marker character (`composerAttachmentMarker`, U+E000 + id — one UTF-16 unit, like the U+FFFC the text view holds, so ranges agree). `CommandTextView.composerText` / `setComposerText` convert between the two; `ComposerTextView` compares the binding against `composerText`, never `string` (writing `string` wipes every chip).
- The storage holds U+FFFC with a `ComposerChipAttachment`; its `ComposerChipAttachmentCell` (TextKit 1 — the view is forced onto it in `makeNSView`) draws `AttachmentChipFace` (`Field/AttachmentChip.swift`) rasterised by `ImageRenderer` (`AttachmentChipImages`, cached per model/size/hover/appearance/art; a thumbnail or icon still loading draws its placeholder at the same size, then redraws). `AttachmentChipSize.inline(for: font)`: height = ascender − descender, bottom on the descender (`cellBaselineOffset`), so a line with chips is no taller. One face, one rasteriser, for the composer and the bubble; no other chip view exists.
- Behaviour: caret movement, Backspace/Delete and undo/redo are AppKit's (the chip is one character; undo restores the same attachment object — checked offscreen on TextKit 1, `isRichText = false`). A chip out of the text stays in the draft for undo (`prune`: the newest 32, dropped at send). Hover × (`attachmentChipInlineRemoveRect`, a tracking area, the cell's last drawn frame by character index) deletes the chip and the space after it, undoably. Copy/cut write the placeholders as `.string` plus `com.winter.composer.chips` (the draft token, the selection with markers, each placeholder); paste or a drop restores chips only into the same draft and only those it still holds, else the placeholder text. Paste/drop/"+" (`ComposerAttachPicker`, an `NSOpenPanel`) insert at the caret or the drop point (`characterIndexForInsertion`), spaced from the words either side. The "+" is dimmed and inert outside a code or dispatch session, its reason on hover (the Dispatch pill has no "+": paste and drop).
- At submit `resolveComposerAttachments` serialises the TEXT: each marker becomes its placeholder at its position, images and files each numbered from 1 by first appearance (`compare [Image #1] with [File #1]`); a chip in the text twice is one placeholder twice; a marker the draft no longer holds is dropped. Only what the text holds is sent; `composerSendSucceeded(sentAttachments:)` clears only those (a refused send keeps text and chips). A draft with chips in a chat session sends nothing — "Attachments work in Code and Dispatch — this chat can't take them" (the "+" tooltip: "Attachments work in Code and Dispatch — chats can't take files or images"); one whose chips are gone sends its text without markers. The older-daemon fallback substitutes images and files in ONE pass (`substituteComposerAttachmentTokens`), like `modelTextOf`.
- Intake: each file URL is an image when `composerImage(fromFile:)` takes it, else a FILE (regular file or directory); image data as before. A refused image (text-only model) leaves the notice; if NOTHING was attached from file URLs, AppKit types the paths.
- The bubble: the reducer copies `images`/`files` onto `Exchange.promptAttachments` (a folded steer's numbers are moved past the prompt's, `PromptAttachments.fold`); `promptDisplay` splits the prompt into prose segments (markdown, as any bubble) and lines holding a placeholder that HAS an entry, which `PromptInlineText` draws as one `Text` with each chip's image in place (`Text(Image(nsImage:))`, same baseline rule). A placeholder with no entry stays text. An unreadable image shows a photo glyph and "Image #n"; a staged copy is NAMED "Image #n".

## The Dispatch pill (2026-10-19)

- **Intake**: the pill's `ComposerTextView` (`DispatchPillView`) is handed `adapter.composerImageIntake`; `DispatchPillController.currentSessionRow` (wired in `AppDelegate.wireDispatchPill`: the focused session's row from `directory.rows`, read fresh) gates it — code or dispatch, so a code session the pill follows takes them too; unwired or chat → off, a paste types the name. `fetchModelCatalogue` fills the attach-time catalogue. A detached dispatch window (`PillChromeComposer`) and the shell already shared the intake and the submit door; widening the predicate is all they needed.
- **Submit** (`DispatchPillController.submit`): a draft holding ANY chip marker is a message — never the `/` menu, a pill command or a shell line (`DispatchPillCommandMode.evaluate` answers "not a command" for any marker, so it never turns purple and Return never runs it) — and goes through `sendWithAttachments`: the session resolved ONCE (`DispatchPillAttachmentSender.session` → `ensureFocusedSession`), `composerTextForSend` staging into that session, then `composerSend` with a send/steer that THROWS (the daemon's sentence becomes the notice; `image_file_unreadable` restages once). Steer vs send is fixed at Enter (`turnRunning`). A draft with no chip goes through `onSubmit` as before (it also serves "Add to transcript").
- **Notice**: the pill has no notice line; `composerNotice` floats above it as a command's answer does (`showCommandNotice`, 5 s). "Clear Draft" and the put-away draft's expiry drop the attachments; hide/show keeps them (the stash holds the markers, the adapter the attachments; the rebuilt text view redraws the chips).
- **Files are on in Dispatch too**, on code's exact rules: the model has `Read` (and `Bash` for inspection), a `[File #n]` is only a path in the text, needs no model capability and passes the same read-deny and `realpath`/`stat` checks. Nothing about Dispatch makes a path riskier to name than in code.
- **Transcript**: full screen is `TranscriptView`, so sent chips draw as in a code bubble; the one-line turn preview shows the placeholders as text. The old orb field never wires a row and stays without attachments.
- Not yet tried by hand: a live drop/paste into the pill (a non-activating panel).

## Transcript: images the model read, and file links (2026-10-13)

- A `read` of an image returns "[image]" — the bytes go to the model and never reach the session log. The reducer keeps the read's whole `file_path` (`ActivityItem.readPath`; the row's `detail` stops at 100 chars) and the tool row draws each image it read as a compact thumbnail (`toolCallReadImagePath`, `toolRunReadImages`): on the collapsed row (deduplicated across the turn, at most 12 with a note) and per call when open. A result with images and no path (a ComputerV2 screenshot) keeps the "Screenshot" chip.
- A reply's thumbnails (`TranscriptFileMentions.swift`) are images the reply NAMES that exist — minus those a read of the same turn already shows. Before this, those were the only pictures, which is why a turn that read seven images showed the two whose paths the linkifier happened to parse.
- Links: inline markdown recurses into bold/italic/strike (a code span inside `**…**` is a code span). Every path that resolves to an existing file or folder links: absolute, `~/`, trailing-`/` folders, code spans with spaces (absolute, or a bare file name), and relative names — resolved against the working directory plus the turn's directories (attachments, tool paths, folders and files the reply names absolutely: `TranscriptMentionResolver`, two stat passes off-main through `TranscriptFileExistenceCache`) and linked only when EXACTLY one path matches. A click (`transcriptFileLinkAction`): images, and any file in a session with a working directory, open in the panel; folders open in Finder; other files are revealed in Finder.

## Files: `[File #n]` + `files` (2026-10-13)

- Same contract as images: `text` keeps `[File #n]`, `user_message.files: [{n, path}]` (`UserMessageFileRef`, ≤ `USER_MESSAGE_FILES_MAX` 20, path ≤ 4096), the model is given the path (`modelTextOf`). Any type, folders too; nothing is read, copied or staged, and no model capability is needed.
- `checkedFileRefs` (`ipc/server.ts`) → `validateFileRefs` (`agent/stage-image.ts`), before any resume/append: harness role only (`file_reference_invalid`); code and dispatch only (`file_session_not_code`); images + files TOGETHER ≤ `USER_MESSAGE_ATTACHMENTS_MAX` 20 (`file_reference_invalid`, "A message can carry at most 20 attachments" — 20 × 4096-char paths stays inside the 160 KiB per-event cap; the Mac refuses the same before staging); `n` unique, in `text`, ≤ 20; absolute, no `UNSAFE_PATH_CHARS` or edge whitespace; not in Read's read-deny set as spelled AND resolved; `realpath` resolves (else `file_unreadable`, `data.n`); `stat` a regular file or directory (never `open`, so a FIFO is refused unblocked). No refusal echoes a path.
- Skew: hello `features` adds `attachment-files` (`DAEMON_FEATURE_ATTACHMENT_FILES`, `WinterClient.supportsAttachmentFiles`); without it the Mac substitutes the paths into the text. `sync.push` refuses a `user_message` with `files`.
- Producers: `hub.send`, `WinterSession.appendUser` (send, steer, `holdForHandoff`), `LegSession.send/steer`'s 4th argument.

## The phone never gets a Mac path

- `phoneViewOf` (`sessions/history.ts`, both phone paths: `session.history` and the remote stream filter) cuts every `images` AND `files` entry to `{n, path: <basename>}` (`phoneAttachmentName`; a bare `/` reads `file`). The `path` KEY stays because the phone kit decodes `{n, path}` with `path` required; the log and the Mac keep the full path. Pinned by `test/ipc/session-send-files.test.ts` and, for Dispatch, `test/ipc/dispatch-attachments.test.ts` (no `/` reaches a remote client).
