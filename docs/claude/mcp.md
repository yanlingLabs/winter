# MCP: connector permissions, sign-ins, elicitation

*Read this before touching an MCP server's permission, OAuth or elicitation path, an `mcp.*` RPC or `winter mcp`.*

## Connector permissions

- A **connector action** is `mcp__<server>__<tool>` of a USER-configured server (user/local/project scope, or an enabled plugin's `.mcp.json` — same on the wire). Never a capability tool (`mcp__winter__<key>__*` for a key THIS incarnation built, or a plain name like `Browser`), never a built-in. Predicate: `isConnectorToolName` (`packages/core/src/agent/mcp/connector-permissions.ts`), never `gate.ts`'s `isExternalToolName`.
- **Store**: `settings.json` → `mcp.toolPermissions: {server: {tool | "*": allow|ask|deny}}`, read live; a tool's value beats its server's `*`; nothing stored = unset. Loose to the row: an unrecognised value reads `ask`, a non-object row all-actions `ask`. `mcp.setToolPermission` hands the daemon the written table at once (`onConnectorPermissionsSaved`) — no wait on the watcher's debounce. Claude-grammar rules in `sdk/settings.json` cannot be the store (snapshotted into the run folder at incarnation; a deny beats any hook); they still bind natively (deny every mode, allow/ask code only) and `mcp.tools` reports them beside the setting.
- **Matrix** (`connectorVerdict`): **deny** → deny under every policy, `bypass` included. **allow** → allow; under `plan` only a read-only action. **ask** → a card in code (even `bypass` or over a saved allow rule), chat and dispatch; deny under `dont-ask`; under `plan` a card only for a read-only action. **unset** → read-only runs unasked everywhere; else a card in chat/dispatch and the gate's per-policy verdict in code. A dispatch child takes the code row; its "ask" relays to its coordinator.
- **Stated server** (hook input `winter_mcp_server {name, config_name, read_only_hint?}` / `canUseTool`'s `mcpServer {name, configName, readOnlyHint?}` — `StatedMcpServer`, `connectorFactsFor`'s `stated`): exactly that server. Tool = what follows `mcp__<name>__` or `mcp__<configName>__`; the stored value is the CONFIG name's; a value under the renamed name only TIGHTENS (deny > ask > default > allow); a renamed server (`name !== configName`, a subagent's clashing inline server) takes the config name's deny/ask but NEVER its allow; read-only is the stated hint.
- **Fallback** (no statement): a server name may contain `__`, so `mcp__cf__prod__x` is weighed at EVERY split (`connectorCandidates`; one resolver for hook, bridge and `mcp.tools`): strictest wins; a configured-but-unlisted split votes the default and forbids read-only; an unconfirmed server's `*` allow never allows; read-only only from a listing naming the tool.
- **Read-only** (`agent/mcp/connector-source.ts`): `McpManager`'s probe (`annotations.readOnlyHint`), from the scope the name resolves to (local > project > user; local never probed, a project server only from its own listing). A miss fails toward ask, never blocks a turn; the only background probe a call may start is an unprobed http/sse USER server's — never stdio or project (a process). Values are keyed by server NAME across scopes; an inline subagent server by its CONFIG name (`agent/mcp/server-names.ts` reads plugin and `agents/*.md` inline names; `mcp.list` shows them `source: "agent"`, never probed).
- **Two-sided**: the PreToolUse connector-permission floor (`runtime-sdk/hooks.ts`, every mode, fail-closed) answers the child directly — the only layer seeing natively-decided calls (bypass, saved allow, dont-ask) and the only one that ALLOWS; `approval-bridge.ts` applies only deny and ask. This reverses "chat never asks" for connector actions ONLY (`gate.ts`'s chat branch answers `ask`; plain Allow/Deny card).
- **Remove/rename** (`agent/mcp/mcp-write.ts`): `mcp.remove` clears a name's values only once nothing uses it (`mcpServerNameDefined`: user scope, any local scope, any trusted project's or linked worktree's `.winter/mcp.json` — gitdir files read, no git process; any read error = in use —, plugins, subagent definitions, plus live sessions' `WinterSession.mcpServerNames`); reports removed even if that fails (`permissionsNote`). `mcp.rename`/`winter mcp rename <old> <new>` renames within one scope; refuses a new name anything uses or that holds values/rules; COPIES values and `mcp.disabled` first, drops the old only when unused — never less strict in between. Claude-grammar rules are never rewritten; both doors list those that could name the server as `rulesNotFollowed`. With a live daemon the CLI goes through it. A sign-in is keyed by URL, so it survives a rename.
- **Doors**: `mcp.tools`, `mcp.setToolPermission` (local only; refuses `winter`/`winter__*`), the Library MCP page, `winter mcp permissions <server> [<tool>|'*'] [allow|ask|deny|default]`; a server-wide value clears the per-action ones.

## MCP sign-ins (OAuth)

- An http/sse server may carry `oauth {clientId, clientSecretRef: {kind:"keychain"} (a MARKER), callbackPort, authServerMetadataUrl, scopes}` on every config surface; validated with the runtime's `validateMcpOAuthConfig(oauth, url)` before any write.
- The SDK (`@yanlinglabs/winter-agent-runtime/mcp-auth`) owns the protocol: discovery, registration (pre-registered > CIMD > DCR; `WINTER_MCP_CLIENT_METADATA_URL` = `https://yanlinglabs.com/winter/oauth-client.json`), PKCE, loopback listener, `state`, issuer checks, and the fetch policy (`mcp-auth/fetch-policy`: https-only, loopback only when the server itself is loopback, no cross-origin redirect, 30 s, 1 MiB, literal non-public addresses refused; no DNS, so a name resolving privately IS fetched — parsed only as metadata/token answers). Every auth request, refresh and revocation uses it.
- Keyed by CANONICAL URL (one sign-in serves every scope) in three Keychain items: `mcp-oauth:<id>` (token record — the only one a session may be answered, via `toSessionMcpTokenRecord`, refresh token masked), `mcp-oauth-client:<id>`, `mcp-oauth-client-secret:<id>` (daemon-only, `isNeverBrokered`; account derived from the URL, never named by config). ONE store per Keychain service (`runtime-sdk/mcp-oauth-store.ts`'s `daemonMcpOAuthStore`; the refresh single-flight is keyed on the store object — never construct a second); injected `secrets` → a memory store.
- **Doors** (`agent/mcp/oauth-doors.ts`, LOCAL only): `mcp.login` (→ `authUrl`; flow kept 5 min), `mcp.loginStatus`, `mcp.logout` (best-effort RFC 7009 revoke; registration kept unless `forgetClient`), `mcp.clientSecretIssuer`, `mcp.setClientSecret`. CLI: `winter mcp login <name> [--yes] [--confirm-issuer-change]` (asks before opening the browser; `--yes` skips only that), `logout <name> [--forget-client]`, `set-secret <name> [--from-clipboard [--issuer <it>]]` (masked prompt only; the clipboard path prints the issuer first, reads via a spawned `pbpaste` — never argv/env/pipe — and clears the clipboard), an auth column in `winter mcp list`.
- A client secret is bound to an issuer: written only with the issuer the USER-scope server's discovery names, confirmed as `expectedIssuer` (`mcp_expected_issuer_required`, `mcp_issuer_changed`; FULL issuers, `sameIssuer`). A sign-in whose issuer differs from the stored registration's refuses `mcp_issuer_change_requires_confirmation` (both in `data`) until repeated with `confirmIssuerChange`.
- Startup: a valid token is used as is (never refreshed at connect); an expired one is refreshed only when a refresh token exists; else `needs-auth` — tools hidden, no authenticate tool, the SDK's persisted `mcp_needs_auth` attachment. `mcp.list` rows: `status: "needs-auth"`, `auth` (`none|signed-in|needs-auth`), `oauthIssuerOrigin`, `oauthPreregistered`.
- A sign-in/out never evicts a child: every live session naming that URL (`WinterSession.mcpServerNamesFor`) reconnects the server by name (`reconnectMcpServer`, `agent/mcp/reconnect.ts`; mid-turn children at their idle boundary).

## URL-mode elicitation

- Every incarnation sets `Options.onElicitation` = `runtime-sdk/url-elicitation.ts`'s `elicitationHandlerFor`. URL mode ONLY (form/no mode declines, no card). Cards only a plain https url: no credentials, no whitespace/control chars, ≤ `ELICITATION_URL_MAX_LENGTH` (2048, checked before parsing); `host`/`origin` from the daemon's one parse (the schema refuses a disagreeing line, `sync.push` included). Cards in code, chat and dispatch under every policy but `dont-ask`, `bypass` included; a dispatch CHILD declines.
- **The url is never persisted** (it may carry a one-time code): `elicitation_requested` carries `serverName`, `message` (capped, bidi controls stripped), `host`, `origin`, `issuedAt`, `expiresAt`; the url lives only in the `ElicitationBroker` while pending. A local client asks `elicitation.url {sessionId, elicitationId} → {url}` (`NOT_FOUND` + `data.code: "elicitation_not_active"` after) and answers `elicitation.respond {…, action: accept|decline}`. `elicitation_resolved` records the answer or the daemon's `cancel`: `by: "aborted"`, `"turn-ended"` (`elicitationTurnTracker` tags a card with the main turn running when raised; one raised between turns waits for its timeout; subagent turns touch nothing), `"timeout"` (`ELICITATION_CARD_TIMEOUT_MS`, 10 min).
- Nothing opens the link by itself: the CLIENT fetches the url, checks https to the card's host, opens, then accepts — Mac `apple/Winter/Sources/ChatContent/ElicitationAnswer.swift` (mouse-only, "Open link" disabled past `expiresAt`, a failed fetch or `alreadyResolved` resolves locally as "no longer active"), TUI `packages/cli/src/elicitation.ts` (`/usr/bin/open` as argv); `winter -p` and the plain shell decline at once naming server and host. No client prints or logs the url; daemon logs name only the origin.
- Both RPCs are LOCAL only (outside every allowlist plus an explicit harness-role check). The pair is persisted like `approval_requested` but in neither `HISTORY_EVENT_TYPES` nor `TRANSIENT_EVENT_TYPES` — never on a remote stream, `session.history` or a model-readable transcript.
