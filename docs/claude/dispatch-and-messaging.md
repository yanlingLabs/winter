# Dispatch and messaging

*Read this before touching mid-turn pushes, turn pairing, Dispatch's children, SendMessage/ListAgents/TaskStop, ListSessions, or the Mac pill's command mode and terminal.*

## The fold: a push made while a turn runs joins it

A steer (`session.steer`), a messaging delivery or a SendMessage to a running session is pushed into the child at once; the child folds every pending push into the running turn before its NEXT request (after the next tool round) and says so with `system/host_input_folded` (`count` = its N earliest pending pushes). A folded push gets no `result`; a push still pending when the turn ends (an interrupt, budget or hook stop included) is its own next turn with its own `result`. `UserPromptSubmit` runs per folded prompt; a block, `/compact` or a resolver-expanded `/name` ends the fold there.

- Members live in ONE file, `packages/core/src/runtime-sdk/fold.ts` (`FOLD_SINCE` = 0.0.44, `runtimeFolds`, `hostInputFoldedCount`, `clearQueuedInput`).
- Projector (`projector/index.ts`'s `acceptFold`): shifts the folded pushes off its held queue, stops owing them a terminal and announces each one's held `turn_started` NOW; the driver drops them from `inFlight` (`winter-session.ts`'s `onFold`). So every pushed `user_message` has a `turn_started` and a resume never re-pushes a folded text. No projector dedupe for a fold. A daemon-held `send` is never pushed early — only what was pushed can fold.
- **Consumer rule: a main `turn_started` while a main turn is OPEN is a continuation, not a new turn.** "Open" is read off the LOG (a main `turn_started` since the last main `turn_completed`), never off the driver's idle settle. Consumers: the Mac reducer (`apple/Winter/Sources/Model/SessionModel.swift`), the TUI, `winter -p` and its watchdog (`packages/cli/src/watchdog.ts`), the headless elicitation gate, `elicitationTurnTracker`, `DispatchChildren.mainTurnOpen`, and `TurnOriginPairer`/`runningTurnOrigin` (`sessions/turn-origins.ts`), which pair a continuation by ADJACENCY — the nearest preceding unpaired message — so the running turn's origin becomes the folded message's.
- A CONFIGURED code runtime is whatever binary is there, so each spawn hook reports its version (`WinterSpawnHook.runtimeVersion`: the pin for locked rungs, else `executable.ts`'s `winterBinaryVersion`); `WinterSession.foldsQueuedInput` is true only for a runtime KNOWN ≥ 0.0.44 (unknown = not folding: SendMessage queues rather than steers). An older runtime never sends the fold frame, and its `unknown_subtype` answer to `clear_queued_input` is caught (nothing cleared).
- A resume racing an eviction waits for the evicted driver to end (`WinterSessionDeps.predecessorDone`, bounded by the end budget) before `open()` reads the log ONCE (`logFacts`), so the dead-turn close never lands beside the old child's own terminal. Per-call tool results: [runtime-and-sessions](./runtime-and-sessions.md).

## Dispatch's children (`SpawnSession`)

The `sessions` server's `session_spawn` runs `packages/core/src/agent/dispatch-children.ts`'s `DispatchChildren.spawn`.

- Pre-flight refusals are tool errors, nothing created: not a dispatch caller, `cowork`, dir not an existing absolute directory or `/` (canonicalised first), empty prompt, a model outside the LIVE `pickerModels` list (the schema enum is a boot snapshot), shutting down.
- Minted through `session.create`'s own transaction (`ipc/server.ts`'s `createSessionInternal`, published as `onSessionCreator`): CODE, `origin: "dispatch-child"`, `parentSessionId` = coordinator, the coordinator's CURRENT policy (`childPolicyFor`, FIXED for the child's life), model stamped at creation, NOT backgrounded. The prompt goes in through the driver's `send` (`clientName: "dispatch"`); the tool returns without waiting; an undeliverable first message rolls the child back. Spawns of one round run at once, every step per call; an interrupted coordinator turn cancels in-flight spawns via `ctx.signal` (before creation: nothing; before `send`: rolled back; after: the child keeps working).
- **T5 detach rule** (`sessions/activity-enforcement.ts`): a terminal-kind harness's last detach aborts only a turn a HUMAN started (`runningTurnOrigin` over the log); an origin in `AUTOMATED_TURN_ORIGINS` (`messaging`, `dispatch`, `dispatch-wake`, `computer-wake`) is never aborted.
- A hub observer follows only turns Dispatch started (the spawn's, and a follow-up it delivered — `expectFollowUp`, keyed on coordinator + exact text), writing `child_update`s onto the coordinator's log (`running | awaiting_approval | awaiting_input | completed | error`, last main-thread message as `resultSummary`). An interrupted turn reports `completed` naming who stopped it — every stop door calls `DispatchChildren.noteStop` first.
- **Card mirroring**: `approval_requested`/`question_asked` of EVERY child turn, whoever started it, are mirrored onto the coordinator's main thread with `childSessionId`, resolutions after them, answered at the child's id; an unfollowed turn's cards ride a relay-only entry (no status, no wake). The unattended notification is skipped when the coordinator or the asking child has a harness attached.
- A child's "ask" CARDS (`cardsRelayedToDispatch`, `runtime-sdk/approval-bridge.ts`); approvals and questions expire after `DISPATCH_CHILD_APPROVAL_TIMEOUT_MS` (10 min) — EXCEPT a card raised in a turn the USER typed into the child (`dispatchChildCardTimeoutMs`; a known non-automated origin is human, unknown stays bounded) and ComputerV2's desktop-switch card ([computer-use](./computer-use.md)). It stays the ONE card on the child's log; both doors answer one broker entry (first wins, second gets `alreadyResolved`). **Dispatch respects its approval policy** (user ruling 2026-10-17, reversing P8b-7 for dispatch): its OWN "ask" is a card on its own log exactly as code's — `approval_requested`, answered with `approval.respond` at the dispatch session's id, shown in the Dispatch pill (the same floating cards as a child's), else on the island, and on the phone — with no rule option (`plainCard`: a saved allow rule never reaches Dispatch's runtime, so "Allow everywhere" could not apply to it — though the daemon's own saved-rule checks still do, e.g. a `WebFetch(domain:X)` rule approving a dangerous domain in its browser, as in code; [tool-surface](./tool-surface.md#saved-allow-rules)). `plan` stays refused for dispatch (`exit_plan_mode` is code-only); `ask`, `accept-edits`, `auto`, `dont-ask` and `bypass` answer as in code, deny texts included — except a connector action with no stored permission that its server does not mark read-only, which cards in Dispatch even under `auto`/`bypass` (WS-26's dispatch row in `connectorVerdict`, `agent/mcp/connector-permissions.ts`; code takes the gate's answer there). A card from a turn the daemon started (a wake, a child's report, a peer's message, an unknown origin) auto-denies `by: "timeout"` after the same 10 min (`dispatchCardTimeoutMs`; its own `AskUserQuestion` resolves unanswered the same way); one the user typed waits. The running turn's origin comes from memory (`sessions/turn-origin-index.ts`: seeded once from a bounded tail of the log, then fed by the hub), never a whole-log read. Its `session_spawn` is allowed under every policy but `plan`. A child's private-address `WebFetch` cards (relayed) like its other asks; a child's MCP link request (URL elicitation) is declined, because elicitations are not mirrored.
- **The wake**: a finished followed turn queues a `<child_update>`, flushed as ONE `send` while the coordinator is idle (resumed if resumable) or at its own settle — coalesced, retried 3 times (`WAKE_RETRY_DELAYS_MS` 2/10/30 s). It is a `user_message` with `clientName: "dispatch-wake"` (`DISPATCH_WAKE_CLIENT_NAME`, `packages/protocol/src/events.ts`): the Mac, the TUI and the dreamer treat it as the daemon's, not the user's. A child's ComputerV2 wake turn (`computer-wake`, [computer-use](./computer-use.md#wake-triggers-computer-usewakes)) is followed like a follow-up when its trigger was armed in a followed turn (`expectWake`). A reported child is forgotten at the coordinator's next turn end; a wake unflushed at stop/crash is lost (the `child_update`s stay on the log).
- Boot: one read of the coordinator's log closes what a restart left open — unresolved mirrored cards (`by: "restart"`) and children still in flight (a closing `error`); only those are re-tracked at their next turn. `beginShutdown()` stops reports and wakes but keeps mirroring resolutions; `stop()` runs just before the store closes.

## SendMessage / ListAgents / TaskStop (`Options.hostMessaging`)

`SendMessage` is the ONE tool that messages AND resumes a session; `TaskStop` stops a session's turn by its `s_…` id. A child resolves `to`/`task_id` in-process first; only a miss reaches the daemon over the control channel (`host_message_send`/`host_message_list`/`host_session_stop`), answered by `packages/core/src/agent/session-messaging.ts`'s `SessionMessaging` — one handler per session, set in `session-driver.ts`'s `optionsFor` (the caller is the session whose handler fired, never a request field).

- Targets: Code sessions (`participatesInActivity` also reserves `cowork`). Refused typed: chat/dispatch targets, the caller itself, an archived session, an empty message. Senders: code and dispatch; chat has no trio ([tool-surface](./tool-surface.md)).
- **A message runs at the TARGET's policy with no card for the message itself — a session at `ask` can drive one at `bypass`. Deliberate (recorded in `gate.ts`).**
- Addressing `s_…` or `session:s_…`. Delivery through the target's own driver (`get ?? ensure`, so a FINISHED session is resumed) under `clientName: "messaging"`: a RUNNING target is STEERED → `delivered` (the steer's own `injected` decides); one whose driver already holds `pendingSends` gets `send` → `queued` BEHIND them (FIFO); idle/finished → `delivered`/`resumed_and_delivered`. Steering needs `WinterSession.foldsQueuedInput`, else `queued`. Otherwise `refused` / `not_found` / `unavailable`.
- One delivery per message: memoised on (caller, caller's runtime INCARNATION — a token per `optionsFor` build, since `msg-N` restarts per process/Worker —, message id, target, text digest) for `DELIVERY_DEDUPE_TTL_MS` (10 min); the abort `signal` and shutdown are re-checked after the resume and before `send`.
- Rendering: Dispatch to its OWN child sends plain text and is FOLLOWED (`expectFollowUp`); every other pair gets an attributed `<agent-message from="session:…">` turn (`runtime-sdk/messaging.ts`'s `renderAttributedTurn`), parsed for `clientName: "messaging"` only by `WinterSessionKit.AgentMessageEnvelope` (`apple/WinterKit`) into "From session …", never raw XML; the dreamer labels it another session's. `notify_when_idle` → a refused `notify` fact.
- **TaskStop**: `stopped` (`interrupt({ discardQueued: true })`), `not_running`, or refused/not_found; never resumes; CLEARS both queues behind the stopped turn — the child's pending pushes (`Query.clearQueuedInput`, BEFORE the interrupt, which would keep them; each gets its `turn_started` at once and `Projector.clearQueued` stops owing it) and the daemon-held sends. While the clear is in flight NOTHING pushes (`clearing`; deliveries deferred in order). A cleared push's `aborted` `turn_completed` lands only after the stopped turn's OWN terminal (at once if the child dies); a daemon-held send is closed with its own `turn_started` + `aborted` terminal, so a resume never re-runs either. `STOP_SETTLE_MAX_MS` (2 s, `winter-session.ts`) only RELEASES waiters: held sends leave the queue with their `turn_started`, their terminals wait for the turn's own — never an aborted terminal mid-turn. The Mac stop button (`session.interrupt`) keeps held messages for the next message.
- **ListAgents**: subagents plus RUNNING peers — `working` (`makeSessionSignalsDeriver`, `onSignalsDeriver`) OR `session.list` label `active` (`onActivityDeriver`) — capped at 50 (`LIST_AGENTS_SESSION_MAX`), the rest `omitted`; never padded with idle sessions.

## ListSessions and the edited-files index

`packages/core/src/agent/tools/list-sessions.ts`. Default: every ACTIVE and BACKGROUND Code session plus Dispatch-spawned ones (idle = `completed`, newest 4 only), capped at 50, overflow and hidden counts stated.

- `query` (≤ 500 chars): `sessions/session-query.ts`, deterministic lexical rules — no model call — across ALL Code sessions, archived included: DATE phrases (local time) must overlap the session's span; PATHS match EDITED files, cwd and title/first message; WORDS match title > first message > edited paths > cwd. The 10 best come back with why.
- **The index** is `session_files(session_id, path, last_ts)` in the store's `index.db` (`sessions/store.ts`): every appended `tool_result.fileDiff` is recorded live (never makes `append` throw); so is every file a **Bash** call wrote (`sessions/bash-edits.ts`): the command read statically with the escape floor's shell reader (`runtime-sdk/shell-words.ts`) under NARROWER, case-kept target rules (the verb list is the file's header; `rm`/`rmdir`/`unlink`/`shred` COUNT, reads never). Paths resolve against the cwd plus every `cd`/`pushd` EARLIER IN THE SAME COMMAND; recorded only when the `tool_result` has `isError: false`. Out of reach by design: anything built at run time, writes not named in the command, a `cd` from an EARLIER Bash call. `appendSynced` indexes too; `recoverAll` re-indexes every log in ONE transaction at open — the backfill (`edited_files_backfill` in `index_markers`) and the crash catch-up. A deleted session's rows go with it; a lost `index.db` rebuilds.

## MCP servers connect after spawn

MCP servers (the daemon's `winter__<key>` ones and user/project servers) connect after the child spawns, so the FIRST turn may wait up to ~2 s while they come up; later turns do not.

## The Mac pill's command mode and terminal

The Dispatch pill (`apple/Winter/Sources/DispatchPill/`) runs a typed line as a shell command when it is one — no prefix. All Mac-app side: the daemon never sees the line, its output or the run.

- **Detection** (`Terminal/ShellCommandLine.swift`, pure): a command only when the whole text tokenizes as a complete shell line (balanced quotes and substitutions, no trailing `|`/`&&`/redirection, compound openers closed), the first word of every simple command resolves (login-shell PATH, a path to an executable, a builtin/reserved word, an alias), and every argument starting `/`, `~`, `./`, `../` exists. `DispatchPillCommandMode` re-judges each edit debounced on a background queue, memoized by text; the purple (and the send circle's run look) stays sticky between verdicts. **Return runs only a text whose own verdict was shown purple** (`shouldRunOnReturn`): it never upgrades white to a run and does NO filesystem or engine access on the main thread (a hung network mount would freeze the app) — the shown verdict alone, at most the 50 ms debounce old. Delete opts out only of a fresh verdict for the exact text; a stale purple deletes. Ghost completion (first word ≥ 2 chars, case-sensitive; path words from their directory) — Tab inserts it (`ComposerTextView.ghostSuffix`). In command mode **→** at the very end of the text (nothing selected, no marked text, no modifier) accepts the ghost and **⌥→** its next word (`CommandTextView.ghostAcceptKey`; every other arrow, ⇧/⌘-arrow and the `/` menu's ↑/↓ are untouched); **Tab** cycles the candidates like zsh's menu-complete (`CompletionCycle`: the common prefix first when longer than what is typed, then each candidate, round; **Shift-Tab** back, only while a cycle holds; any other key ends it, keeping what is in) — candidates from `shellCompletionCandidates`, computed off the main thread with the verdict: on-screen paths first, then zsh's (same engine and gates, nothing runs), then the folder's entries (folders with `/`); while cycling the ghost gives way to a quiet `2/7`. The ghost is STABLE between verdicts (`commandGhostContinuation`): typing its own next characters trims it at once, deleting grows it back, a recompute with the same result changes nothing, and it is cleared only when the suggestion is truly none (or the text diverged).
- **Whole-command validation** (`Terminal/ZshCompletion.swift`), after the structural rules pass: ONE quiet background `/bin/zsh -f` per environment (`ZshCompletionEngine`, started once the PATH probe lands) running only its fixed protocol script; the inner shell that COMPLETES runs under `sandbox-exec` with a DENY-DEFAULT profile (`zshCompletionSandboxProfile`), made per start inside the new pty so it names that pty's own slave (`$(tty)`) as the one terminal it may write: fork/exec and all file READS allowed — path completion lists any directory; writes only to its private temp folder (TMPDIR and TMPPREFIX point there), its own terminal, `/dev/tty`, `/dev/ptmx`, `/dev/null`; signals only within the sandbox; no network, Apple Events, pasteboard, LaunchServices or window server; `osascript`/`open`/`pbcopy`/`pbpaste` cannot run), stopped on app quit, `compinit -C -D` on the system fpath, never the user's `.zshrc`; it drives an inner `zsh -f -i` through `zsh/zpty` the zsh-capture-completion way (a widget around `complete-word`, a `compadd` override printing candidates and whether `_files`/`_message` asked). Return and line-feed are unbound in the inner shell and control characters never reach it (`zshEngineQuoted`); a directory change is its own widget. **Only an allowlist of characters is ever shown to it** (`zshEngineAllowedCharacters`: letters, digits, space, `. _ / : @ % + , = - ~`) and only when the first word (after assignments) of every simple command is on `shellCommandsShownToZsh` (local tools, exactly as typed — never a path, never a wrapper such as `nice`/`command`/`env`/`sudo`/`xargs`/`exec`/`nohup`/`time`/`watch`, never rsync/scp/ssh) — completion functions `eval` parts of the line (`_path_files` the word under the cursor; `_rsync`/`_scp` an `ssh … <host>` line), so `ls $(touch x)/` and `rsync ';touch A;#':` once ran while being typed. Such lines get the prose guard, an expansion counting as a plain word. The engine never starts or waits on the caller's thread: a stopped engine answers nil and restarts in the background with exponential backoff; three consecutive timeouts open a 60 s breaker (prose guard only); the lock is taken with the query's deadline. For each simple command with a completion function (`$_comps`), every later word must be a candidate at its position (exact, a directory's `/` ignored), or an existing path at a file position, or a `-word` where options are offered, or anything at a `_message` position. No completion function, or no answer within `shellCompletionCheckBudget` (300 ms) → the PROSE GUARD (`shellProseGuardRejects`: the line ends in `?` `.` `!` `,`, or ≥ 3 plain words). A lone word is a command only if it is in `shellBareCommandAllowlist` (or a path) — `yes`, `true`, `wait`, `continue`, `say` alone are replies; free-text commands (`shellFreeTextCommands`: `say`/`yes`/… after one unquoted word, `echo`/`printf` after three) and unquoted words at a `_message` position (three) are prose; quoted text never counts. Compound lines (`if`/`for`/`{`/`(`, several lines) stay structural. Replies are memoized per (directory, buffer); a check costs ~1–20 ms uncached. The ghost for argument words comes from the same engine (`shellCompletionGhostBudget`, 150 ms), the directory listing when it cannot answer.
- **On-screen paths** (`Terminal/OnScreenPaths.swift` pure, `Terminal/OnScreenTextReader.swift`): the argument ghost offers file paths the user can SEE in the app they are in. `OnScreenPathStore` reads the FOCUSED window of the frontmost app (never Winter's own; the pill is non-activating) through accessibility in-process, only when `AXIsProcessTrusted()` (never prompts), off the main thread, READ-ONLY: it never sets `AXManualAccessibility` or `AXEnhancedUserInterface` on any app, and a Chromium-family app (Electron, CEF, Chromium browsers — `onScreenAppIsChromiumFamily`, mirroring the helper's `CUChromium`) gets no paths. Bounds: ≤ 2,000 elements, ≤ 200 children per element, 150 ms checked before every read, a 0.1 s messaging timeout per call, depth-first so later = more recent. Text is asked length-first (`AXNumberOfCharacters`): past 64 K characters only the tail, as a range (never the whole value), past 4 M skipped; static texts add their title; a secure field (role or subrole) is never read, nor anything inside it. Reads: on summon, when command mode turns on (≤ 1/s), and when an argument is being typed and the paths are > 2 s old (a read that changes them re-judges the draft). `onScreenPathCandidates`: `/…`, `~/…`, `file://` (decoded); quotes/backticks/brackets and trailing punctuation trimmed (a `.ext` kept), `:line:col` dropped, `\ ` kept, a wrap joined only where obvious (the line ends in `/`, or it fills the text's wrap width ≥ 40); most recent first, one per file, ≤ 30; then only those that exist. The ghost (`shellGhost` → `onScreenPathOffer`) ranks them ABOVE filesystem/zsh completion at a file argument (`shellFileTakingCommands`, a redirection target, or zsh says `_files`): an empty argument gets the most recent, a prefix gets the path it starts (`~/` ↔ home either way; `cd` directories only). Tab accepts; Tab again with the text unchanged cycles the next candidate (`OnScreenPathCycle`, `ComposerTextView.onTab`). An offered path still has to pass the validator to turn purple. **Privacy: the captured text is turned into paths at once and dropped; the paths live in memory only while the pill is up (`deactivate` on hide), never logged, never sent to the daemon or a session.**
- **Folders macOS guards with a privacy prompt** (Desktop, Documents, Downloads, iCloud Drive, CloudStorage, `/Volumes`) are checked like any other — validator, zsh engine and on-screen existence alike; macOS may show its standard one-time "Winter wants to access …" prompt (accepted). Slow mounts are guarded, told apart by FILESYSTEM TYPE (`getfsstat` `MNT_NOWAIT`, `f_fstypename`: nfs, smbfs, afpfs, webdav, autofs such as `/net`, FUSE such as sshfs — anywhere, home included), never by path: the live filesystem is `SlowMountGuardedFileSystem` — answers memoized 10 s, stats on ONE serial queue with at most one in flight (while it is out, every other question is "no" at once — no new thread), one unanswered within 250 ms is "no" and that mount is left alone for 30 s.
- **Delete to opt out** (`CommandModeSuppression`): Delete at the end, nothing selected, mode on → nothing deleted, the text recorded and no longer a command; the mode returns when the text differs from the record AND validates. The record clears on a run, a send or Clear Draft.
- **The shell** (`Terminal/LoginShell.swift`): `pw_shell`, then `$SHELL`, else `/bin/zsh`. PATH and alias names come from a probe shaped like the daemon's `login-shell-path.ts` (`-l -c`, the rc file sourced quietly, markers, own process group, 5 s deadline, refreshed every 10 min). A run is a TERMINAL TAB (`loginShellSessionInvocation`): the user's own shell, INTERACTIVE and login, which runs the line once and stays at its prompt. The line travels in a 0600 `line` file inside the run's private 0700 `mkdtemp` folder, read and deleted as the shell starts — never an environment variable, argument or script. zsh: a ZDOTDIR shim — `.zshenv`/`.zprofile`/`.zshrc`/`.zlogin` source the user's real files at top level (their `ZDOTDIR` or `$HOME`), switching `ZDOTDIR` back between files; the last restores `ZDOTDIR` (and a `HISTFILE` `/etc/zshrc` aimed at the shim) and a one-shot `zle-line-init` hook puts the line in the buffer at the FIRST prompt and accepts it — an ordinary typed command (job control, Ctrl-C, history, prompt hooks, instant prompts) — with HISTORY EXPANSION OFF for that line (`histchars` emptied in the hook — toggling `BANG_HIST` there is too late — and restored in `preexec`), so `fix!it` and `!!` run exactly as validated. bash: `--rcfile <shim> -i` doing a login shell's files; sh/ksh/dash: `ENV`; fish: `--init-command`; each sources the folder's RUN SCRIPT, which `eval`s the line once (`__winter_state` guards a second run). The marks are `133;C;winter-<nonce>` and `133;D;<status>;winter-<nonce>` with a random per-run nonce; `TerminalSemanticMarkScanner` counts ONLY marks carrying it (the line's own output or a nested shell cannot end it early), split reads included; zsh/bash also write `D` from the first `precmd`/`PROMPT_COMMAND` so an interrupted line reports. `CommandRun.commandOutcome` is the line's, `outcome` the shell's. **No automatic fallback**: when no `C` mark has come 5 s into the run (a `ZDOTDIR` set in `/etc/zshenv`, a plugin such as zsh-vi-mode replacing `zle-line-init`), NOTHING is typed for the user (typed bytes could land in a `sudo`/`ssh`/passphrase prompt): the pill shows a neutral waiting cursor, never "failed", and the terminal window says "Your shell didn't run the line automatically (its startup overrides Winter's)" with **Type it** — the user's click writes the line itself plus Return, once (history expansion then applies as for anything typed), drops a `typed` marker in the shim folder so the shim never runs it as well, and the line's state becomes `typedByHand` (status unknown). A line that starts late clears the notice. The shim folder stays until the run ends (or quit). In a SwiftTerm PTY (`Terminal/CommandRun.swift`), cwd = the session's directory when it exists, else home; environment = a login shell's minimum (`loginShellEnvironment`), never Winter's variables. SwiftTerm's `forkpty`+`execve` has no pre-exec hook, so the run starts in a `/bin/zsh -f` trampoline (`loginShellRunTrampoline`) that closes every descriptor above 2 and `exec`s the user's shell; the app's own pipes and each run's pty master are close-on-exec too. No sandbox, no approval. Under unit tests the environment is `.inert` and no test spawns a shell.
- **Autosuggestions in Winter's zsh terminals** (`loginShellZshAutosuggest`, the shim folder's `autosuggest.zsh`, sourced last by `.zlogin`): like zsh-autosuggestions — on every line change (`line-pre-redraw`) the rest of the line is suggested in dim text after the cursor (`POSTDISPLAY`; `region_highlight` APPENDED to with `memo=winter-as`, so zsh-syntax-highlighting keeps its own). Source 1: the most recent history entry starting with the line (`${history[(r)…]}`, `HISTORY_IGNORE` respected); source 2, when none matches and the word is a path (`/`, `~`, `./`): the paths on screen, which the app writes — PATHS only, never screen text — to `paths` (0600) in the run's private shim folder at the run's start and afresh whenever its window becomes key (`OnScreenPathStore.readOnce`); the file goes with the folder. → or End at the end of the line accept it all, ⌥→ (forward-word) one word — the widgets are wrapped and fall through to the key's own otherwise; Tab stays zsh's own completion (its menu cycles). No command runs per keystroke (one in-shell history search, a ≤ 30-line file read for a path; ~tens of µs measured). Off entirely when the user's own zsh-autosuggestions is loaded (`ZSH_AUTOSUGGEST_*` set or its widgets present — checked at start and on every redraw). It lives in that shell only; no dotfile is touched. Residual: bash, sh and fish terminals get none (fish has its own).
- **Idle shells end themselves** (`CommandRunStore.checkIdleShells`): a run's or `/terminal`'s shell ends — as End ends it — once, for `idleShellLifetime` (60 s) without a break, its window has been CLOSED (an open window, even unfocused or minimized, keeps it), it has sat idle at its prompt (the pty's foreground group is the shell's own) and nothing else has run in its terminal session (no background job, no `nohup`'d child — the session enumeration). Any output, keystroke, window opening or process in the session restarts the countdown. One 5 s timer (`idleCheckInterval`, 1 s tolerance) runs only while some shell is open with its window closed — none otherwise. An auto-ended run then VANISHES: its pill rolls back up out of the row (the row's own exit, on the child row's spring, in one change so the stack re-flows without a jump) and the run is discarded — its shim folder deleted, its captured output and terminal freed (`CommandRunStore.vanish`; the session record stays until quit). A shell that ends any other way (`exit` typed in its window) stays as a finished pill, dismissible. Residual: a prompt framework that keeps a helper in the session (gitstatusd) keeps its shell alive.
- **`/terminal`** (the pill's `/` menu, `DispatchPillLocalCommand.terminal`): opens a detached terminal window at once — a plain interactive login shell with NO line (`CommandRunStore.startTerminal`, `CommandRun.isTerminal`), in the dispatch session's folder (home if none). Same shim (so the autosuggestions), same session ownership, End and quit cleanup; its pill reads "Terminal" with the live-shell `›`; "Add to transcript" sends its session tail.
- **Runs and windows** (SwiftTerm 1.18.0, `exactVersion` in `project.yml`; its MIT notice ships at `Contents/Resources/Licenses/SWIFTTERM-LICENSE.txt` — refresh `Support/Licenses/` when the pin moves): `CommandRunStore` owns the runs (≤ 8 kept; ones whose shell ended pruned oldest first), their pills (`CommandPillsView`, a row under the child pills in the floating stack) and their `TerminalWindowController`s (a `PillChromeWindow`; the terminal takes the keyboard on open, on a click and on becoming key). The emulator belongs to the run: closing the window unparents it, the shell keeps going, reopening shows the scrollback. The pill shows the LINE's state (cursor, then ✓ or a red mark) plus a purple `›` while the shell is still open; Stop = Ctrl-C to the foreground job (the shell stays). End (the pill's; the window has none) and app quit signal EVERY process in the run's terminal SESSION (`CommandRunSession`: `proc_listallpids` + `getsid`, the shell being the session leader) — HUP, then KILL whether or not the shell already went — so background jobs in their own groups and ones that ignore SIGHUP go too. A session is pinned to its leader's pid AND start time (`proc_pidinfo` `PROC_PIDTBSDINFO`): while the leader matches, the whole session; once it is gone, only processes still in that session that started after the run began; a pid now held by another process (someone else's session leader) is never signalled. Quit covers every recorded session, dismissed runs included; sessions with nothing left are forgotten. Output is kept as chunked tails (`CapturedOutput`), decoded as UTF-8 before escapes are stripped. "Add to transcript" sends `terminalTranscriptMessage` (header, fenced `$ cmd` + output stripped of ANSI, last 400 lines / 30k chars): the line's own output (`C` → `D`), or — once the user pressed Return in the shell after the line ended — the session's tail from the line's start (`TerminalTranscriptScope`). It is ENABLED whenever the run has any output, and disabled — with the reason as its tooltip (`transcriptUnavailableReason`) — only when there is none yet, or when a send to the target FAILED and a re-list proved the session deleted (`sessionIsGone`): being merely absent from the app's session list (refreshed only now and then) never counts — that is what kept a `/terminal`'s button grey. Its target (`commandTranscriptTarget`): the dispatch session recorded AT RUN TIME through that session's own `session.send` while it exists; a run that recorded NONE goes, on its FIRST click, to the pill's current conversation through the pill's own send (`onSubmit` → `sendOrSteer`, which creates it like a first message) and is then PINNED to that conversation (`pinnedSessionId`) — later clicks go there whatever is focused; only a recorded or pinned session that has since been deleted disables the button.
- Nothing logs a command line, its output, or a PATH value.
