# Usage and cost tracking

*Read this before touching `packages/core/src/usage/`, the projector's `onTurnUsage`, the `usage.*` RPCs, `settings.usage`, `apple/Winter/Sources/Usage/`, or the island's Usage tab ([island](./island.md)).*

Tokens and cost for every model — cache reads and writes kept apart, because the savings matter — from four sources: **Winter**'s own sessions, the user's own **Codex** (CLI and desktop app), the user's own **Claude Code** and the user's own **OpenCode**; plus the user's **plan windows** for Codex, Claude Code and **Antigravity** (Google's `agy`, successor to the Gemini CLI), and the **subscriptions** they enter. Everything is local: nothing is fetched by Winter from a provider, and no other app's credential is ever read — every other app reports itself through its own installed CLI.

## Storage (`usage/db.ts`)

- Its OWN SQLite file, `<WINTER_HOME>/usage/usage.db` (0600, WAL), its own `PRAGMA user_version` (`USAGE_DB_SCHEMA_VERSION` = 4; a failed open or migration closes its handle). Never a table in `runtime-state.db`, whose schema other branches move.
- `usage_records`: one row per model per Winter turn, per Codex `token_count` increment, per Claude Code assistant message — `source`, `at`, `session_id`, `mode` (Winter only), `provider`, `model`, `input` (UNCACHED), `output`, `cache_read`, `cache_write`, `reasoning` (Codex, OpenCode; never added to a total), `cost_usd` (NULL = unpriced), `cost_basis` (`list` | `estimate` | `reported` | `unknown`), `cache_savings_usd`. OpenCode adds one row per model per variant per LOCAL day (below). `dedupe` is UNIQUE: a re-read never counts twice. All-time history is kept.
- `usage_hourly`: the same numbers per hour × source × provider × model, written in the record's transaction only when the record was new. Ranges ≤ 24 h read records; 7 d / 30 d / all read the rollup.
- `ingest_files`: per-file read state — keyed by a SHA-256 of the path (the plaintext path names the user's project), with the inode, byte offset and the per-file carry (Codex's last cumulative totals, model, session id).
- `subscriptions`: the plans the user entered.
- `synthetic` (schema 3): `usage_records.synthetic` = 1 marks a row DERIVED from Claude Code's `/stats` cache (below); `usage_hourly.synthetic_records` counts them, and every row/total answer carries `syntheticRecords`. They are the only rows ever replaced or removed (`UsageDb.reconcileSynthetic`, which takes a removed row's numbers back off its hour). Index `(source, synthetic, at)`: the first-transcript-day lookup is a seek.
- `probe_latches` (schema 2): a plan probe switched off for one exact binary — `claude:` / `agy:<sha256 of the realpath>:<mtime>:<size>` (hashed: the path names the user) — because its `/usage` reached the model loop. It survives restarts; an updated binary is a new key and is tried again.
- `reported` (schema 4): `cost_basis` `reported` = the other app's OWN cost figure (OpenCode's), counted in `usage_hourly.reported_records`; a model row's basis folds list / estimate / reported (one kind = that kind, several = `mixed`). OpenCode's day rows are the only non-synthetic rows ever replaced (`UsageDb.replaceDay`, which takes a removed row's numbers back off its hour); its progress is a JSON record in `ingest_files` under the key `opencode:progress` (`sourceState`, no file behind it).

## Winter's own turns

- The runtime's `result` carries `modelUsage`: a session-CUMULATIVE ledger per model row (`inputTokens` uncached, `outputTokens`, `cacheReadInputTokens`, `cacheCreationInputTokens`, `costUSD`, `costBasis: "list"` only on a priced row, `canonicalModel`, `provider`), unpriced rows included at `costUSD: 0` (agent SDK `engine.ts`'s cost ledger; prices from `@yanlinglabs/winter-provider-runtime`'s `estimateCostUsd` over the pinned catalog's `official-doc` pricing). Reasoning tokens are not on it.
- `projector/terminal.ts`'s `turnModelUsageOf` differences each row against the previous result's copy (a row that went DOWN is a fresh ledger — a new incarnation — and counts whole); a result with no ledger but claude's per-turn `usage` block is its own figure, keyed on the session's model. The projector calls `deps.onTurnUsage({sourceId, rows})` INSIDE the terminal's claim, so a replayed prefix never calls it twice; `session-driver.ts` adds the session id, `daemon.ts` the mode, and `UsageService.recordWinterTurn` stores it (`dedupe` = `winter:<session>:g<generation>:rs:<backend>:<turn>:<model>` — a new incarnation restarts its turn counter, so the generation keeps its turns apart). `turn_completed` is unchanged: no protocol event changed.
- A runtime-priced row keeps the runtime's price (`list`). An unpriced row (a subscription row such as `codex-oauth/*`) gets Winter's estimate at its API twin's list price (`openai/<model>`; `estimate`); a row nothing prices stays `unknown` (never a guess).

## Pricing (`usage/pricing.ts`)

The SAME catalog and price function the runtime uses: `loadCatalog()` + `estimateCostUsd` (cache reads and writes at their own rates, a missing cache rate at the input rate, the 1-hour cache-write subset at 2× input). Lookup: the exact key, the provider's upstream id or alias, the twin provider (`codex-oauth`/Codex → `openai`, Claude Code → `anthropic`), and for Anthropic ids a dated id without its date and `4-5` as `4.5`. Every cost for Codex, Claude Code or a subscription row is a **list-price estimate** (the UI marks it "est."): a subscription is not billed per token. `cache_savings_usd` = the same reads priced as plain input minus as cache reads.

## The external ingest — on demand, never in the background

- Runs only when a Usage surface asks (`usage.summary` / `usage.series`): single-flight, throttled to one pass per 20 s (a flipped tracking switch, or a pass that ran out of budget, skips the throttle); the RPC waits at most 1.5 s for it and answers what is stored. No watcher, no timer: an idle daemon does nothing (`check:idle-wakeups` stays at 0/s; it points every `WINTER_USAGE_*` at nothing, so the measurement never touches the developer's own apps).
- `ingest-files.ts`: only the bytes appended since the stored offset, whole lines only (a partial last line waits); the inode changed (rotated, replaced) or the size below the offset (truncated) → from 0, with dedupe keeping the counts right; a line over 16 MiB is skipped whole — and a skip that outlasts a pass's bytes is persisted (`__skipping` in the file's state, the offset past what was read), so the offset ALWAYS advances; 64 MiB per file per pass (a whole budget for every file) and 256 MiB per pass before more files wait, yielding between files.
- **Codex** (`usage/codex.ts`): `<CODEX_HOME>/sessions/**/rollout-*.jsonl` and `archived_sessions/`. Only `session_meta` (`id`, `model_provider`, `model`), `turn_context` (`model`) and `event_msg`/`token_count` are parsed. The delta is `info.total_token_usage` against the file's previous total; a file's FIRST count uses `last_token_usage` (a resumed session's file opens with the old cumulative total), a total that went down uses `last_token_usage`, an unchanged total is nothing. OpenAI's `input_tokens` INCLUDES `cached_input_tokens` and `output_tokens` includes `reasoning_output_tokens`: normalized to uncached input + cache read; reasoning kept as its own column, never added. `dedupe` = `codex:<session id>:<cumulative total>` (an archived file re-read counts nothing new).
- **Claude Code** (`usage/claude-code.ts`): `<claude config dir>/projects/**/*.jsonl` (subagent transcripts included). Only `type: "assistant"` records with `message.usage`: `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens` (+ `cache_creation.ephemeral_1h_input_tokens`), `message.model` (`<synthetic>` skipped), `message.id`, `requestId`, `sessionId`, `timestamp`. A streamed message repeats per content block and across files: `dedupe` = `cc:<message id>:<request id>`, first copy wins.
- **Claude Code's `/stats` history** (`usage/claude-stats.ts`) — see the section below.
- **OpenCode** (`usage/opencode.ts`) — see its section below.
- **PRIVACY (hard rule)**: from another app's files only numbers, a model, a time and an opaque session id are kept — never content, a cwd, a path (offsets are keyed by its hash) or a project name, and nothing of them is logged or sent. `test/usage/ingest.test.ts` greps the raw DB and WAL bytes and every RPC answer for fixture sentinels.

## Claude Code's `/stats` history (`usage/claude-stats.ts`)

Claude Code deletes transcripts after its retention period (30 days by default); its `/stats` cache, `<claude config dir>/stats-cache.json`, keeps per-day per-model totals after that. Winter backfills from it ONLY the days its transcript ingest cannot cover.

- **What the numbers mean** (read from Claude Code 2.1.293's bundled code — cache `version` 5, `dailyModelTokensVersion` 5): `dailyModelTokens[].tokensByModel[model]` = input + output + cache read + cache write of each assistant message whose own timestamp falls on that **UTC** date. Before `dailyModelTokensVersion` 5 it was input + output only (cache excluded, keyed by the session's first message): such a day is scaled to all four kinds by the model's all-time ratio. A v5 rebuild recomputes the days from the transcripts still on disk, so the file's coverage starts at its last rebuild. `modelUsage` = all-time sums of the four kinds; its `costUSD` is not accrued by that code (stays 0). Claude Code counts a streamed message once per transcript LINE (no message-id dedupe), so its totals run higher than Winter's deduped rows — hence the calibration.
- **Read**: only during an ingest pass, with the Claude Code switch on, and only once the transcript ingest has nothing left (`more` false — the boundary depends on it; the removal below does not wait). Re-parsed only when the file's mtime or size changed; over 8 MiB (`CLAUDE_STATS_MAX_BYTES`, enforced on the bytes read) never parsed; a missing, corrupt or over-cap file changes nothing (one fixed log line each). ONLY `dailyModelTokens`, `modelUsage`, `lastComputedDate` and `dailyModelTokensVersion` are read — `longestSession` (a session id), the counters and every other key are dropped with the parse (`test/usage/claude-stats.test.ts` plants decoys and greps the DB, its WAL, the log lines and the answers).
- **Boundary**: the cutoff is the UTC day of the earliest TRANSCRIPT-derived Claude Code record (`UsageDb.earliestReal` — synthetic rows excluded, or the import would chase itself). The brief's per-model rule (before that model's first transcript day AND before the first transcript day overall) reduces to this one cutoff. A row is planned for each (model, day) with day < cutoff, day < today (UTC) and day ≤ `lastComputedDate`; with no transcripts at all, every computed day. **Consequence of the single cutoff**: an old resumed session whose file survives Claude Code's cleanup pulls the cutoff back to its first day, so the days between it and the retention edge (whose other transcripts are gone) are UNDERcounted — never double counted.
- **Row**: `dedupe` = `ccstats:<model>:<YYYY-MM-DD>`, `at` = noon UTC of that day (the same local calendar date from UTC−12 to UTC+11:59; at UTC+12 and beyond it lands on the NEXT local day — and Claude Code's days are UTC days anyway, so near midnight a day's tokens can sit one local day off), `provider` `anthropic` (as transcript rows; the raw `message.model` name on both sides), no session id. The day's tokens × the calibration, split into input / output / cache read / cache write by that model's all-time `modelUsage` ratios (whole tokens, summing exactly). Cost: ALWAYS the catalog's list price of the split (`estimate` — one basis with the transcript rows; the 1-hour cache-write subset is unknown, so priced as 5-minute); only for a model the catalog cannot price, a positive `costUSD` shared out (`costUSD × dayTokens / modelTotal`); else `unknown`; a model with no `modelUsage` keeps its tokens as input, unpriced.
- **Calibration**: per model, Winter's deduped transcript total ÷ Claude Code's own total over the SAME (model, day) pairs — those both have tokens for, inside the reliable window (after the cutoff day, within the last 28 days, before today, ≤ `lastComputedDate`); a model with no shared pair takes the factor of all shared pairs; none → 1. Clamped to ≤ 1: it only corrects the over-count.
- **Never twice**: EVERY pass with the switch on — a chunked transcript import, a missing, corrupt or over-cap stats file included — first removes the synthetic rows on or after the first transcript day (`dropCoveredSynthetic`, an index seek; the transcripts win). Planning is separate: re-planned and re-calibrated only when the file stamp or the first transcript day changed (never merely because a day passed), written only where a row differs (tokens, cost, basis, cache savings) — stable re-imports, same ids. A day the cache stops listing (a v5 rebuild) KEEPS its row: history is never dropped. The tracking switch off: not read, rows kept.
- **Shown**: `usage.summary` / `usage.series` carry `history.claudeCodeStats = {from, before}` (noon UTC ms; `before` = the first transcript day, or with no transcripts the day after the last imported one). The Usage window marks a model row with synthetic records "est.*" with a footnote, and puts "History before <date> from Claude Code’s /stats" under the Claude Code plan.

## OpenCode — tokens and cost only (`usage/opencode.ts`, `UsageService.ingestOpencode`)

OpenCode's plan limits (Go) live only on its web console, so it has NO plan slot; it is a usage SOURCE (chart, per-model table, totals, source toggle), like Codex and Claude Code. Its own CLI reports it: `opencode stats --standalone --days N --models --cost --json` (`opencodeDaysArgs`; `--standalone` runs a private server for the one command and exits — nothing left running; seen live under a second per run), and `opencode stats --standalone --all --json` (`OPENCODE_ALL_ARGS`) for the active dates. Same probe dir, process-group kill (15 s) and allowlisted env as the plan probes, plus `XDG_DATA_HOME` / `XDG_CONFIG_HOME` / `XDG_STATE_HOME` / `XDG_CACHE_HOME` (where it keeps its data) and `TZ` (its days must be the daemon's days).

- **Kept**: per model (`model.providerID` + `model.id` + `model.variant`) the tokens — `input` (uncached, as OpenCode counts it), `output`, `reasoning` (own column), `cache.read`, `cache.write` — and `cost` (OpenCode's own USD figure; a free model reports 0, still "priced"); and `activity[].date`. Sessions, prompts, steps and the tool table are dropped with the parse (`test/usage/opencode.test.ts` plants decoys).
- **`--days` (verified live)**: `--days 0` = `--days 1` = since LOCAL midnight today; `--days N` (N ≥ 1) = the last N local calendar days including today. So today = stats(1), and the local day k days ago (k ≥ 1) = stats(k + 1) − stats(k), per model (`opencodeDifference`; a negative difference clamps to 0).
- **Rows**: one per model per variant per local day — `dedupe` `opencode:<providerID>/<id>:<variant>:<YYYY-MM-DD>`, `model` `<providerID>/<id>` (qualified: the same model on another provider is another model; the variant lives only in the dedupe), `provider` the providerID, cost `reported`. `at` = the day's LOCAL NOON (inside its own local day bucket whatever the DST shift) — except TODAY before noon, where it is `now` (a future `at` would hide the row from every range until midday). OpenCode has day granularity: a sub-day range shows a day's total in one bucket.
- **Each batch** (inside the single-flight ingest pass; at most one per 10 min, `opencodeEveryMs`): (1) today = `--days 1`, REPLACING today's rows (`replaceDay`: every stored row of that local day out, the new set in — written only when something differs); (2) the days to FINALIZE, newest first, by the two-run difference (a run is memoized, so neighbouring days share one): yesterday once after midnight (so a day's tail is final), the last day written as "today" (the daemon may sleep through midnights — asleep since before yesterday, `--all` is asked once more and the active days in between are finalized too), and the one-time BACKFILL — `--all`'s active dates, saved as a `pending` list until done (an interrupted backfill resumes, across restarts, without asking `--all` again). A finalized day is in `done` (the last 14 days kept) and never asked again — marked done even when its difference was empty, so an idle day never burns the budget twice.
- **Budget**: at most 40 runs per batch (`opencodeSpawnBudget`); out of budget = `more` (the next pass skips both throttles — the background catch-up runs it to the end). A FAILED run ends the batch as an ordinary failure, retried after the throttle and never `more` (a broken binary never loops the catch-up). A local midnight crossed mid-batch discards the batch (the runs' days moved under it).
- Not installed (no executable) or the switch off: nothing run or read; stored rows still show. `usage.summary` carries `installed.opencode`: the app shows OpenCode's toggle only when it is on this Mac (`UsagePresentation.showsToggle`).

## Plans — source ladders (`UsageService.codexPlan` / `claudeCodePlan` / `antigravityPlan`)

**Only the apps on this Mac (user 2026-10-18).** Before any rung, a plan whose executable does not resolve answers `source: "not-installed"` — no rollout, no `~/.claude.json`, no Winter codex-oauth status — and the island and the window show no slot for it (`UsagePresentation.showsSlot`). "Installed" is the executable resolution below, which also tries the JS package managers' global bins (`packageManagerBins`: bun, volta, pnpm, every nvm node) so a CLI installed through one is not hidden when the app's `$PATH` is launchd's.

A plan read waits at most 2 s (`planWaitMs`) for a spawn still running — a client's request times out at 5 s — and answers from the next rung meanwhile; the spawn finishes in the background (single-flight) and the next ask gets it. `usage.summary` runs the ingest and the three ladders side by side. A reading says its `source`, its `at` and, per window, `usedPercent` (0…100), `resetsAt` (ms), `stale` + `staleReason`. **Stale**: measured longer ago than its own window (`older_than_window`), or its reset has passed (`reset_passed`) — `plan.ts`'s `staleness`.

**Codex** (`codex.ts`):
1. **Codex's app-server** — the user's `codex app-server` (stdio JSON-RPC, Codex's own protocol, no `jsonrpc` field; shapes from `codex app-server generate-ts`): `initialize` → `initialized` → `account/rateLimits/read {excludeResetCreditDetails: true}` → shut down. `rateLimitsByLimitId.codex ?? rateLimits`: `primary`/`secondary` `{usedPercent, windowDurationMins, resetsAt (s)}`, `planType`, `credits`, `rateLimitReachedType`. Codex asks with ITS OWN login. On demand only, at most once per 60 s (answer or failure cached), 8 s hard timeout, its own process group killed on timeout; never resident.
2. **The newest rollout's `rate_limits`** — the newest 5 rollouts by mtime, each read BACKWARDS from its end to the last record with `rate_limits` (`primary`/`secondary` `{used_percent, window_minutes, resets_at | resets_in_seconds}`); passive, offline, possibly stale.
3. **Winter's own codex-oauth report** — the island's `rate_limit_event` windows from sessions on `codex-oauth` (status only, no percentage), labelled "From Winter's ChatGPT sign-in".
- A non-JSON stdout line (a banner) is ignored; only the replies to our two ids are judged. The rollout rung is cached for 60 s (`fallbackEveryMs`), `~/.claude.json` by its mtime and size; staleness is re-judged at every ask.
- NEVER `~/.codex/auth.json` or any credential: nothing opens a file outside `sessions/` and `archived_sessions/`.

**Claude Code** (`claude-code.ts`; the seam is `ClaudeCodePlanUsageSource`):
1. **Claude Code's own `/usage`** — `claude -p "/usage" --output-format stream-json --verbose --no-session-persistence --setting-sources "" --strict-mcp-config --max-turns 1 --tools ""` (`CLAUDE_USAGE_ARGS`: the invocation verified live, plus two documented hard bounds should `/usage` ever reach the model loop — one turn at most, every built-in tool off; with `--strict-mcp-config` there are no MCP tools; a local command uses neither, though the two extra flags have not been run live), stdin from /dev/null, in its OWN fresh directory (both probes; below) with the probes' allowlisted environment: no hooks, no MCP servers, no session file. NOT `--bare` (it refuses OAuth, so no plan report). The `assistant` message carries `usage_report.rate_limits.limits[]` (`kind` `session` | `weekly_all` | `weekly_scoped`, `group`, `percent`, `resets_at` ISO, `scope` (`{model}`), `severity`, `is_active`). **Guard — latched only on POSITIVE evidence of the model loop**: a `result` with `num_turns` or cost above 0, or a `local_command` naming another command, or a model-turn signal anywhere in the stream (an assistant message that used tokens, or any `tool_use` — then also when the run ends without a result: a timeout, an exit). The binary is then LATCHED off in `probe_latches` (one warning, no content) until it changes. A `result` naming no command at all (an early startup error) and one with `is_error` but the local command (logged out, offline) are ordinary failures: cached for the 5-minute throttle, then retried. On demand, at most once per 5 min, 15 s hard timeout with a process-group kill. The report exists only for a claude.ai login with a known plan; absent → next rung. Source: https://code.claude.com/docs/en/agent-sdk/typescript (`/usage` → `usage_report`).
2. **`~/.claude.json`'s `cachedUsageUtilization`** (`$CLAUDE_CONFIG_DIR/.claude.json` when set) — re-parsed only when its mtime or size changes; over 32 MiB it is not read at all — the cap is enforced on the bytes actually read (at most cap + 1), not only on a stat — with one fixed log line per process — `fetchedAtMs`, `utilization.{five_hour, seven_day, seven_day_<model>}.{utilization (percent), resets_at}`; undocumented, refreshed only while Claude Code runs. The file holds unrelated config (possibly MCP env secrets): parsed in memory, ONLY that key read, nothing else kept, logged or sent.
- NOT used: the statusline route (it would edit the user's `~/.claude/settings.json`), stream-json's `rate_limit_event` (needs inference), OpenTelemetry. Winter NEVER reads, copies or uses Claude Code's Keychain item or token — https://code.claude.com/docs/en/legal-and-compliance.

**Antigravity** (`antigravity.ts`; one rung — nothing else of agy's is read):
1. **agy's own `/usage`** — `agy -p "/usage" --output-format json --print-timeout 20s` (`AGY_USAGE_ARGS`), stdin from /dev/null, its own probe dir, the probes' allowlisted env (no extra variable: no `GEMINI_*`/`GOOGLE_*` key crosses). agy's changelog: print-mode read-only slash commands "emit … a structured payload under --output-format json … without starting an agent turn, spending quota, or leaving a conversation behind"; seen live once (2026-10-18): exit 0, `num_turns` 0, every `usage` count 0, `conversation_id` "". The answer is ONE pretty-printed JSON document (read whole at exit; a banner before it is skipped): `command.name` "usage", `command.data.groups[] {name, buckets[] {id, window ("5h" | "weekly"), remaining_fraction (0…1; may be an int 1), reset_time (ISO UTC)}}` — groups seen: "Gemini Models" (`gemini-weekly`, `gemini-5h`), "Claude and GPT models" (`3p-weekly`, `3p-5h`). Each bucket is a window: `usedPercent` = round((1 − remaining) × 100), `5h` → five_hour/300 min, `weekly` → weekly/10 080 min, `resetsAt` from `reset_time`, `scope` = the group's short name (`agyGroupScope`: a trailing " models" dropped, "Claude and GPT" → "Claude & GPT", an unknown group keeps its name). No plan name (agy reports none). Hard timeout 25 s (above agy's own 20 s), at most once per 5 min (`agyCliEveryMs`), `planWaitMs` as above.
- **Guard** (`judgeAgyUsage`): accepted ONLY when `command.name` is "usage", `num_turns` is 0 and every `usage` count is 0. POSITIVE evidence of a model turn — turns or tokens above 0, another command, a non-empty `conversation_id` — LATCHES the binary in `probe_latches` (`agy:` key; one warning, no content) until it changes, whatever the exit. Ordinary failures — no JSON, a non-zero exit, a timeout, no `command`, a non-`SUCCESS` status, no buckets — are cached for the throttle and retried. Source `agy-cli` (else `none` / `disabled` / `not-installed`); staleness as for the others.

## Spawning the probes (`usage/spawn-lines.ts`)

- **Its own directory**: each probe runs in a fresh `mkdtemp` directory under `<home>/usage/` (`probe-XXXXXX`, 0700, lstat-verified as a real directory). Afterwards exactly that directory is removed — only if lstat still says a real directory (not a link) and its realpath lies inside `<home>/usage`'s realpath; empty → `rmdir`, else `rmSync` on that verified path (which unlinks a link left inside instead of following it). No shared or pre-existing path (a planted `neutral` symlink included) is ever used or cleaned (`removeProbeDir`; `test/usage/probes.test.ts` plants both).
- **Environment: an allowlist** (`probeEnv`): `HOME`, `PATH`, `USER`, `LOGNAME`, `LANG`, `LC_ALL`, `LC_CTYPE`, `TMPDIR`, `SHELL`, the proxy and CA settings (`HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY` and their lowercase forms, `ALL_PROXY`, `NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE`), plus the tool's own config-dir variable (`CODEX_HOME` for Codex, `CLAUDE_CONFIG_DIR` for Claude Code — so it finds its own sign-in where the user keeps it). Nothing else crosses: no `ANTHROPIC_*`/`OPENAI_*` key or base URL (which would move the tool off the user's plan login), no `CLAUDECODE`/`CLAUDE_CODE_*`/`CODEX_*` sandbox or nested-session marker, no `WINTER_*`.
- **Resolution**: an explicit `WINTER_USAGE_*_EXECUTABLE` is authoritative (absolute only; missing or `off` = none); else the absolute install places FIRST (Homebrew, `/usr/local/bin`, `~/.local/bin`, `~/.claude/local`, `~/.opencode/bin`, `~/.npm-global/bin`, the Codex app bundle, then `packageManagerBins`), then `$PATH`'s ABSOLUTE entries — a relative entry is never searched.

## Where the other apps live (`usage/wiring.ts`)

Codex: `$WINTER_USAGE_CODEX_HOME` → `$CODEX_HOME` → `~/.codex`. Claude Code: `$WINTER_USAGE_CLAUDE_HOME` → `$CLAUDE_CONFIG_DIR` → `~/.claude`; its `.claude.json`: `$WINTER_USAGE_CLAUDE_JSON` → `$CLAUDE_CONFIG_DIR/.claude.json` → `~/.claude.json`. Executables: `$WINTER_USAGE_CODEX_EXECUTABLE` / `$WINTER_USAGE_CLAUDE_EXECUTABLE` / `$WINTER_USAGE_AGY_EXECUTABLE` / `$WINTER_USAGE_OPENCODE_EXECUTABLE` (authoritative: a missing path or `off` = none, never a fall-through) → the usual install places (`CODEX_INSTALLS`, `CLAUDE_INSTALLS`, `AGY_INSTALLS`, `OPENCODE_INSTALLS` + `packageManagerBins`) → `$PATH`. `startDaemon({ usage })` injects all of them. **Both test preloads (and `check:idle-wakeups`) point every `WINTER_USAGE_*` at nothing**: no test reads the real `~/.codex`/`~/.claude*`/`~/.local/share/opencode`/`~/.gemini*` or spawns the real `codex`/`claude`/`agy`/`opencode`; tests use fixture trees and FAKE executables (`test/usage/fixtures.ts`: `fakeAgy` by mode, `fakeOpencode` answering `--days N` / `--all` by argv from a history file; the live-seen shapes, sanitized, in `test/usage/shapes/`). Never run the real binaries from an agent: they use the user's own credentials and quota.

## Settings

`settings.usage = { codex?: { enabled? }, claudeCode?: { enabled? }, antigravity?: { enabled? }, opencode?: { enabled? } }`, default all on; the ONE reader is `usageTrackingFrom`; a flipped switch skips the ingest throttle. Off: nothing of that app is read and nothing is spawned, from the next ask (live: `settings.json` → the watcher → the live holder; no restart). `usage.setTracking` writes it.
