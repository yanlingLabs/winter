# Computer use (ComputerV2)

*Read this before touching `packages/core/src/computer-use/`, the `computer_v2` capability, the helper client, the app adapters or Settings → Computer Use. Browser tabs, Phase 3, WebMCP, Winter for Chrome: [computer-use-browsers.md](./computer-use-browsers.md); Winter Headless: [headless.md](./headless.md); the guardian, the focus blip and "never move the user's view": [Focus, the guardian and the user's view](#focus-the-guardian-and-the-users-view).*

## The tool

- `script` on the `computer_v2` server, shown as `ComputerV2` (`["ComputerV2","computer_v2"]` in `packages/core/src/runtime-sdk/tool-names.ts`; `mcp__winter__computer_v2__script` strips to `computer_v2`). Code + dispatch, deferred, concurrency-safe with NO lane (`CapabilityToolFacts.concurrent`): per-target locks replace it.
- Built INSTEAD of the old `computer` server, never beside it (`capabilities/index.ts`); `computerUse.legacyComputer: true` builds the old `Computer` (`computerUseLegacyComputerFrom`, live). The old `Browser` keeps its own transport and lane, no lock between them; ComputerV2's description never names it.
- API (`worker/runtime.ts`): `apps`, `screen`, `App`, `print`, `show`, `sleep`, `browsers`, `scripts`, one class per `AUTOMATION_ERROR_KINDS` entry (`errors.ts`, 13): `StaleRef`, `TargetLost`, `NoWindow`, `TargetBusy`, `Uncertain`, `WaitTimeout`, `NotAllowed`, `Refused`, `NeedsForeground`, `HelperUnavailable`, `PermissionMissing`, `Cancelled`, `BrowserUnavailable`. `NoWindow`/`Refused` keep the helper's sentence (never "the app quit"; canned only when none came); `Uncertain` (sent, unconfirmed) is never retried.
- Description PER INCARNATION (`description.ts`, `capabilities/computer-v2.ts` → `imagesAcceptedBy`): no image input → no `screenshot`, `show`, `Image`, `Point`, `screen.appAt`; calling them is `NotAllowed`.
- **No card per script**: `agent/gate.ts` `SELF_GATED` (allow under every code/dispatch policy, deny in chat); PreToolUse `computerV2AllowHook` (`runtime-sdk/hooks.ts`) allows explicitly so `dont-ask`/`plan` children reach it (a user's deny rule still wins); `toolSearchDontAskHook` states READ_ONLY for `ToolSearch` under `dont-ask` only, else no deferred tool loads there. Policy is per APP, inside the call.
- TUI/`-p` label: `title`, else "<apps> · <verbs>", else "Using the computer" — never the script (`cli/src/tui/format.ts` `computerV2Label`).

## The worker (`worker-host.ts`, `worker/`, `service.ts`)

- One `winter-core __automation-worker` per session under its own seatbelt (`sandbox.ts`): read ALLOWLIST (system paths, the binary, dev-only `packages/core`), `<WINTER_HOME>` and the Read fence denied last, no writes/network/Keychain, minimal env, cwd `/`. `process` and `import("node:fs")` ARE reachable from a script: the sandbox is the boundary (`test/computer-use/worker-process.test.ts`).
- Persistent REPL (`worker/repl.ts`): depth-0 declarations become assignments to a store run `with` (sloppy mode on purpose; redeclaring = reassigning), top-level `await`, TypeScript stripped only after a JS syntax error, errors on the script line (`//# sourceURL`).
- Runs SERIALIZED per session; ends after `WORKER_IDLE_MS` (30 min, never mid-run), with the session's deletion, or at daemon stop (`computerUseRuntime.stop()` first in `stop()`); `reset: true` starts fresh; a lost worker (the idle end too) is reported at the next call.
- Timeout: default 30 s, clamped 1…300 s, PAUSED while a card waits, extended by a long type/paste's estimate (`typing-estimate.ts`). Timeout or interrupt: the in-flight primitive rejects `Cancelled`, later ones throw, the helper gets `cancel {callId}`, an unsettled script loses its worker after `CANCEL_KILL_MS` (1 s). The runtime's own wait is `COMPUTER_V2_CALL_TIMEOUT_MS` (100,000,000 ms, `McpSdkServerConfig.timeout`, `capabilities/computer-v2.ts`): cards wait INSIDE the call.
- **Saved scripts** (`saved-scripts.ts`; limits in `worker/bridge.ts`): `scripts.save(name, fn)` keeps SOURCE in daemon memory only — 32 names, 32 KiB each, 256 KiB/session, 16 MiB daemon-wide (LRU OTHER session cleared, told at its next call), no delete, gone with the session — re-installed into every fresh worker (`run.install`). One function/arrow expression, nothing after (`worker/saved-shape.ts`: a lexer refusing `/` after `of`/`yield`/`await` and any `<!--`/`-->`; checked by worker AND daemon). Installing is INERT: `scripts.<name>()` asks the daemon first (`scripts.run`, counted, cancellable), then re-creates from the stored text, never the closure. `scripts` enumerates nothing. Allowed under every policy; a forged bridge save is a residual risk; audit/metrics carry names only.

## Result (`result.ts`) and diff base (`diff-base.ts`)

- The daemon builds it; worker output is UNTRUSTED. Ordered text/image content (`capabilities/server.ts` `orderedResult`), text cut at 64 KiB with a marker, ≤ 6 images, the error last and never cut (`normaliseScriptError`: a known kind or `Error`, message ≤ 4 KiB). A primitive outside the API is refused before telemetry or audit.
- `<screen-data id="<random>">` fences EVERY text item, prints included, once the runtime has read screen content since its last reset/restart — per SESSION. Daemon sentences (typed failures, a cancel, the omitted-images note) stay outside; the preamble only with a fenced block.
- Diff base: per (session, target) the snapshot the model last SAW (printed, whole-target; never `emit:false` or `within`), sent as `since`; forgotten on reset, worker restart, window switch, `{full:true}`, main-thread compaction (`continuity_warning` `warning: "compacted"`).

## Policy (`policy.ts`) — the daemon decides; the helper enforces only its floors

- Per-app card: daemon-raised `approval_requested`, `toolName: "ComputerV2"`, "Allow Winter to use <App> (<bundleId>)?" (the id: a look-alike cannot borrow a name), callId `cu_<hex>`, options once/session/always, no `rule`; approve without option = once, deny = `approved:false`. `plan`: card on bind, then observe only. `ask`/`accept-edits`/`auto`: ONE card on first bind. `bypass`: no per-app or rung-4 card, but the desktop switch. `dont-ask`: always-granted apps only, no card. Once covers the CALL (target released after: `TargetLost` "allowed for one call only"); session grants last the session (an idle end keeps them); always writes `computerUse.apps.<id>.grant`. A Dispatch COORDINATOR raises these cards; a child's relay through the mirror, bounded.
- Nothing is bound or launched before the bundle id is known (`service.ts` `identifyApp` over `app-resolve.ts`): a name/id from the helper's `apps.list`; a path by `Info.plist` `CFBundleIdentifier` via `plutil` (unreadable = refused); an unlisted id by a LaunchServices lookup, never a launch; an unlisted name refused; the helper's bind must answer the same id.
- `effectiveAppAccess`: the user's `access` → (if `removed: true`) the switch → `DEFAULT_APP_EXCEPTIONS` (password managers `deny`; the listed terminals and System Settings `click`) → the switch (`computerUse.allowAllApps` on = `full`, off = `deny`).
- Floors under every policy, BEFORE any grant (Always-allow never lifts `deny`): Winter itself (`WINTER_OWN_BUNDLE_IDS`), the auth surfaces (`AUTH_DIALOG_BUNDLE_IDS`), helper Floor F — an act on a Chromium-based BROWSER's inspect page or "Allow remote debugging?" dialog, `refused` `remote_debugging` (never Electron/CEF). The dialog is known in every UI language by the browser's OWN words for it — read from its locale packs under the resource ids its English pack anchors (`Floors/RemoteDebuggingLexicon.swift`), the English rule beside them — and fail closed (any dialog of it refused) when the language it shows contributed no words.
- A whole-screen shot blacks out, and `screen.windows` hides, the auth surfaces and every `deny` app (`excludedFromScreen`; switch off: every running app without an allowing exception, from `apps.list` per shot) — NEVER Winter's own windows (seen, never bound).
- Rung 4 (helper `needs_foreground`): a second card under ask/accept-edits/auto ("Winter needs to bring <App> to the front and use your mouse for a moment", Allow once), then a retry with `allowForeground: true` under the global foreground lock; `bypass` retries at once. Refused `NeedsForeground` under dont-ask, plan, and when unattended — `attended` = a non-remote harness on the session ITSELF (never the phone, never the Dispatch pill, which shares the window's client name `orb`; a child only by its own window). `requestForeground(reason)` holds the app in front for the run, on the user's own desktop only. A window on ANOTHER desktop is never retried in front: the helper answers `window_elsewhere`/`needs_desktop_visit` → the desktop switch.
- **Desktop switch**: only for an act or `screenshot({ live: true, reason })` (image models) that cannot be had without moving the user, after every background route. EVERY policy, a Dispatch coordinator too, asks in two places, first answer wins: the session card (`onTimeout: "allow"`, option `switch`) and the helper panel `prompt.desktopVisit` on the user's current desktop (non-activating, never captured, countdown to the card's `expiresAt`). `DESKTOP_VISIT_PROMPT_MS` 60 s (+1 s grace); no answer ALLOWS (`by: "timeout"`). "Don't switch" → `NeedsForeground`, HELD for that app in that session until the user's next human-origin message (`liftDesktopRefusals`; memory only). An allowance covers bundle id + pid for the run. The visit stays OPEN per stretch of work; it closes `visitCloseGraceMs` (1 s, helper) after the last primitive needing it, at script end (`visit.close`), on cancel/Esc, before another desktop is needed, when the user moves, or at the guardian's cap — the user returned and verified; the daemon holds the foreground lock meanwhile. One result line per visit, one `desktop.visit` metric, an audit count. Floors and access first (a `view` app: a live read, never an act).
- Helper ≥ `HELPER_MIN_VERSION` (1.7.0, `protocol.ts`) at `hello`: older → ended, relaunched once, then refused "update Winter". A card's wait never counts against the script timeout.

## Locks and screenshots

- `locks.ts`: per target (bundle id + pid) across sessions, from a script's first primitive on it to its end; a waiter gives up after `LOCK_WAIT_MS` (30 s, sooner near its own timeout) with `TargetBusy` naming the holder. One global foreground lock (rung 4, visits, whole-screen shots; `display` is an index, 0 = main).
- `budget.ts` by model family: Claude 1568 px / 28-px tiles ≤ 1568; Claude 5.x 2576 / ≤ 4784; GPT 1440 / 32-px; Gemini 1440; others 1280; JPEG 0.8 stepped down while over 3 MiB; `computerUse.screenshotMaxDim` an upper bound. Bytes stay in the daemon; the worker holds an opaque handle.

## The helper client (`helper-client.ts`, `protocol.ts`, `helper-verify.ts`)

- "Winter Computer Use" has its OWN TCC identity (`com.winter.computeruse[.dev]`). ONE persistent connection per daemon over `<home>/run/computer-use.sock` (0600, NDJSON JSON-RPC 2.0, `hello` first), lazy. Nothing answering → launched by path through LaunchServices (`open -g -a`; never `-j`; never a child — TCC would check the daemon): dist inside `Winter.app/Contents/Helpers/`, dev `dist/dev/`, `$WINTER_COMPUTER_USE_APP` overrides — only when `launchAllowed` (`daemon.ts`: the profile's default home, no injected `secrets`), so no test daemon launches it.
- `hello {protocol: 1, client: "daemon", home}` answers a `pid` the daemon VERIFIES by code signature (`helper-verify.ts`) or closes typed `helper_unavailable`. The pid is self-reported: the helper's audit-token check of the daemon is the load-bearing direction.
- A closed connection (quit, crash, the helper's 10-min idle quit) = helper gone: targets `TargetLost` at next use, bases reset, next call relaunches. A plain `busy` is retried once after 200 ms, then `TargetBusy`; a `busy` marked uncertain is `Uncertain`, never retried.
- Notifications: `escPressed` cancels the named sessions' scripts and interrupts their turns — only a session running a script NOW; `targetLost`; `permissionsChanged`; `desktopVisited`. The daemon tells `script.active` around each run (again after a mid-run relaunch, `HelperClient.generation`), `turn.ended`, `session.ended`, and `mirror`/`privatePath` on every `target.bind`. A bind's, `useWindow`'s or screenshot's `detail` prints as an unfenced daemon line; `unsupported` passes the helper's sentence, `data.axError` only to the log.

## Telemetry, settings, RPCs

- `<home>/logs/automation-metrics.jsonl`: one line per primitive, 8 MB rotation (`telemetry.ts`); one `audit.jsonl` line per script `{kind:"automation", sessionId, apps, primitives, durationMs, outcome, …}` — never code, typed text, screen text or image bytes.
- `computerUse.*` (`settings.ts`, ONE reader each — `computerUse<Key>From` — hot): `enabled`, `screenshotMaxDim`, `mirror` on, `privateEventPath` on, `legacyComputer` off, `allowAllApps` on, `headless.enabled` on, `webmcp` on, `apps.<bundleId> {access?, grant?, name?, removed?}` (loose; an unknown access reads `deny`).
- Five LOCAL-only RPCs (`packages/protocol/src/methods.ts`; harness role, never remote): `computerUse.status` (never launches the helper), `computerUse.requestPermission` (launches it, forwards `permissions.request`), `computerUse.apps.list` (the EXCEPTIONS only; `lastUsedAt` from `<home>/computer-use/recent-apps.json`), `computerUse.apps.set` (`access: null` stores `removed: true` for a built-in default, else deletes `access`; `grant: null` drops Always allow; an empty row is deleted), `computerUse.setSettings`. Every write and Always-allow answer is served from memory until the watcher swaps the holder (`wiring.ts`).

## App adapters (`computer-use/adapters/`)

- A bind may print, in the TOOL RESULT only (never the description): `app.extras.<name>()` (class view/click/full, applied by the per-app policy — plan, view-only and click-only refuse as for acts, naming `extras.<name>`), `app.dict.<name>(direct?, params?)` (`dict.ts`, from helper ≥ 1.8.0 `target.scriptingCommands`; never `run`/`reopen`/`activate`/`launch`/`quit`/`print`, every one `full`, run like `app.applescript()`), and ≤ 1 guide `<key>@<rev>` ≤ 2,000 bytes (`registry.ts`, `guides/`). Delivered once per session per bundle id (`delivery.ts`), again after a main-thread compaction, reset or worker restart; `app.help()` any time. The daemon re-checks every `extras`/`dict` name.
- THE INVARIANT (`types.ts`): an extra composes only helper methods a script could reach (`target.act/snapshot/find/waitFor/waitIdle`, AppleScript through the service's path, `apps.openDocument` with the opener's own card, read-only `scriptingCommands`); acts held to its class, background only (never the foreground or a visit); no new privileged path, no image.
- It works in the BOUND window, never the app's front window (`window id <windowId>`); unresolvable or wrong kind → `NoWindow`, no fallback.
- `BUILTIN_ADAPTERS` (`registry.ts`): Finder (`selection()`/`reveal()` only when PROVEN the bound window's; `trash()` never follows a link and refuses — "ask the user" — where Finder would raise a dialog), Safari + Technology Preview (`openWindow(url)` = the agent's own window), Mail (headers + DRAFTS, never sends), Notes, Xcode, the Chromium family — a GUIDE only (its dictionary cannot name the bound window). Tests add theirs via `ComputerUseInjection.adapters`. A dictionary is read once per running app; an adapter or dictionary failure never fails a bind. Helper side: `target.scriptingCommands` never reads a DYNAMIC dictionary and drops hidden/refused/JavaScript commands; AppleScript refuses Chromium's `execute … javascript` everywhere and, per run, every JavaScript door the bound app declares. `metric.extra` is the name only.

## Focus, the guardian and the user's view

**ComputerV2 never moves the user's view** (user rule: "this shouldn't happen on any app at all ever"). No action may change the user's frontmost app, key focus or desktop. The only exemptions: the consented rung-4 foreground card, the scoped desktop visit (both above), and the focus blip below. The helper engine is `apple/ComputerUse/WinterCUCore`; its contract is `apple/ComputerUse/PROTOCOL.md` (current helper `VERSION` 1.16.0).

### The focus blip (`Core/CUCore+Blip.swift`)
- Used only to re-validate a menu command/shortcut that reads disabled in the background (and its one retry), and for keyboard input (type, paste as keys, key, editing shortcuts) into a window that does not hold the key focus — once per burst of keys, a fresh blip per burst (`CUKeyBlips`). Never for clicks or reads.
- Focus records make the bound window key for ~60 ms (the user's app resigns active; its front and Space stay), followed by yabai-style make-key records (`Input/SkyLight.swift`: a synthesized ⌘-mouse down/up to the target at a FINITE point outside every screen — never 0xFF/NaN, which traps apps converting the location to `Int`) only when the bound window is not its app's key window; the app is deactivated first when another standard window of it is key; never while it shows a menu/popover/sheet; Chromium excluded (`CUCore+UserView.swift`).
- A head keyboard tap on the target is installed first (`CUKeyReroute`): the user's physical keys go to their place, not the target. Everything ends within 250 ms (`blipDeadlineMs`) with the user's app front again, else the guardian restores it.
- Refusals: when the window could not be made the one the keys go to (a panel, dialog or other window holds them; where they go can't be told) → `focus_not_placed` naming the holder; the app came to the front → `app_in_front`. The keys are NOT sent.

### Accessibility first (`Core/CUCore+Act.swift`, `Core/CUCore+Focus.swift`)
- Presses, values, menu items, AX copy/paste/select-all over accessibility. The `AXFocused` write is NEVER made on web content nor in an app known to activate on it: focus is placed by a press, then a window-targeted click; a typing act whose focus cannot be placed refuses `focus_not_placed`, never typing into whatever has focus. Space/Return INTO a pressable control is that one press; any other key into one is refused.
- Keys go to the focused element's OWN process (Safari's WebContent) with real keycodes. Window-targeted pid events (`CGEventSetWindowLocation`) are preceded by a synthetic activation (type-13/subtype-1, `Input/FocusEnforcer.swift`) so the app believes it is active; a background click gets the make-key records when the window is not key (`keyForClick`; an app that came forward meanwhile gets none: `app_in_front`).
- A web page takes no hover from a synthetic pointer: the daemon says so once per session per app (`service.ts`'s `hoverNote`, from the helper's `webContent` flag); with `requestForeground` or rung 4 the real pointer moves.
- A link pressed in a non-browser app: the helper hands it back (`target.act` `linkOpensViaDaemon`, helper ≥ 1.11.0; older helpers open it themselves) and the daemon opens it through its own door — an act in the opener under its access/card and the dangerous-domain floor. Files/URLs open via `apps.open` (NSWorkspace, `activates: false`). Nothing calls `SetFrontProcess`, sends ⌘N or opens a window to reach one (a running app with zero windows gets one background reopen).

### The Focus Guardian (`Core/CUCore+Guardian.swift`, `Core/FocusGuardian.swift`)
- Runs only with `privateEventPath` on, while a script runs (`script.active`) plus a 3 s tail (`guardianTail`) — never merely because targets are bound. NSWorkspace activation/Space observers plus a listen-only session tap (type-21 CPS notifications, left clicks, hardware-origin event times; never the window server's own source-less events). Secure Event Input polled at 4 Hz.
- **Whose move a change is, is ONE rule**: `CUFocusGuardianCore.judge`, contract §4.12 of `PROTOCOL.md` (invariants I1–I6; I2′ is written down but NOT enforced). Every path asks it; every restore goes to the user's place as it is when it runs; theirs → `app_in_front`, nothing undone; the agent's → undone. Facts it owns: the user's place, causes per pid, `CUSwitchInput` (instants explaining one change only, after the agent's last cause on that app — never typing), claims, visits.
- Causality, not identity: an activation/Space change is the agent's only for an app it touched within 1.5 s (`causalWindow`); anything else is the user's and their new place — except the agent's INDIRECT effect, undone only when CLEARLY the agent's: no user input for 2.5 s (`quietBeforeUndo`), an agent action within 1.5 s that can open THAT app (its reach), no Secure Event Input at any moment of those 2.5 s; otherwise left in front, never adopted, and said. Launches: `Core/LaunchRule.swift`'s `CULaunchRule` decision table (user input between act and launch → theirs; in reach and clearly the agent's → undone; else left and said, never adopted later).
- **I6 `user_working`**: once the user works in a bound target (a click into its window, plain typing, a scroll, while it is in front; watched between scripts too) every act and AppleScript on it is refused `user_working` until it leaves the front; the guard is sticky for the rest of an act (a drag stops at its next step, a click still releases). An agent-caused activation never ends it. With the bound app in front and another window key → `app_in_front`.
- An activation by a touched app not caused by the user is undone under `SLSDisableUpdate` (retried ≤ 2 s, off-main) and noted on the next result; ≥ 3 steals in 10 s are named to the model.
- `GuardianModelTests` (`Tests/WinterCUCoreTests/`, with `GuardianSim.swift`) checks the invariants after every event of seeded random runs on the real engine in simulated time: `WINTER_CU_SIM_SEEDS` (20), `WINTER_CU_SIM_STEPS` (250), `WINTER_CU_SIM_TARGET=<bundle>` (an ordinary app instead of Finder), `WINTER_CU_SIM_SURVEY=1`.

### Windows on another Space
AX where macOS has an element; a window no client ever read while on the active Space has none → the bind is capture-only (screenshots and point clicks; said to the model). Stills via `SLSHWCaptureWindowListInRect` with `0x800` (live content). Windows on no Space are not windows.

### AppleScript
`app.applescript(source)` / `app.scriptingDictionary()` run in the helper (its one entitlement: `com.apple.security.automation.apple-events`). The text and EVERY Apple Event are checked by the OSA send hook (`Script/AppleScriptRunner.swift`, `OSASetSendProc`; policy in `AppleScriptPolicy.swift`): only the bound app, never System Events, no shell/dialogs/files/clipboard/activate/`do JavaScript`/`javascript:` URLs; JXA refused (its ObjC bridge bypasses the check). Counts as FULL access; refused `user_working` like an act.

### Dev and tests
- `bun run dev:helper` rebuilds the dev helper; a rebuild has been observed to lose its Screen Recording grant (Accessibility survives) — never rebuild or restart it during a live task.
- Logs: `/usr/bin/log show --predicate 'subsystem BEGINSWITH "com.winter.computeruse"'` (categories `bind`, `act`, `guardian`, `presentation`, `helper`; zsh's `log` is a builtin).
- The live suite (`WINTER_CU_LIVE_TESTS=1 bun run e2e:cu-live --unattended …`) takes over the screen and runs only with the user's standing go-ahead — see [testing](./testing.md). `bun run check:idle-wakeups [--pid N]` measures idle wakeups.
