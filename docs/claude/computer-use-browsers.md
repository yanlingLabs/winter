# ComputerV2 browsers

*Read this before touching `packages/core/src/computer-use/browser/`, `extensions/winter-for-chrome/`, `apple/ComputerUse/WinterBrowserHost/` or Winter.app's browser link.* Core ComputerV2: [computer-use](./computer-use.md). Winter Headless: [headless](./headless.md).

## Engine (Phase 2, `packages/core/src/computer-use/browser/`)

- Tabs are targets beside apps: `Target` (state, find, screenshot, click, setValue, type, paste, key, scroll, drag, select, hover, waitFor/waitForIdle) is shared by `App` and `Tab` (+ url, title, goto, back/forward/reload, text, upload, keep, handoff, close); `browsers` lists backends, `browsers.open(url, { browser })` (built-in `winter` by default), `browsers.tab(id | { url })` binds an open tab.
- **Backends** implement `transport.ts`'s `CdpTransport`, registered in `registry.ts`'s `BrowserBackendRegistry` (ids stable per instance key for the daemon's life: `chrome`, `chrome#2`). Built-in = Winter.app over the BROWSER LINK (`cef-link/`: a dedicated harness connection, clientName `browser-link`, harness role only, never remote, never a session event; the daemon writes `browserLink.command` notifications settled by `cmdId`; the app sends `browserLink.attach/result/events/tabGone/download`). `BROWSER_LINK_PROTOCOL` = 2 (`cef-transport.ts`; protocol 2 added `tab.present/mute/downloads/download` and `browserLink.download`), parity-tested against WinterKit's `BrowserLinkProtocol.version`. A second attach replaces the first; the link closing reads "Winter isn't running".
- **Only `cdp-allowlist.ts`'s methods/events are ever sent.** It and `transport.ts` change only through the controller.
- `engine.ts` routes `bt_<12 hex>` bindings BY MEMBERSHIP; one `TabDriver` per tab (`tab-driver.ts`): OOP iframes as flattened child sessions, `SNAPSHOTS_KEPT` 8 for diffs (grammar `state-format.ts`), refs never reused (`StaleRef` + "new page" on a new top document, also when the top-frame runtime changed with no navigation event).
- **Page runtime** `page-runtime/main.ts` → `bun run build:page-runtime` → COMMITTED `bundle.generated.ts` (`browser-units.test.ts` fails when stale); installed lazily per document per frame in isolated world `winter`, never ahead of a navigation, invisible to the page. A context is the engine's ONLY by the id its own `Page.createIsolatedWorld` answered — never by name. Safety rules in `page-runtime/rules.ts` + `redact.ts`, typechecked under their own DOM `tsconfig.json`, never core's.
- **World rules** (every transport): Runtime enabled in a frame's session before its world is made; a cross-document navigation ends the world; an ENDED world answers in Chrome's words ("Cannot find context with specified id") so the engine re-reads in a fresh one.
- **Input**: a child-frame point is brought into view by every ancestor and painted before the click; a page dialog stops the wait; a cancelled run stops typing/repeats/drags between events (a drag always releases its button). macOS editing keys carry AppKit commands (`input.ts` `MAC_COMMANDS`; Return/Tab/Escape none) because Winter.app stops a held tab's unhandled keys. **⌘/ctrl C/X/V and ⇧Insert are `Refused`**: use `paste(text)`/`text()`.
- **Dialogs** print first in `state()`; any other act is `TargetBusy`; a `beforeunload` from the model's own goto/close on its agent tab is accepted.
- **`upload()`** (`upload-paths.ts`): real non-symlink regular files in the session cwd or temp dir, never under the home or the sandbox read-deny list; `UPLOAD_MAX_FILES` 10 / `UPLOAD_MAX_BYTES` 50 MiB; the browser gets a private COPY (opened `O_NOFOLLOW`, device+inode matched) in `<home>/cache/uploads/<session>/<random>/`, removed when the session's runtime ends and at engine start.
- **Release** undoes what attach enabled (file-chooser interception, focus emulation, auto-attach, domains) BEFORE the detach.
- **Holds**: a built-in tab's hold goes at turn end (binding stays; next use re-attaches, refs new). `HOLDS_PER_SESSION` 8, `HOLDS_GLOBAL` 16 (below Winter.app's 24, whose `tab.ensure` `not_allowed` the link tags `holdCeiling` → `TargetBusy` "too many built-in browser tabs … tab.close()"); past a cap the LRU idle tab is let go with a daemon line, never one in use or locked by another run.
- **Lost vs detached**: LOST only when closed, crashed or user-detached; `stopped`/idle `Inspector.detached` keep tab, binding and agent mark, the next primitive re-attaches. A navigation across a detach (`TabDriver.navigation`: `Inspector.detached`, `tab_gone`, `cdp_error` with `data.navigated`) is re-read — re-attached within `NAVIGATION_WAIT_MS` 10 s, URL checked; `tab_gone` `{ navigated, tabKey }` REKEYS (`engine.ts` `rekey`: driver, bindings — same id — and agent mark move). A refused navigate with no detach is an error.
- **Never navigate the user's own tab**: goto/back/forward/reload on a tab Winter did not open, or handed over with `keep()`, is `NotAllowed` (use `browsers.open(url)`); in-page acts allowed; the built-in browser (hides dialogs) exempt.
- **Tab lock** `tab:<backend>:<tabKey>`, never the foreground lock; a tab-only script never launches or tells the helper.

### Policy
- Built-in: no card, ignores "Allow all apps"; `plan` observes only.
- A user's browser IS the app with its bundle id (`families.ts`): one grant covers app + tabs. `browsers.open` = full-class act then bind; listing a user's browser's tabs is checked as a bind (card; only Always-allow under dont-ask) — with no `{ browser }`, `browsers.tabs()`/`tab({ url })` read only the built-in and already-allowed browsers and say what they skipped. back/forward/reload/keep/handoff/close are click-only; `close()` refuses a `keep()`-ed tab.

### Floors (both backends)
- URLs: http(s) and `about:blank` only, `NotAllowed` before a browser sees it; bare `host[:port][/path]` → `http` for localhost/127.x/[::1], else `https`.
- Native pickers: a press/key on `<select>`, date/time/month/week/color/file inputs or their label is `Refused` naming `setValue(ref, value)` or `upload(ref, paths)`; pixel presses hit-tested through frames first. `showPicker()`/scripted `input.click()` is a stated residual. Right-click suppresses the browser's context menu unless the page shows its own.
- Dangerous-domain floor (`site-policy.ts`) on the model's URL, the bound tab's URL, where a (re)bound/opened tab LANDED (before state prints) and every committed top-frame navigation: site card once/session under ask/accept-edits/plan (a `WebFetch(domain:…)` rule counts), hard block under auto/bypass/dont-ask and Dispatch; after an unapproved navigation only `BLOCKED_TAB_PRIMITIVES` (back, close, url, title, dialog, answerDialog, waitForUser) work.
- Secure-field floor in the page runtime (password, `autocomplete` current/new-password/one-time-code/cc-*, payment-provider frames; fails closed; values and token-looking text read `<redacted>`). Credential query/fragment values (`?code=`, `#access_token=`) and token-looking runs are redacted in every URL/title the model reads; `browsers.tab({ url })` matches the redacted spelling too.

### Agent tabs
ONE rule, `lifecycle.ts`'s `shouldCloseAgentTab`: in a user's browser every unmarked agent tab closes at each main-thread turn end — `keep()` hands it over for good, `handoff()` keeps it one more turn; deletion/archiving close the rest; after a daemon restart agent tabs this run never opened close unless their session runs a turn. Built-in tabs are never auto-closed. The user's own tabs are released at turn end, never closed. A tab with an armed wake trigger (any session's) is never closed at a turn end (`waiting`); when the trigger ends mid-turn the tab gets the `handoff` mark (`engine.wakeEnded`).

### `browsers.read(url)` (`http-read.ts`)
Page text over plain HTTP, NO browser — the daemon fetches for the network-less worker; observe under every code/Dispatch policy (`plan` too).
- GET only, honest User-Agent, no cookies/credentials; ≤ `READ_MAX_HOPS` 5, each checked BEFORE it is sent: http(s), no userinfo, the dangerous-domain floor (card names "Winter's page reader").
- Address rule (`agent/tools/web.ts`'s additive helpers; `followRedirects`/`ssrfGuard` untouched for the old Browser): LOCAL only by literal host (`localhost`/`*.localhost` dialled 127.0.0.1 then ::1 without DNS, 127/8, ::1) and then loopback only; a name must resolve to public addresses only (a mixed answer refuses — never a fallback across classes); a redirect INTO loopback only from a read that started there; multicast, broadcast, NAT64/6to4/compatible private forms refused. Connect pinned to the checked address, original host as `Host`/TLS name. Never via an environment proxy: refuse while one applies; nothing process-wide changes.
- 15 s; 5 MiB off the wire AND decoded (inflated by hand, streamed); 1,048,576 chars; 8 in flight per session, 4 per host (each hop takes its host's place); identical in-flight reads shared. Type from the header before the body; undecodable charset = error, never mojibake; status ≥ 400 returned, not thrown; `needsJs` hints a tab. Marked page data before anything response-shaped prints or throws; URLs redacted like a tab's; no daemon sentence repeats a page-chosen address. Metrics carry `backend: "http"`, `httpStatus`, `bytes` — never the URL.
- The service routes every `BROWSER_PRIMITIVES` member (`worker/bridge.ts`) to the engine; an answer too big for one bridge line is a typed error at both ends, never a dropped line.

## Wake triggers on tabs (`browser/wake/backend.ts`, `page-runtime/watch.ts`)

*The registry, the endings and the wake itself: [computer-use.md](./computer-use.md#wake-triggers-computer-usewakes).*

- `new BrowserWakeBackend(engine)` is the registry's `tab` backend (`wiring.ts`; its `stop()` runs before the engine's).
- **One watcher**, `wakeWatcher` (`page-runtime/watch.ts`), STANDS ALONE: Chrome serializes it for `executeScript`, so nothing outside its body and nothing the extension's bundle scan forbids, comments included. The page runtime runs it in the frame's winter world (`watchLocate` → role, name, the secure-field floor and a LOCATOR; `watchArm`, `watchWait`, `watchDisarm`). Winter for Chrome ≥ 1.2.0 injects the same function into ITS OWN isolated world (feature `watch`).
- It reports only the kind, `at`, the top document's ORIGIN AND PATH ("?…"/"#…" where a query or fragment was, `watchUrlShape`: a GET form's typed values never leave) and a title watch's title. A `navigated` detail is origin + path (redacted; `{ url }` adds "matched “…”").
- Input conditions take trusted DOM events. `clicked` counts on its `click` (a press dragged off the element is none). `submitted`/`changed` also need a trusted pointer or key event of the user's on the submitter, in the form or in the field within `WATCH_CAUSE_MS` (1 s) before; it is reported as `cause` and held to Winter's own input too. User activation is NOT the test: Winter's CDP input grants it. Enter counts only where it submits implicitly. State conditions report a false→true transition (the text re-read at most every 2 s while the DOM churns).
- Visible: one `<winter-wake-overlay>` (closed shadow root, no pointer events; the page runtime's SKIP and `isOverlay` leave it out) with the ring and the fixed pill (`wakePill`). Watchers of one page in several worlds share one pill list (`data-pills`); a watch armed again retires its old world's copy (`data-retire`).
- **Debugger-free path** (Winter for Chrome ≥ 1.2.0; page conditions and top-frame elements): the tab is let go at once, and the watcher is injected again per document on `tabs.onUpdated` "complete" (`"baseline"` after the extension's own input or navigation, else `"fire"`). An element watch is never silent: a load that never completes is looked at after 10 s, a page that takes no script loses it, a watcher silent for 65 s is injected again. A `navigated` watch sees only the address shape, a digest (`watchUrlKey`) and its own match of the model's words. The extension stamps `own` within 500 ms of its own `Input.*`/navigation, moves a replaced tab's watches (`moveTab`) and drops every watcher when the link drops (`extensions/winter-for-chrome/src/watches.ts`).
- **Debugger path** (the built-in browser; an older extension, where `WakeArmed.note` says to update it; an element in a child frame): `TabDriver.wakeWait` long-polls (≤ 20 s rounds, acknowledged per world, polling around a page dialog — never answering or dismissing it) and holds the tab as `wake:<id>` WATCH-ONLY. While only wake holders remain there is no file-chooser interception, focus emulation, emulated screen size or agent overlay, and the built-in browser's hold is `tab.ensure {watchOnly: true}` (link feature `watchOnly`, `BROWSER_LINK_FEATURES` ↔ WinterKit's `BrowserLinkProtocol.features`; link protocol still 2). A Winter.app without the feature never holds a built-in tab for a wake (`NotAllowed`, "update Winter"). A primitive takes the full hold back; its turn end drops it back.
- **Dialogs**: letting go never dismisses one the user raised (`keepsDialogHeld`). One that opens outside Winter's input while a wait holds the tab keeps the full hold and ends each wait on the tab `lost`, naming it (`wakeDialogReason`), so the session can read and answer it; the tab is let go once it closes or after `WAKE_DIALOG_HOLD_MAX_MS` (10 min).
- Waiting tabs' holds count against the session's 8 and the 16 in all: past them, arming is `TargetBusy` naming `wakes.cancel(id)`.
- A trigger keeps the tab's DRIVER, never the binding: a reset, a worker restart, the idle end and turn ends leave it armed. It ends on a cancel; the tab closing or crashing (a rekey keeps it); a ref condition's document going (`lost` "the page changed", or `fired` when the user's own press of that element or form came ≤ 3 s before the navigation STARTED); the link dropping ("Winter for Chrome disconnected" / "Winter isn't running").
- **Winter's own input**: every `Input.*` and `Page.navigate`/`reload`/`navigateToHistoryEntry` a driver sends (`TabDriver.ownInputAt`) plus each act primitive the engine marks, from any session, + 500 ms; the extension's own stamp; the helper's input to the browser app (`BrowserEngineDeps.ownAppInputAt` → `service.ownAppInputAt`). `own()` asks all three for every judgement; a navigation's owner is decided at the top frame's `Page.frameStartedLoading`. What lands inside never fires, and a state transition there becomes the baseline.
- **No scope at arm** (no run, so no card): a headless tab is `NotAllowed`; a secure field `Refused`; a dangerous-domains host `NotAllowed` unless approved for the SESSION (a one-run approval does not count) or a saved `WebFetch(domain:…)` rule allows it, and a page condition never fires on such a page; a user's browser needs `persistentlyAllowed`; a condition already true is `NotAllowed`. `engine.hostOf` gives the audit host.
- Residual: a page's own first-registered window capture listener that stops propagation starves the watcher.
- Tests: `test/computer-use/browser-wake.test.ts` and `browser-wake-watcher.test.ts` (fakes in `browser-wake-fake.ts`), `extensions/winter-for-chrome/test/watches.test.ts`, `test/computer-use/extension/extension-transport.test.ts`; both e2e runners run the REAL watcher (`wake.html`; the USER acts over the test's own CDP session, `PipeTransport.asUser`).

## Winter for Chrome
The engine's way into the user's OWN Chromium browsers. Contract: `apple/ComputerUse/WinterBrowserHost/PROTOCOL.md`.
- **Extension** `extensions/winter-for-chrome` (MV3; `EXTENSION_VERSION` 1.2.0, `EXTENSION_PROTOCOL` 1; `edge` flavor = "Winter for Edge", `src/manifest.ts`'s `PRODUCT_NAMES`).

Reads its home from its ENCLOSING helper's bundle id, verifies the daemon by audit token (`LOCAL_PEERTOKEN` → `SecCodeCheckValidity`; dist `winter-core` / dev `com.winter.core.dev` + team) before writing a byte, says `host.hello`, then only relays (native messaging ⇄ NDJSON; 16 MiB in, 1 MiB out; retries 2 s doubling to 60 s while Winter is down, 30 s after a refusal).
- **`<home>/run/browser.sock`** (0600; `browser/extension/host-server.ts`, at boot — a socket that cannot be created never fails boot). `host.hello` checks in order: protocol → origin in the profile's allowlist (`extension-ids.ts`: dist = Chrome Web Store `flfkppajaamjgfmdljlklfdffkdcmicc` + Edge Add-ons `bapmmpefcbjabfdfeehimdhldpjaoemd`; dev `jikdcokcpbacalfeipkognejnlnobbbf`) → known Chromium family by bundle id (Chrome for Testing = Chrome) → the host's code BY ITS REPORTED PID (the host's check of the daemon is the load-bearing direction) → `computerUse.enabled`. Then one `ExtensionTransport` per `instanceId` in `computerUseRuntime.backends` (same id across reconnects). An idle/`target_closed` detach reaches the engine as `Inspector.detached`, never a lost tab.

The EXTENSION enforces the allowlist and world rules (`guard.ts` bundles `cdp-allowlist.ts` from source): every cap STATED (`Network.enable` without `maxPostDataSize: 0` + both buffer caps, or `IO.read` without `size`, refused — Winter.app's `CDPTabGate` likewise); a context is winter only when its own `createIsolatedWorld` returned it; no reload script, no non-web navigation. It:
- opens tabs only `active: false` in the session's "Winter · <title>" group and never activates a tab or focuses a window except `tabs.present` (the sign-in hand-off, after the user's OK on Winter's card); the three allowed `chrome.tabs.update`/`chrome.windows.update` spellings are pinned by `scripts/build.ts`'s `ALLOWED_EXACT_CALLS`;
- attaches `chrome.debugger` only while a tab is bound (`IDLE_DETACH_MS` 5 min; all detached when the link drops or a worker restarts);
- draws an indicator-only overlay (no pointer events) under a closed shadow root; Stop is the toolbar button while driving, but while Winter waits on a handed-over tab the button stays the popup (Done first, Stop inside) so a click never stops another task;
- closes/keeps (ungroups) only agent tabs, only when the engine says. A close DISCARDS the tab first (a beforeunload prompt brings a tab forward; a discard does not), accepting the prompt over the debugger only for the active tab. Same for a top-level `Page.navigate`/`reload`/`navigateToHistoryEntry` of a background agent tab with any `Input.*` or user visit since load: discard, then the engine's command on the SAME debugger session; a browser that ended the session or replaced the tab answers `cdp_error`/`tab_gone` with `data.navigated` (§5.3);
- tracks agent tabs by id in `chrome.storage.local` (a browser start clears them).

**Features/permissions.** Since 1.1.0 the extension names its additions in `hello.features` (12 at 1.2.0, `cdp3` and `watch` among them; see the daemon's `EXTENSION_FEATURES`, `extension/protocol.ts`, parity-tested to it); a member is offered only when its feature is named — one needing more answers "update Winter for Chrome"; without `cdp3` (1.0.0) only Phase 2's events are subscribed. `browsers.list()` names a family by its channel and counts only a REAL install (`families.ts`'s `isRealInstallPath`: not Trash, cache, translocated or temp). Optional permissions `history`/`bookmarks`/`downloads` are toggled in the popup on the user's click, never at install; a request needing an ungranted one is `not_allowed` + `data.permission` (`library.ts`).

**Manifests.** Release Winter.app writes `com.winter.browser.json` at every launch from its own bundle path (`apple/Winter/Sources/BrowserExtension/BrowserHostManifest.swift`); `bun run dev:helper` writes `com.winter.browser.dev.json` into existing browsers' `NativeMessagingHosts/` (`--out <dir>` writes nothing; never point a test at the real directories).

## Phase 3: readers, downloads, the sign-in hand-off

### Developer and element readers
- `console()` (console calls, uncaught exceptions, `Log` entries) and `network()` (URL, method, type, status, MIME, timing, size): 1,000 entries a tab (`packages/core/src/computer-use/browser/devtools.ts`). `networkBody(id)` reads one response through `Network.getResponseBody` on request — the browser keeps ≤ 1 MiB a response / 8 MiB a tab, never a request body — 64 KiB by default, ≤ 256 KiB, secrets redacted (`body-redact.ts`); a binary body is not returned (it points at `download({ url })`).
- Element readers in the page runtime: `inspect(ref | Point)`, `html({ within, maxChars })` (scripts, field values and secrets left out; every URL-valued attribute redacted, `redact.ts`'s `redactUrlAttribute` — in `inspect()` too), `text({ within })`, `assets({ kinds })`, `find`'s `label`/`placeholder`/`testId`/`css`/`exact` keys (tabs only), `screenshot({ within | fullPage })` (full page ≤ 10,000 CSS px — `FULL_PAGE_MAX_CSS`, for looking only, a Point in it refused; on the USER's own tab a picture never moves the page: `fullPage` refused, `within` only for an element wholly in view), `setValue(ref, true | false)` (pressed only when it differs), `waitFor({ load })`, `dialog()` / `answerDialog(accept, text?)`.
- Every reader prints FENCED. **Redaction is display hygiene, NOT a security boundary**: a `download()`'s bytes are saved exactly as sent.
- **Everything leaving a browser is reduced first**: `cdp-reduce.ts` keeps only `cdp-allowlist.ts`'s `CDP_EVENT_PARAMS` paths (never headers, cookies, post data, initiators, page objects; strings cut at 4,096, arrays at 32; `Fetch.requestPaused` headers only content-type/-disposition/-length). Applied by EVERY transport: the extension's guard, Winter.app's link (`CDPEventReducer`, WinterKit — `packages/core/test/computer-use/fixtures/cdp-reduce-cases.json` holds the two equal), the daemon's transports, the e2e pipe.

### Tab facts and the user's library
- Only a tab Winter opened and still owns takes `viewport({ width, height, mobile, scale })` (width 200–3840, height 200–2160, scale 1–3; put back when the tab is taken again, cleared by `keep()`) and `mute()`. `keep({ group })` hands it into a user group; `browsers.group({ title, color, collapsed })` names/colors/folds the session's Winter group (never folded while the user has one of its tabs in front); `browsers.windows()`; tab rows carry `lastUsed` and `group`; `browsers.tab({ active: true })` binds the user's front tab.
- `browsers.history({ query, from, to, limit })` / `browsers.bookmarks({ query, limit })`: READ ONLY, 25 by default ≤ 200, history 90 days back; checked as a BIND of the browser and `NotAllowed` until the extension's optional permission is on. The built-in browser has neither.

### `download(ref | { url }, { to, timeoutMs })`
- Saves into the session temp folder's `downloads/` (`to`: in the working directory, or absolute in either root); returns `{ path, name, bytes, mime }`. A `data:` link is decoded by the daemon. Built-in browser: Winter.app's CEF handler (link protocol 2 — `tab.downloads` arms one download into the staging folder, `tab.download` for a URL, the click otherwise). A user's browser: an http(s) link loads in a TEMPORARY background tab under CDP `Fetch` interception (the bound tab is never navigated), a button arms the bound tab and clicks — the first ATTACHMENT (any frame) or the tab's own TOP-LEVEL document of a stated non-HTML type (a frame's document is the page's; an untyped one is left to the browser; the temporary tab's top document whatever its type) is read via `Fetch.takeResponseBodyAsStream`/`IO.read` then failed `Aborted` (the browser saves and shows nothing); the arm (`Fetch.disable` everywhere it was put) always comes off.
- **The dangerous-domain floor holds EVERY address a file came through**: each redirect hop of the top-level document as it is paused (a frame's redirects are the page's; only a frame attachment's final address is checked), the file's own address before a byte is read (the request and the clock wait while a site card is up), and a browser's own download's final address (`TransportDownload.url`) before placing — refused: staged copy and browser-folder file removed.
- A page-made `blob:` file is caught only by the backend's handler: Winter for Chrome's optional `downloads` permission (saved to `<Downloads>/Winter/<random>/`, MOVED by the daemon, subfolder removed; a "save as" elsewhere is COPIED and left), else the wait says to allow downloads. A download the arm stops waiting for while it still runs is cancelled, erased from the browser's list, and the daemon told why.
- Staging: `<home>/cache/downloads/<session>/<random>/`, placed by `download-paths.ts` under `packages/core/src/agent/stage-image.ts`'s discipline (never through a link, never over a file — `name (2).ext`; hidden segments, settings file names, the deny-write list and the home refused; bytes copied into the O_EXCL|O_NOFOLLOW descriptor proved to be the walked path; `com.apple.quarantine` set). Limits: 200 MiB a file, 20 per script, 60 s to start, 10 min in all. An unarmed download is reported in the next state header.

### `waitForUser(reason, { timeoutMs })` — the sign-in hand-off
- Card 1 ("<Browser> — <host>: <reason>. Winter waits while you do it.", options `handoff_show` "Show me the tab" / `handoff_done` "I've done it"; Mac buttons "Show me the tab" / "Not now") under every policy but `dont-ask` (refused naming the host), Dispatch coordinators included. `TargetBusy` while a page dialog holds the tab (`answerDialog()` first). On a headless tab: one card with "Show me the tab" only, and the tab is shown in Winter's panel with the person in control ([headless.md](./headless.md#showing-a-headless-tab-lane-h3)).
- The tab is let go BEFORE the card: a full detach by every session holding it (`TabDriver.handOff`), the built-in hold dropped (so passkeys/permission prompts can show); what the page logs meanwhile stays out of `console()` (`TabDevtools.hideWindow`). "Show": built-in via link op `tab.present` (Winter activates, panel tab shown), a user's browser via `tabs.present` — the extension's ONLY activation. Then card 2 ("Waiting for you on <host> in <Browser> — press Done when you have finished.", `handoff_done` "Done" / "Stop waiting"), also answerable from the extension popup (`user.done`). Done → tab taken again, full state printed, `{ done: true }`; declined/stop/no answer → `{ done: false }`, tab left with the user; tab closed → `TargetLost`. 5 min default, ≤ 30; the script clock is paused.
- Policy classes (`engine.ts`'s `OBSERVE_PRIMITIVES`, `policy.ts`'s `ACT_PRIMITIVES`/`CLICK_ONLY_PRIMITIVES`): readers and `waitForUser` observe; `answerDialog`/`viewport`/`mute`/`browsers.group`/`keep` click; `download` full. Audit counts `downloads`/`handoffs`; the metric carries a download's size only.

## WebMCP: a site's own tools

- A page's `document.modelContext` tools are read and called from the `winter` world inside the already-allowed `Runtime.callFunctionOn` (`page-runtime/webmcp.ts`) — nothing added to the CDP allowlist. Winter.app's CEF runs `--enable-features=WebMCP` (`apple/Winter/Sources/CEF/WinterCEF.mm`, fixed at launch); the hot `computerUse.webmcp` (default on, `settings.ts`'s `computerUseWebMcpFrom`, read per primitive) gates only whether the daemon reads or calls them.
- Discovery FAILS CLOSED (no/throwing/misshapen API, a listing over 2 s, a tool not shaped as the draft → no site tools) and keeps only the top frame's own window and origin. The page's words are untrusted: one-lined, redacted, cut (`SITE_TOOL_CAPS`: 500-char descriptions, 2,000-char schema JSON, 50 described / 32 KiB, 200 names), printed only FENCED, never in telemetry, a daemon line or the tool description.
- A whole-tab `state()` names them on one line after the dialog line (`site tools (WebMCP): …`, 20 names then "… and N more"; diff only on change, "none now" when gone — `state-format.ts`'s `siteToolsLine`). `tab.tools()` describes them.
- `tab.callTool(name, input, { timeoutMs })` is an ACT (`ACT_PRIMITIVES`; `access: "full"` on a user's browser — plan, click-only and view-only refuse it; the site floor applies; NO card of its own — the description tells the model to confirm one that buys, sends, deletes or publishes). It re-reads the current document's tools (an earlier page's name refused), sends the input (≤ 64 KiB) as a JSON string first and as the object only after a `TypeError` (thrown before the tool runs; a tool's own `UnknownError` is never retried), aborts the page's signal at the timeout (30 s default, ≤ 5 min, clamped to the run) or a cancel and waits 2 s more (`SITE_TOOL_STOP_GRACE_MS`), reads a call its page navigated away from as "navigated" (daemon line, `null`, every ref stale), and returns the answer (≤ 256 KiB) redacted like a response body, parsed when JSON, printed fenced; a failure's words are fenced and the error only says it failed. Audit counts `siteTools`; the metric carries backend and time only.
