# Providers and credentials

*Read this before touching a Keychain slot, a credential door, the host-credential broker, the boot Keychain passes or Anthropic sign-in.*

## Inventory (`packages/core/src/runtime-sdk/keychain.ts`)

- `credentialInventory()` is DERIVED from the pinned catalog: every provider with `api-key` in `authKinds`, `risk.class` not `blocked`, no `requiresUserEndpoint` gets slot `<providerId>:default`. Four pinned rows first — `openai`, `codex-oauth`, `anthropic` (`anthropic:default`), `console` (`anthropic:console`); the order never selects a provider (it orders `credential.list` rows; the head is pinned by `keychain.test.ts`).
- One slot per provider. `ANTHROPIC_ACCOUNT_REQUIRED_KIND` (api-key in `anthropic:default`, bearer in `anthropic:console`) narrows `credentialPresenceFrom` and `credential.list` alike.
- A model is a provider-qualified tag; `providerFor(tag)` (`runtime-sdk/provider-selection.ts`) names its credential via `credentialRefFor`. Nothing picks a provider for a bare id.
- No daemon endpoint table, ever: the catalog ships endpoints; `providerBaseUrlFor` (`settings.ts`, `settings.providers.<id>.baseUrl`) is the only override, hot. `migrateSettingsV2ToV3` copies the legacy `provider.baseUrl` into `providers.openai.baseUrl` once.
- No key for the decided provider → `runtime_selection_refused`, `data.reason: "no-credential"` at the first turn (`runtime-sdk/session-driver.ts`), never a mid-turn 401.

## Locators on the wire, material over the control channel (`packages/core/src/runtime-sdk/host-credentials.ts`)

- Every `authRef` (`Options.provider`, `advisor`, `web.search`, `web.fetch`) is a `{kind:"keychain", account, service}` locator, never material.
- A child or embedded Worker asks `credential_resolve {ref, minGeneration?}`; the daemon answers ONLY the refs its final `Options` named, the slots of permitted AND credentialed providers, and `mcp-oauth:<id>` for http/sse servers in the session's MCP fold. Else `not_allowed`; `isNeverBrokered` refuses pairing tokens (+ shadows), `mcp-oauth-client*` items and the retired Brave key first.
- No refresh token crosses (MCP records via `toSessionMcpTokenRecord`); every refresh is the daemon's, single-flight per item. `generation` is a derived digest counter per item (API keys too); a 401'd child asks with `minGeneration` (unmet → `stale`). Material rides only in the one `control_response` frame — never argv, env, `Options`, `runtime-state.db`, the session JSONL, the remote stream or a log.
- `winter-core` (daemon + CLI, one binary) is the only Winter process reading or writing an item: that bounds the agent (sandboxed `Bash` cannot reach `securityd`), not same-user processes.
- Eviction stays: a write through the daemon replaces every live child whose record or cross-provider advisor pin names the provider, mid-turn ones at the next idle boundary (`evictSessionsForCredential`, `runtime-sdk/credentials.ts`) — `Options` carry PRESENCE-derived facts (Exa surface, pins) and a removal must stop a child holding old material. MCP sign-ins reconnect instead ([mcp](./mcp.md)).

## Doors

- RPCs `credential.list|set|remove`; CLI `winter credentials [list] | set <id> | remove <id>` — masked TTY prompt only, never a flag, pipe or env var; `winter login --api-key|--anthropic-key|--exa-key|--anthropic-console`; `winter logout --openai|--anthropic|--anthropic-console` (bare: Codex). Key doors go through the daemon when the socket is live, else the CLI stores in-process and says so (picked up at the next incarnation). The in-process-only doors (Codex `login`/bare `logout`, the Console sign-in/out) poke a live daemon through `credential.list` so its view reconciles ([internal-jobs](./internal-jobs.md)).
- `credential_kind_unsupported` + `door`: `codex-oauth` set (`cli-oauth`), `console` set/remove (`provider.login`), `web-search` set.
- `TOOL_ROWS` (`packages/core/src/runtime-sdk/credentials.ts`, raw values under long-standing names): `exa` evicts EVERY live child (`Options.web.search.authRef` names it AND it decides the tool surface — `exaKeyPresent`); `web-search` (Brave) is retired: nothing reads it, listed only when stored and only removable (`manageable: false`), `--web-search-key` prints a deprecation.

## Keychain ACLs at boot (`packages/core/src/daemon.ts`)

- Only on the profile's default home, no injected `secrets`, keychain unlocked, user interaction disabled. Only an item's CREATOR can re-create its ACL (delete + re-add): shadow `<name>.migrating` → delete → add with the new ACL → read back → drop shadow → marker. A failure after the delete restores the value at once; a shadow outliving its original is restored BEFORE `ensureTokens` (it would mint and unpair).
- Pairing tokens `harness-token`/`remote-token` (`auth/app-token-acl.ts` over `auth/keychain-ffi.ts`), the only items another binary reads: ACL = this process + the app by designated requirement; marker `<home>/migration/app-token-acl.json`, re-run when the trusted set changes or a token was minted. Trusted — dist: the app bundle `winter-core` runs from, nothing else (never a local Release build); dev: this process + `com.winter.app.dev` bundles signed by Winter's team, within a 5 s budget (`TRUST_SCAN_BUDGET_MS`, uninspected = untrusted). A differing shadow/original pair is kept.
- Every other item (`auth/credential-acl.ts`: provider slots, tool keys, MCP sign-ins, admin token): ACL names this process alone. Accounts listed attributes-only (`listGenericPasswordAccounts`), app tokens and shadows excluded, non-UTF-8 or unreadable items skipped and counted, the original re-read just before the delete (vanished → nothing put back). Marker `<home>/migration/credential-acl.json` keyed on service + designated requirement (never a path), not written when nothing migrated; unreadable requirement → recovery only. A credential's shadow beside its original is stale and dropped; every delete door (`KeychainSecretStore.delete`, the MCP OAuth store) deletes `<name>.migrating` too.
- Lock (`auth/credential-migration-lock.ts`, `<home>/run/credential-migration.lock`): every shadow pass and migration, the dev transition included, runs under it — never the boot lock (a booting daemon has no socket). Atomic; pid + start time in epoch seconds (sysctl, `ps` under `LC_ALL=C TZ=UTC` fallback, never a formatted date); stale = dead/reused pid or our pid not taken; unreadable and < 5 s old = held.
- Order (`auth/keychain-boot.ts`): `beginKeychainPass` waits ≤ 60 s, then refuses typed `credential_migration_busy` → `winter daemon run` exit 75; restore-only recovery before `credentialPresenceFrom`; after the boot lock and Migration B: full recovery + migration (restore pass if it failed) → token recovery → `ensureTokens` → `migrateAppTokenAcl` → release. The Mac `DaemonSupervisor` treats exit 75 as waiting (respawn after 5 s doubling to 60 s), never a crash.

## Anthropic

- The tag prefix is the arm: `anthropic/*` API key, `console/*` Console profile, `cc/*` reserved. No claude.ai subscription auth: `claude-oauth` never routes; a legacy record holding it is refused at resume ([runtime-and-sessions](./runtime-and-sessions.md)).
- Console: one login door, `winter login --anthropic-console` → the SDK broker (`packages/core/src/auth/console-profile-broker.ts`) runs `ant auth login --profile winter` on `<home>/runtimes/anthropic-config`, profile `…/credentials/winter.json` (`consoleProfileCredentialFile`, `runtime-sdk/anthropic-paths.ts`); `ant` is also the refresh and logout door. The minted bearer lives in `anthropic:console`, which `credentialRefFor("console")` names to children and Winter's jobs. READINESS IS THE SLOT, not the file: `credentialPresentProbe` drives router admission, `sync.config` models and `models.catalog`'s `credentialPresent` (`credentialDoor: "console-profile"` — a sign-in, never a pasted key); the broker's watcher deletes the slot when the profile disappears. A signed-out Console session refuses `no-credential` naming the login. `provider.login`/`logout` evict `console` children and re-probe the internal-jobs view; `provider.status` reports presence only.
- The retired `runtimes.*` keys (`claudeExecutable`, `official.*`, `handoff.crossRuntime`) still parse and are ignored: [settings-and-migrations](./settings-and-migrations.md).
