# Cowork

*Read this before touching `packages/core/src/cowork/**`, `packages/protocol/src/cowork.ts`, `apple/Cowork/**`, the host-storage fence or `home-fence`'s Cowork roots, `refreshForStorage`, or the `workspace.*` / `project.*` methods and events.*

Cowork is not an implemented session mode: no Cowork session can be created or run, and `SpawnSession` refuses `type: "cowork"`. The protocol RECOGNISES the name (`SESSION_MODES`) so every door can refuse it typed: `session.create {mode: "cowork"}` answers `unsupported_topology` for every role, and a stored cowork row is refused rather than read as Code (see [runtime-and-sessions.md](./runtime-and-sessions.md)); there is deliberately no Cowork prompt, tool allowlist or run home. The host side exists: workspace metadata, guidance, schedules, outputs, the session-door records and (inert) the native worker, libkrun and guest-image source ([below](#native-guest-stack-on-the-integration-branch-source-only-never-booted)). What exists and what still blocks a functional mode: [cowork-status.md](../cowork-status.md). The design: [cowork-spec.md](../cowork-spec.md).

## Native guest stack on the integration branch (source only, never booted)

`cowork/output-integration` now holds the whole native source stack, and none of it runs: the activation seam (`cowork/native-activation.ts`, `COWORK_NATIVE_ENVIRONMENT_ACTIVATED = false`) answers `undefined`, the host-env graph loads lazily behind it (`test/cowork/host-env-lazy.test.ts`), and no VM, Hypervisor.framework call or app launch has ever been made from it. Wire contract and revision history: [cowork-native-worker.md](../cowork-native-worker.md) (revision 3 added host-backed shares, cold resume and the guest file channel). There is no NIC and no vsock anywhere in it.

- **libkrun stack (SH2).** `apple/Cowork/WinterCoworkLibkrun` is a pinned patch queue (0004-0026) over upstream libkrun v1.19.6 with a reproducible build of one stripped archive that the worker links. Patches 0024-0026 are SH2: the confined virtio-fs server core, its git rules and quarantine, and the guarded fs device with the shares ABI gate. Nothing in the repository imports the directory (a test pins that); its README holds the pins and the rebuild steps. A release ships the worker only with the archive inputs ([release.md](./release.md#the-cowork-native-pair-is-an-explicit-choice)).
- **Host-backed shares over virtio-fs (SH6, guest side).** PID 1 (`apple/Cowork/WinterCoworkGuest/init/shares.c`) reads the virtio-fs tag inventory (it must equal the declared tags), mounts each share with `nosuid,nodev` and `dax=never` on a checked mount point's descriptor, then verifies every mount in `/proc/self/mountinfo`; any failure unmounts what it mounted. Three Winter shares are fixed: guidance at `/run/winter/shared-instructions` (read-only; PID 1 also links `/workspace/.winter/WINTER.md` to it), memory at `/workspace/.winter/memory` and outputs at `/workspace/outputs`, all `noexec`. A connected Mac folder is a guest share at `/workspace/folders/<name>` (mode 0700 mount point, `exec` kept because builds run there, read-only when the share is). Guest ownership and modes on a share are no boundary: the host serves shares under simplified ownership.
- **Plan view.** For a conversation under policy `plan`, PID 1 makes `/workspace/plan/<sid>/<epoch>` (contract 12.5) for its own conversation only: owned by the conversation's tool uid alone (0700, never the workspace group), parents never symlinks, refused when a later epoch already exists. The guest supervisor admits it writable only under `plan` and never below an epoch already made; the tool launcher mounts it writable for the file worker only.
- **Environment image `/etc/gitconfig`.** The image carries a fixed system gitconfig (`scripts/cowork-guest-artifact/environment/gitconfig`, hash pinned in `pins.json`): an empty git template directory, `core.hooksPath=/dev/null`, no fsmonitor, no credential helper, no include, `protocol.ext.allow=never`. The tool launcher mounts it read-only at `/etc/gitconfig` for the process worker; `verify.py` accepts exactly those settings and refuses a stray `/etc/gitconfig`.
- **Memory root.** The memory share (`/workspace/.winter/memory`) is a host-query tool root of the guest runtime (agent SDK SH6b); the host side is the `memory` role in `WinterCoworkVM`'s `SharePolicy`.
- **Cold resume.** Host half: `cowork/cold-resume.ts` maps the recorded `store_state` (`none`, `started`, `created`, `lost`) to a continuation (`fresh`, `either`, `resume`, refuse) and the proven-ended boots of the last incarnation (runtime-state schema v21). Guest half: the session-owner patch (agent SDK #50) is in the pinned SDK commit. The host port stays GATED OFF: no production composition supplies `CoworkSessionDriverDeps.coldResume`, so a conversation with a recorded backend still refuses `cold_resume_unavailable`. Supplying it is the owner's flip.
- **Reproducible pinned guest image** (`scripts/cowork-guest-artifact/`). `pins.json` pins the agent SDK commit `ec91fe06` (plan view, shares, environment gitconfig, cold-resume owner), the expected runtime/cpio/root-manifest digests and the helper, init and relay binary digests, as produced by build 5 (two identical builds, both receipts compared). `kernel/pins.json` pins the Linux 6.18.35 `Image` and `vmlinux`, which two builds under different work paths reproduced byte for byte (status `built-reproduced-unbooted`). The runtime image digest is SHA-256 of the raw kernel-`Image` digest followed by the raw cpio digest (`runtime_image_digest.py`; the worker and launcher recompute it): `runtimeImageDigest` `da1795da4155dca3d40efda00aab2eab87fe6a7c3cc6175078396cff5a86ca65`. A build whose digests differ from the pins stops with exit 3 UNPINNED (the one-run workflow still uploads the image, receipts and `digests.json`, then fails its assert step). The one-run workflow's trigger is now `cowork/guest-image-build-6` (build 5's branch is spent); build 6's result is not recorded in the pins yet.

## Ordinary host execution policy

Accepted 2026-10-12.

- Ordinary native Code, approved shell escapes, plugin hooks, LSP and third-party MCP tools get NO persistent outer Cowork Seatbelt profile. Each tool's own sandbox stays unchanged; never inject sandbox/GPU/Chromium/LSP compatibility overrides.
- Sandboxed Bash gets the protected Cowork, runtime, control and socket roots in the existing `sandboxConfigFor` denyRead/denyWrite arrays, rendered as ONE profile.
- Approved escapes keep main's behavior and no Seatbelt. Cowork escape matching is write-shaped integrity guidance, not confidentiality.
- Core/SDK file tools keep their canonical protected-path checks.
- Actual floors apply only to explicitly Winter-owned Cowork workers and bridges.
- Ordinary child execution history never requires a daemon restart before first activation.

## Storage scope (first version)

Separate per-workspace encryption is DEFERRED (user ruling, 2026-10-12). The contract and its gates: [cowork-storage-security.md](../cowork-storage-security.md).

- Private VM/disk images are plaintext, with owner-only permissions, verified file identity and backup exclusion.
- FileVault protects offline host-volume access when enabled. Same-user processes, approved escaped commands (which run as the user) and authenticated API access can read images; these are explicit residuals.
- Still required: VM isolation, selected-folder boundaries, host credential custody and active RAM return. Key-broker/LUKS work is preserved as deferred research, not an activation gate.

## `refreshForStorage`

The installed SDK has no live sandbox-settings control, so `refreshForStorage` awaits the daemon's policy consumers:

- **Code** holds queued work, lets its current turn finish, then recreates its logical incarnation/run home with the same session/backend identity and the current sandbox paths; held work resumes there.
- **Chat/Dispatch** Workers, with the accepted SDK v1 nine-family context contract, acknowledge live protected-path updates without aborting their turn or recreating the runtime; a cold protected start waits for its own matching acknowledgment. Namespace, version and family checks stay required.
- The unchanged installed SDK pin lacks that contract: its existing Workers must close before activation and its protected Chat/Dispatch launches stay refused.
- A pending or failed refresh blocks provisioning, without claiming third-party descendants were stopped.

Historical persistent-Code-floor reports describe the superseded approach.

## Storage lifecycle (records and guards only)

None of this makes Cowork runnable; there is still no creation door. Sentences followed are quoted in the code and tests.

- **Backup exclusion** is the raw-volume primitive's (`cowork/volumes.ts`, `volume-backup.ts`): a sticky `tmutil addexclusion` (never `-p`) on each image when it is created, re-verified on every claim and open; shared instructions, memory and outputs get none. `test/cowork/volume-backup-adapter.test.ts` pins the real adapter on disposable files.
- **Image pins and export generations** (`cowork/images.ts`, `cowork/exports.ts`, `cowork/storage-lifecycle.ts`, runtime-state schema 16): trusted-controller classes with a mandatory authority port, no RPC. A pin records the base and runtime image digests and walks an update through `beginUpdate` then `confirmUpdate` or `abandonUpdate`, only while stopped and unowned, with a mandatory compatibility port; the live digests do not change until confirmed. An export generation is a recorded, manifest-bound descriptor of a stopped, ready, pinned workspace. `validateImport` judges a presented descriptor against canonical records and grants nothing. Content-out (PR #97) added the byte-copying `.winterworkspace` writer (`export-writer.ts`, `export-bundle.ts`, with a two-pass shared snapshot) and an in-place restore of a stopped workspace's two images from a verified generation (`restore-bundle.ts`), all behind ports: no RPC reaches them and no production composition runs them.
- **Migration B** never copies Cowork storage (`migration/cowork-exclusion.ts`): `cowork/**` is skipped, and a source holding any Cowork tree or populated Cowork table refuses with `cowork_storage_present` (the daemon's boot hook logs one skip line instead). Only the coordinated, quiescent migration the contracts describe could move it, and that does not exist yet.
- **Migration C** never names Cowork storage: its moves are the fixed `SDK_COMPAT_LINKS`, `hostRuntimePredicate` keeps guest sessions out of runtime-state rewrites, a workspace that is not `stopped` or a volume that records an owner refuses it, and a manifest naming a `cowork/` path refuses resume, phase 2 and rollback. A rollback with populated Cowork records is refused by the schema step.
- **Retention**: deleting a standalone workspace's only conversation tombstones its binding and, when the workspace is retained and stopped, archives it in the same transaction ("Detach/archive its workspace for explicit later deletion/export"): wake and disk admission refuse until an explicit restore, and both volumes and every shared file stay untouched. A Project workspace is unaffected, and a workspace that is not stopped stays retained. That transition lives in `abandonConversation`, and every route that retires a session reaches it: through `createCoworkSessionDeletionHook` (the boot reaper in `daemon.ts`, the mint-time reaper in `ipc/server.ts`, the cleaner's `onDelete`, the `session.create` refusal rollbacks, and the dispatch-children spawn-failure rollback) and directly from the missing-session branch of `CoworkWorkspaceEvents.drain`. None of them removes a volume or a shared file; they delete a session, tombstone its binding, and archive a stopped standalone workspace. **Owner decision 2026-10-16: keep archive-on-any-deletion, no behavior change.** The owner treats a workspace's own state (memory dir, temp dir, scratch, the VM disks) as temporary. It is removed only by the explicit, confirmed workspace delete (not built yet); the reapers, the cleaner and retention archive without removing anything, consistent with `cowork-spec.md` ("Scratch and outputs survive ordinary stop/archive"). Connected Mac folders and GitHub repositories are not part of the workspace and are never cleared. Archive is a state flip that deletes nothing, so automatic archive from every trigger above is acceptable. `test/cowork/storage-retention.test.ts` pins the behavior and ratchets the destructive primitives allowed under `src/cowork`.
- **Owner decisions 2026-10-16** (detail in [cowork-storage-security.md](../cowork-storage-security.md#owner-decisions-2026-10-16); the slices are not built): workspace delete removes the VM disks plus the workspace's shared guidance, memory and outputs, only after a confirmation that lists them and offers an export first, never touches connected Mac folders or GitHub remotes, and warns when a GitHub-backed clone on `data.ext4` has unpushed commits or uncommitted changes; an export is a `.winterworkspace` folder bundle (the intended implementation, not part of the decision: the closed manifest plus sparse-copied images, cloned with APFS `clonefile` where possible); VM disks stay excluded from Time Machine and export is the backup path.
- **Still open (technical)**: the confirmed workspace delete; the `workspace.archive`/`restore`/`delete` operations and `workspace.export.*` RPCs that would reach the writer and restore above; wiring the image pin into admission with the native controller slice; and a Cowork-aware Migration B (until then it keeps refusing).
