# Winter Headless

*Read this before touching the `headless` browser backend, the Winter Headless helper app, its network rules, or the Chromium embed layout.*

`browsers.open(url, { browser: "headless" })` opens a tab in Winter's private, invisible browser — background reading, many tabs at once. One engine: `HEADLESS_ENGINES = ["winter"]` (`packages/core/src/computer-use/browser/headless/engines.ts`). The engine (Phase 2 tab driver, policy, CDP allowlist) is shared with the other backends — see [computer-use-browsers.md](./computer-use-browsers.md).

## The helper app

- **Winter Headless** (`apple/Winter/Sources/HeadlessHelper/`): `LSBackgroundOnly`, activation policy `.prohibited`, and a window guard (`WinterHeadlessApplication.installWindowGuard`) that refuses to order ANY window in. Windowless CEF on the Chromium Winter already ships — `apple/Winter/Sources/CEF/WinterCEF.{h,mm}`'s `WinterCEFInitializeHeadless`, `WinterCEFCreateWindowlessBrowser`, `WinterHeadlessClient`: 1280×800 at scale 1, `kHeadlessFrameRate` 10 fps — the agent's view (a tab shown in Winter's panel is laid out in the panel's size while it is shown, below). Every browser renders ACCELERATED (`shared_texture_enabled`: frames as borrowed IOSurfaces, no CPU readback); the mode is fixed at creation, which is what lets any live tab be presented later without recreating it. Winter.app itself never turns windowless rendering on.
- Each session gets its own IN-MEMORY `CefRequestContext` (no `cache_path`; printing and network prediction off; WebRTC `ip_handling_policy = disable_non_proxied_udp`), disposed when the session's runtime ends (`context.dispose`).
- Fixed switches (`HeadlessLayout.swift`'s `HeadlessArguments`): `--use-mock-keychain`, `--mute-audio`, `--enable-features=WebMCP`, `--disable-features=…` (`disabledFeatures`), the resolver and PAC belts (below), and `backgroundRequestSwitches` (`--no-first-run`, `--gaia-url=https://127.0.0.1:4/`, `--disable-background-networking`, `--disable-domain-reliability`).
- **Every CEF handler whose default could show UI is answered explicitly** (list above `WinterHeadlessClient` in `WinterCEF.mm`): dialogs held for the engine; permissions, media and screen capture denied; file choosers, downloads, pop-ups, context menus, HTTP auth and certificate errors cancelled; a client-certificate request continued WITHOUT a certificate (CEF's default is a dialog); no external protocol handed to another app.
- **It carries Winter's ONE Chromium**: the CEF framework and the five "Winter Helper" bundles (`HEADLESS_NESTED_HELPERS`) live in the helper's own `Contents/Frameworks`, and Winter.app's own CEF runs from there (`WinterChromium.swift`); Winter.app's `Contents/Frameworks` holds none (release.ts checks). Why: a Chromium subprocess's sandbox reads only inside its BROWSER's main bundle, so a helper borrowing Winter.app's Frameworks could not run a page. CEF's `main_bundle_path` is the helper ITSELF (naming the enclosing Winter.app crashed every subprocess); Winter.app keeps CEF's default.
- Nested at `Contents/Helpers/` in every configuration (`scripts/embed-headless-helper.sh`): Release `Winter Headless.app` / `com.winter.headless`; Debug `Winter Headless Dev.app` / `com.winter.headless.xcode-debug`. `bun run dev:headless` builds the standalone dev helper `dist/dev/Winter Headless Dev.app` as `com.winter.headless.dev` through `WINTER_HEADLESS_DEBUG_BUNDLE_ID` (read only by the helper's target, so its nested helpers keep their own ids). All signed with hardened runtime, NO entitlements, a STATED designated requirement (identifier + Winter's team, `scripts/headless-helper-lib.ts`), never `--deep`, Winter.app last. Running a nested helper re-registers its enclosing Winter.app with LaunchServices: after a run from a Release COPY, `lsregister -u` it.

## How the daemon runs it

- Ladder (`engines.ts`, explicit path authoritative): `$WINTER_HEADLESS_APP` (either identity; the ONLY rung for a daemon off its profile's default home) → dev: the helper beside `dist/dev/winter-core` → dist: `Winter.app/Contents/Helpers/Winter Headless.app` next to the running `winter-core`.
- SPAWNED directly, never through LaunchServices (`winter-engine.ts`): a `pipe(2)` pair over bun:ffi, both ends close-on-exec, handed to `Bun.spawn` as fds 3 (commands in) / 4 (answers out); env = fixed `PATH`, `HOME`, `TMPDIR` only; the process is checked against the requirement BY PID before a byte is sent. The helper exits on fd 3's EOF (a dead daemon takes it along). Pipe protocol 1 (`HEADLESS_PIPE_PROTOCOL` = `HeadlessWire.protocolVersion`).
- Ops: `headless.hello`, `tab.ensure` (creates only WITH a url; a tab belongs to one session), `cdp.*`, `tabs.live`, `context.dispose`; notification `headless.notice {tabId, kind: popup | local-network}` → one daemon line per tab and kind, never the address. Every CDP command goes through Winter.app's own CDP door and `CDPTabGate` (WinterKit) — allowlist and world rules; no browser-level CDP command at all.
- **The pool** (`headless/pool.ts`, backend id and family `headless`, "Winter (headless)"): starts the helper at the first headless `browsers.open` (never a listing); ends it after 5 idle minutes with no tab (`HEADLESS_IDLE_EXIT_MS`), at daemon stop, or when `computerUse.headless.enabled` turns off (`computerUseHeadlessEnabledFrom`, default on; read at every command and every 10 s; listed off with that reason). After 3 timeouts in a row (`HEADLESS_WEDGED_AFTER_TIMEOUTS`) it asks `tabs.live` (answered on the helper's main thread): answered → only the tabs those commands named are lost; silent for 3 s → wedged, killed, every tab lost. A crash makes every headless tab `TargetLost`; the next open relaunches.
- Caps: `HEADLESS_TABS_PER_SESSION` 8, `HEADLESS_TABS_GLOBAL` 24, `HEADLESS_MEMORY_LIMIT_BYTES` 3 GiB — the helper's process tree's PHYSICAL FOOTPRINT summed (`memory.ts`, libproc; an RSS sum only as the fallback), read per new tab after closes in flight settle (`HEADLESS_CLOSE_SETTLE_MS` 2 s). Running out is `capacity` → `TargetBusy`; nothing is closed for the model; over the limit with NO tab open, the helper is restarted (`exitReason: "memory"`).
- Files: `<home>/run/headless.pid` (pid + start time; a boot sweep, `sweepHeadless`, kills a leftover), a fresh `<home>/cache/headless-cef/<random>` cache root per run (removed at exit). Only the browser's COMPONENTS (root store, CRLSet) outlive a run, in `<home>/cache/headless-components` (`components.ts`) — never cookies or cache.

## Policy and lifecycle

- No card, "Allow all apps" ignored (as for `winter`); `plan` observes only; the dangerous-domain floor applies.
- Every headless tab is an agent tab (`lifecycle.ts`): closes at each main-thread turn end unless `handoff()` (even while the pool is not offered), when the session is deleted/archived, and when the computer-use runtime idles out; daemon stop closes nothing per tab (the helper exits). `keep()`, `waitForUser()`, `download()` and unmuting are `NotAllowed`; `mute()` is a no-op.

## The local network is refused, this Mac allowed

ONE lexical rule, held equal in `headless/private-network.ts` and the helper's `HeadlessNetworkRule.swift` by `packages/core/test/computer-use/fixtures/headless-private-network.json`: RFC 1918, link-local, CGNAT, 0/8, multicast/reserved, ULA, fe80::/10, fec0::/10, IPv4-mapped/-compatible/-translated and NAT64 forms, `LOCAL_NAME_SUFFIXES` (`.local .home.arpa .internal .lan .home .corp .intranet .private .localdomain`) and single-label names — refused; loopback, `localhost`, `*.localhost` — allowed. Nothing resolves a name.

- Daemon: refuses the model's URL (`browsers.open`, `goto`) before anything loads (`HEADLESS_LAN_REFUSAL`) and reads no further on a tab whose committed top frame landed there.
- In the browser, before any socket, four layers: (1) the REQUEST GUARD (`WinterHeadlessRequestGuard`: `OnBeforeBrowse` every navigation and redirect, `OnBeforeResourceLoad`/`OnResourceRedirect` every other load — a cancelled `goto` reads as the LAN refusal); (2) the PAC BELT (`--proxy-pac-url=data:…`, `pacScript` — the same rule in JavaScript over the host string, no DNS) sending refused hosts to `PROXY 127.0.0.1:4`, a privileged port nothing can listen on, so even requests no CEF handler sees (WebSockets) fail at once; (3) the RESOLVER BELT (`--host-resolver-rules`, `hostResolverRulesSwitch`) mapping every name under the suffixes to not-found; (4) WebRTC held to proxied TCP with the mDNS responder off.
- **No request a page did not cause, but one**: the switches above turn off the first-run ping, network-time, autofill, AI Mode, Safe Browsing, and move Google's sign-in cookie check to the dead port. The COMPONENT UPDATER stays on on purpose (the Chrome Root Store and CRLSet).
- Stated residuals: a public name that RESOLVES to a private address (DNS rebinding — nothing judges a resolved address), and the DNS queries for public names themselves.

## Showing a headless tab (lane H3)

A live headless tab is shown in the session's panel in Winter.app WITHOUT recreating or reloading it — the same document, its sockets, uploads and form state kept — for the sign-in hand-off and for the person to watch or take over. **The wire** (`Sources/HeadlessPresent/WinterPresentWire.h`, version 2, both halves in ObjC: `HeadlessHelper/HeadlessPresentProducer.mm` in the helper, `HeadlessPresent/WinterPresentConsumer.{h,m}` in Winter.app and the proof tool): the helper checks in a fresh bootstrap service per presentation (`com.winter.headless.present.<pid>.<32 hex>`); the viewer looks it up and says HELLO with the daemon's nonce; EVERY message both ways is checked by the audit token in its trailer — the viewer against `winterAppRequirementFor(profile)` (`com.winter.app[.dev]` + Winter's team), the producer against the requirement the daemon verified the helper by — and only the kernel's own dead-name notifications (pid 0) count. Frames: CEF's accelerated paint copied on the GPU into an owned 3-slot IOSurface pool (a new generation per scale change; a slot the viewer still reads is never written; frames dropped, never queued), the viewer's slot released once its GPU read COMPLETED. Version 2 adds, only while the viewer holds CONTROL: input (mouse, wheel with trackpad precision, keys as CEF's own macOS sample sends them — adapted, BSD-3, credited in `HeadlessPresent/THIRD_PARTY.md`), IME (set/commit/finish/cancel + the composition's character rects for the candidate window), edit commands (a paste carries the text Winter read on the person's ⌘V — the helper never reads the pasteboard; ≤ 64K UTF-16 units, sent in pieces that stop at the first undeliverable one), page dialogs offered to the person (with the ORIGIN that raised them — a sheet names that host, an opaque origin "this page") and withdrawn when control goes back (a held dialog stays the agent's), file choosers answered with COPIES the app makes in `<home>/cache/headless-uploads/<random>/` (the helper accepts only a regular file inside that folder, derived from its own cache root, realpath + lstat), the page's cursor, and PAGE updates (address and title). A window the page opens while the person holds it (a sign-in window) is ADOPTED natively — windowless, accelerated, `window.opener` kept — announced as `headless.popupOpened`, shown in the panel in front of its opener (the panel shows a session's newest view) as purpose `popup`, never listed to the agent, and closed when the person lets the opener go; anything else is cancelled as before. An in-page HTML5 drag by the person runs inside the browser (CEF's drag target/source calls). **While it is shown, the page is laid out in the PANEL's size** (the view's bounds in whole points at its screen's backing scale — `RESIZE {cssWidth, cssHeight, scale}`, `WinterCEFHeadlessSetPresentation`'s view; at least 320×240 CSS pixels, at most 8192 device pixels a side), so it reflows to the panel and is drawn one CSS pixel per point, crisp, following a resize, the panel's expand button and a move to another display; a reflow, never a reload (the proof's oracle holds across a live resize and a 2×→1×→2× move). Watching counts as viewing (the controller's ruling: the person needs a readable view; the agent then works in that layout) — the helper says each view as applied (`headless.viewChanged {tabId, cssWidth, cssHeight, scale}`, the pool counting size changes only, `HeadlessPool.view`), and on the agent's first primitive after a size change one daemon line says "the view is now W×H while the user watches" (or that it is back to 1280×800) while a Point of a screenshot taken before it is refused, "the tab was resized while the user was looking — take a new screenshot before using a Point" (`TabDriver.syncView`, each shot stamped with the view it was taken in, as a full-page shot's Points are refused); refs keep working. When the presentation ends the agent's own 1280×800 at 1 comes back — not the person's size: the agent's screenshots, Points and a site's width-dependent layout stay what they were before the person looked, and a 2× view would cost every agent screenshot and the GPU four times the pixels. Two quick view changes stall CEF's windowless painting entirely, so a browser's view (size and scale alike) changes at most once per 300 ms, the newest wish winning; the panel sends one at most every 100 ms. A pool generation's frames carry the view they were painted at (the pool's `scale`; CSS = pixels / scale), and until the new view arrives the old frame is drawn from the top-left at one point per CSS pixel, scaled down only while larger than the panel. **The daemon** (`browser/headless/pool.ts`): the helper's hello names `features: ["present"]` and Winter.app's `browserLink.attach` names `headless` (the daemon answers its own `BROWSER_LINK_FEATURES`) — feature detection, no protocol bump; a missing side refuses typed with the sentence to update or open Winter. `present` (the transport's, for `waitForUser`) and the panel's `watch` check in a presentation, send the app `headless.show {sessionId, tabId, service, nonce, producerRequirement, control, purpose: handoff|watch|popup, url, title, uploadDir}` and wait for the helper's `headless.presentationStarted` (`HEADLESS_PRESENT_START_MS`, 10 s; nobody connected: ended, typed). **The control lease**: while the person holds a tab, every agent command on it is `capacity` → `TargetBusy` "the user has this tab in Winter's panel — …" (letting go is always allowed), and the engine refuses every primitive on a held tab itself before it reaches the pool — reads the driver could answer from what it has (`console()`, `network()`) included; only `close`, `handoff` and `waitForUser` pass (`headless/lease.ts`); an attach the backend let go of midway does not count as held; the lease ends only once the helper has taken the viewer's control away (a helper that can't ends the view), a take-over the helper may have half-applied is taken back there, and every change of control is a daemon log line naming the tab and why; taking control first stops new commands and lets the ones in flight finish (`HEADLESS_DRAIN_MS`, 5 s), then undoes what the agent turned on that would get in the person's way (the file-chooser interception, focus emulation, a device-metrics override) — the CDP events keep flowing, so the engine still follows the page. `waitForUser` on a headless tab: one card with "Show me the tab" only (the tab is in Winter, not the user's browser), then the panel shows it with the person in control and the wait card; the panel's Done answers it (the tab's control comes back and the view goes, then a fresh `state()`), Stop waiting or no answer leaves it the person's — still shown, `headless.update` turning its buttons into Hand back — until they hand it back or close it. From the panel's headless list (`headless.tabs` pushes, debounced; `browserLink.headless {sessionId, tabId?, action: list|watch|takeOver|handBack|done|stopWaiting|close}`, LOCAL harness only): watch (no control), take over (the lease), hand back, close; a tab the turn's end would close while the person holds it is closed when they let it go. A `waitForUser` that ends by any other road (the script cancelled, the tab gone, the show failing) leaves the tab the person's with Hand back (`headlessHandoffOver`), never a Done that answers nothing. **What the person does in a tab they hold is theirs** (`HeadlessPool.held`/`holds`: from the moment the agent's attachment is undone for them until control returns): the engine still follows the page (frames, navigations, dialogs) but records none of its console, network or downloads (`TabDriver.onEvent`'s `person`), hides the browser's replay of them at the next attach (as after a hand-off), and says once on the agent's next primitive that the user had the tab; the page's refused popups and local-network requests meanwhile are dropped (no LAN refusal read into the agent's next `goto`); the site floor is never met during the hold — it applies to whatever page the person left at the agent's next act, and before `waitForUser`'s Done prints that page (a refused listed host prints nothing of it). The person's input travels app ↔ helper only, so no daemon-side clock, `lastUsed`, telemetry, audit or own-input fact can be stamped by it. The app (`Sources/HeadlessPresent`): `HeadlessPresentStore` (one per app) runs the ops and shows the newest presentation of the session the panel shows; `HeadlessPresentView` is a `CAMetalLayer` viewport (the page drawn top-left at one point per CSS pixel, its view asked for from the panel's bounds and backing scale — `HeadlessPresentGeometry.viewWish`/`pageRect` — nothing drawn while occluded) that sends input only while the person holds control, with the IME as an `NSTextInputClient`, and one accessibility element (the page's own content is not exposed — no VoiceOver into the page). Measured: a static page costs no GPU time accelerated or not, an animated one the same cycles and energy, and the GPU process holds less memory accelerated. Gates: `bun scripts/browser-e2e/headless/present/proof.ts --app <Winter Headless .app>` (show → take over → hand back cycles with a page oracle — same document, ticks, keys, socket and upload — plus frames, ports, scale generations, a slow viewer, dialogs, `<select>`, IME, paste, file choosers, a window and its hop to another site, a drag, a dead viewer, a wrong nonce and a wrong signer), `packages/core/test/computer-use/headless-present.test.ts` over the fake helper, WinterKit's `BrowserLinkHeadlessTests` and the app's `HeadlessPresent*Tests`. Not done: the page's accessibility tree, and a file dropped onto the view from outside.
