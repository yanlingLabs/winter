# Bounded RAW block + active-return fixture proposal

Status: prepared plan only. No block-bearing VM has run. Root review and the focused producer-progress delta acceptance must precede implementation/launch. This does not use or claim disk encryption, trusted guest bootstrap, real Winter integration, production hardening or a passed resource gate. The verified A6 artifacts/evidence and accepted patch0004 stay separate.

## Exact proposed profile

- One disposable self-sandboxed worker, exactly 768 MiB and two vCPU, reviewed libkrun pin plus accepted block candidate/delta only. External cached Linux `6.18.35-197-debug` Image SHA `fb2cfb79eb1ae19447a85d75682d7fa5cfec97e24beb2609a492b806e8072c8d`; new deterministic fixture-only static initramfs. This kernel lacks the required crypto stack and is intentionally a plaintext synthetic block comparison.
- Actual PL011 earlycon/RNG/balloon plus one explicitly raw, Writeback/Full-sync, writable 64 MiB regular backing file created exclusively under the private owned fixture directory. Explicit implicit-vsock disable; no virtio console, network, fs/DAX, host folder share, GPU/audio/input, firmware bundle, nested VM or key transport. No user credentials, live homes/daemon/Keychain or host pressure generator.
- Separate opt-in artifact directory/build receipt and test code (`block_init.c`, `block_worker.c`, `build_block.py`, `run_block.py`, `block_receipts.py` proposed); do not overwrite A6 worker/initramfs/library or change its runner mode. No production API activation.
- Keep the existing worker-ownership lock and refuse any stale owned A6/block worker before launch. Ad-hoc signing uses a unique fixture identity. Worker installs/verifies sandbox before libkrun context creation; read/write authority is restricted to that one canonical regular RAW file. Denial checks cover another file in the same fixture, host read outside grants and loopback connect. File path/inode/size and link count are checked before admission; no image-format auto-detection. Current read-only A6 policy cannot be silently reused for the writable backing file.
- Parent creates the file with exclusive create, mode0600, initial sparse size64 MiB and no real data. Worker receives its explicit canonical fixture path, never a generic disk path. Logs are host-created stdout/stderr pipes; worker has no general fixture write grant. Empty credential environment, private HOME/TMPDIR, /dev/null input and exact signed artifact/kernel/initramfs/patch hashes are required.

## Bounded guest workload

Keep exactly the three A6 allocation/free/reuse cycles: 256 MiB workload, 32 MiB retained sentinel, every-word zero/reuse/retained integrity and independent one-second heartbeat. Keep the free interval ten seconds so normal Linux page_reporting has time to report; no balloon pressure or forced host-memory pressure.

Add two short-lived guest I/O threads with distinct fixed regions on `/dev/vda`, bounded aligned 256 KiB owned buffers each. Discover the virtio block device through guest sysfs/devtmpfs, never infer host paths. Use O_DIRECT and sector/alignment checked offsets so buffered page-cache growth does not become a different memory workload. Each thread owns a disjoint 4 MiB extent; write a nonsecret deterministic pattern containing cycle/thread/offset identity, flush at bounded checkpoints, read it back and compare every byte. Buffers total512 KiB; touched user workload remains below289 MiB and the prior384 MiB workload ceiling. Disk content is synthetic plaintext and may be inspected only as fixture integrity evidence.

Run the I/O loop throughout touched, freed and reuse intervals, capped by time and operation count (initial proposed maximum100 operations/second total and6,000 operations over60 seconds). This is device work concurrent with guest memory activity, not a storage benchmark or host pressure test. No external programs/network dependencies are loaded into the guest. Shutdown and join I/O threads before the final guest completion/poweroff; no orphan threads or indefinite guest retries. I/O errors/short transfers/flush errors fail the fixture rather than falling back to buffered or plaintext alternative storage.

## Evidence required before claiming block overlap

New bounded native receipts must identify capture/head/queue generation, short-copy lease release, per-request pin ranges, owned-I/O start/end, deferred completion and status/used ACK. Existing reclaim logs record exact CPU park/resume roster, pin/ring exclusions and every retained-HVA unmap/replace/remap return code. Bound trace records and preserve overflow as an incomplete-evidence failure. Adding instrumentation is a reviewable follow-up change, not permission to modify accepted bytes while review runs.

Require actual successful reads/writes/flushes in every ten-second freed interval and continuing guest heartbeat/retained/reuse checks. At least one reclaim epoch must snapshot a registered outstanding request pin while the I/O loop is active; permanent ring pins alone do not satisfy the outstanding-I/O observation. Mark overlap unverified if timing never yields that snapshot. A separately reviewed fixture-only owned-buffer/completion hold could make that overlap deterministic; report it explicitly and do not mislabel a hold as an OS syscall being blocked. Any actual syscall overlap claim requires start-before/finish-after native receipts.

Independently audit that no replacement intersects any ring/request pin, all parked CPUs ACK the exact epoch, no mapping occurs after Stop, used ACK follows successful mappings, and both queued requests survive producer append. Record host worker phys_footprint/resident samples at one-second cadence and per-cycle touched versus8–10-second post-free windows, plus pause/drain timings. A flat footprint or working disk alone is not active memory-return evidence. Preserve raw logs and distinguish guest completion, host audit, return verified in this expanded scope, and production readiness.

## Lifecycle and exit

Guest duration <=100 seconds; worker alarm120 seconds; parent watchdog130 seconds. On failure/timeout the runner kills/reaps only its direct owned Popen child and retains uncertainty/evidence. Never stop another VM or launch/clean live Winter state. It records no-owned-worker-left and final disk SHA/size; host reads of the bounded synthetic disk can verify expected patterns after verified VM exit. Cleanup removes only that fixture when explicitly desired, preserving evidence by default.

Before launch: exact frozen source/module/hash correspondence, full no-VM tests, focused independent review, explicit native profile inventory and sandbox denial probe. After launch: root independently inspects raw receipts before updating any verification scope. A successful raw fixture will still leave crypto-capable kernel/bootstrap, authenticated at-rest storage/crash behavior, trusted key delivery, other asynchronous devices, guest confinement, resource admission and full Cowork end-to-end integration open.
