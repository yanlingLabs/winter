## Concrete code and contract

- `reclaim_access.rs`, compiled directly into `krun-devices`: private device-generation tokens, short RAM-copy leases, bounded range pins, exact monotonic freeze epochs, lease drain, frozen exclusion snapshots and explicit mapping completion before admission resume. Timeout, Stop or abandoning a frozen/mutating transaction closes access permanently. Pins survive deferred completion and are conservative exclusions; dropping a pin during freeze cannot remove it from the frozen snapshot.
- `block_bounce.rs`, compiled directly into `krun-devices`: one captured request and owned payload/result at a time. Each request is at most 1 MiB; host disk calls receive at most 64 KiB per operation and never a GuestMemory reference, DescriptorChain or VolatileSlice. `service_next` is the actual worker transaction, shared with the no-VM tests. It checks Stop, defers completion during freeze and revalidates the token/queue generation before copying/status/used ACK. Unsupported commands receive virtio status 2 without I/O.
- Native `src/devices/src/virtio/block/cowork.rs`: opaque checked GuestMemory leaf and queue adapter. Full queue spans/readiness/pending count and complete descriptor chains are checked before capture; copied request DTOs leave this leaf. Permanent queue-ring pins persist between requests. Request buffer/header/status/ring pins persist across blocking host I/O. Guest copies occur only under a verified access lease. Native `DiskProperties` receives only host-owned standard buffers. The epoll worker uses the shared `service_next` transaction.
- Native `src/vmm/src/cowork_fixture.rs`: briefly clones the fixed reduced-profile snapshot under `Arc<Mutex<Vmm>>`, then releases it before every CPU park, access drain, device lock, mapping or resume operation. Exact CPU park precedes closing RAM admission, so CPU MMIO can finish before ACK. With CPUs parked, access closes/drains and adds every pinned range to the reviewed planner's exclusions. Mappings and balloon ACK finish before device admission and CPU resume.
- Native `Block` selects the guarded worker only when explicitly configured. It advertises bounded SIZE_MAX/SEG_MAX; DISCARD, WRITE_ZEROES and EVENT_IDX are disabled in this first profile. Only read/write/flush/GET_ID are handled. Device reset signals Stop and joins before changing the registered device generation.
- Native `krun_enable_cowork_block_fixture_reclaim` is separate from the A6 API. Admission requires `--no-default-features --features blk`, exactly one raw/Writeback/Full-sync disk, 768 MiB/2 vCPU and the existing external-kernel/legacy-serial/RNG/balloon topology. No fs/DAX, network, vsock, virtio console, GPU/audio/input, firmware bundle or nested VM is admitted. There is no block launch option in the current fixture runner: independent review is required first.

## Review boundaries and remaining work

Astra must review actual native lock/lifecycle/mapping order and the opaque queue/pin leaf before any disk-bearing VM. No test here proves an actual HVF mapping transaction with real block I/O. The reviewed A6 planner/barrier/coordinator modules remain byte-identical. Revision two separately changes the control module for absolute WFE deadlines; its exact mirror is `block_reclaim_control.rs`. Their new block integration needs independent review.

A host disk call can block indefinitely. It holds no RAM lease or VMM mutex; pending guest ranges stay pinned and an active-return transaction can exclude them. Device reset currently joins while servicing the device MMIO reset and can consequently delay a CPU park; the bounded park timeout fails the whole owned worker before mapping. This is a fail-closed candidate, not a demonstrated reset/drain recovery guarantee. External process termination remains the recovery boundary. Stop checks cannot cancel an already running host syscall.

The permitted lifecycle is deliberately fixed: one pre-registered block device, serialized main-event-thread reclaim and no DAX/GPU mapping-message worker. Hotplug, cross-device registration/removal, asynchronous renderer callbacks and general mapping ownership have not been proved. Current ring/token revalidation and in-flight pins rely on that profile; enabling another device requires its own access contract and tests.

The original A6 WFE relative-timeout/deadline issue remains historical. Revision two captures an absolute deadline before post-emulation park and regresses those actual functions; no timer or latency guarantee is claimed. A future bounded disk fixture must show continued guest heartbeats, retained/reuse integrity, actual in-flight block reads/writes, full range/ACK/syscall receipts and host footprint. Crypto-capable kernel/bootstrap, authenticated disk behavior, trusted key transport, worker signing/library validation and full Cowork integration remain separate gates.


## Revision two: required independent-review fixes, 2026-10-12

This revision preserves commit `90c34d59` and patch SHA `4ddbf8a2d1c04a0fcd07320b18c0dd253214797e405286b0b965037eb1e2ed87` plus its 32-test receipts as historical evidence. `block-candidate.json` selects the new full pinned-source patch; `prepare_block.py` also verifies the preserved original and A6 hashes. There was no block-bearing VM run in either revision.

1. Actual `krun_start_enter` calls `cowork_validate_profile` while the context is still in the registry, before any payload loader, disk opener or VM allocation. It checks both context GPU flags/shared-memory/render FD and normalized VmResources fields. It repeats validation after normalization immediately before identity changes/VM construction. Public GPU setter and normalized-resource tests call the public start API and prove the rejected context is still present for `krun_free_ctx`; rejection therefore precedes consumption and any opener, rather than accidentally failing later on the deliberately nonexistent disk.
2. `cowork_construct_blocks` validates the entire disk count/raw-format/cache/sync/memory profile before invoking any construction callback. Rejected Qcow2, VMDK, unsafe cache, no sync, zero and two-disk configurations produce zero callback invocations. The production callback is `VmResources::add_block_device`; format parsers and implicit dependencies cannot run before this check.
3. `run_guarded_epoll` is the actual native worker loop and uses a drain guard on every return, including Stop during owned I/O. Block reset drains again after joining so a reset notification written after a worker already exited cannot survive. Activation drains before starting its replacement. The real epoll regression runs two worker incarnations against the same stopfd and verifies successful actual Queue I/O/used completions in both; a separate real epoll test stops during a stalled read and checks the reused FD is empty.
4. The opaque queue leaf uses `fixture_checked_pop`. A validated zero pending count alone returns empty. Invalid first index/NEXT produces a terminal error, never empty. First-head/pending metadata is re-read before advancing next_avail; deterministic injection tests modify those actual guest fields between reads and prove zero consumed-head advance/used ACK.
5. Terminal access faults notify the registered VMM exit event and set exit code 77 plus the global Stop bit. The actual epoll loop marks Access stopped on error; its malformed-head test wakes an otherwise quiet real EventManager without a balloon kick or guest activity. Each real HVF unmap/replacement/map and FRQ ACK uses the same `checked_mapping_operation`, backed by `Access::frozen_operation`: it verifies the exact frozen mutation epoch, zero leases and Stop under the state lock held across that short mapping/ACK operation. Access Stop is serialized against each operation and prevents every subsequent operation/ACK; the no-VM actual helper test fails the frozen transaction and prevents resume. These short state locks contain no disk I/O or VMM/device drain wait.

The WFE follow-up is also carried here. Native `run_emulation` converts the relative HVF timeout to an absolute Instant before `step` can park the CPU. `wait_for_event` passes that same deadline to `wfe_deadline`; it does not re-establish a timer after resume. `block_reclaim_control.rs` is the byte-identical extracted implementation. Its regression pauses during the post-emulation control drain, allows the deadline to expire, resumes and proves the queued IRQ remains unconsumed because the expired wait returns immediately. This fixes that specific extension; it is not a timer or latency SLA.
