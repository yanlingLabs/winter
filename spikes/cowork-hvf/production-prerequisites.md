Existing accepted workspace/session/grant/storage contracts remain authoritative.

## Proposed RAM access boundary

Create a per-VM memory coordinator below the VMM/device split, with an acyclic shared module and explicit registration. Distinguish `OwnedAnonymousRam`, immutable/borrowed payload mappings, DAX/shared file windows, GPU/resource windows and device/MMIO ranges at **allocation/registration time**. `create_guest_memory` currently appends shared regions before one `GuestMemoryMmap::from_ranges`; the production registry must not classify every resulting region as reclaimable merely because the initial reservation is anonymous.

Device code receives a scoped accessor, not an unrestricted clone or raw `GuestMemoryMmap`. It offers checked ring parsing, copied descriptor DTOs and bounded copy operations. Raw slices/pointers stay inside audited leaf methods and cannot escape a lease. Queue snapshots contain GPA/length/operation/generation values, not live borrowed slices. Inventory and remove every alternate pointer/copy path, including renderer callbacks and reset/destructor code; a wrapper around only the balloon hook is insufficient.

For TX/write operations, copy a bounded chunk into a host-owned buffer under a short RAM lease, release that lease, and perform host I/O. For RX/read operations, receive into a host-owned buffer first, then reacquire a lease and revalidate incarnation, device/queue generation, descriptor ownership and full destination span before copying or completing. An operation that genuinely needs zero-copy must hold an explicit range pin until completion; pinned pages and all queue rings are excluded from reclamation. A host-owned copied buffer alone does not justify forgetting its outstanding guest destination/status ranges.

Leases and pins are private runtime state. Editable instructions, guest packet fields and persisted plaintext manifests cannot create them. Bound per-device queue depth, bounce-buffer capacity, pinned bytes and completion backlog; expose aggregate counters to daemon resource admission. User-facing per-VM CPU/RAM/GPU knobs are not introduced.

## Proposed drain transaction and lock order

1. Coalesce a report notification and leave the device callback. Snapshot the VM incarnation/device roster under a brief lifecycle lock. Freeze new device registration, reset/removal and mapping mutations for this epoch.
2. Publish/control/kick the exact vCPU roster and wait for epoch ACKs **without a device or global VMM mutex held**. Leave ordinary device RAM admission open until CPU MMIO callbacks finish, so a CPU cannot be trapped behind a closed lease gate while it needs to reach its ACK. All blocking host I/O must already occur outside RAM/device guards.
3. After all CPUs park, close new device RAM leases and notify every registered worker/callback participant. Drain current short memory accesses; host I/O can continue only against host-owned buffers, with completion deferred. Obtain exact epoch/device-generation acknowledgments and immutable exclusion snapshots. Pending zero-copy operations must finish within the bound or remain pinned and excluded; do not destroy their mappings to force progress.
4. With no RAM readers and lifecycle/mapping mutation frozen, validate the complete FRQ, every queue ring and every in-flight range. Copy a bounded batch. Valid empty/stale notifications resume without invented entries; valid planning rejects return consumed heads as no-ops. Malformed queues/ownership state fail the worker before mutation. Keep 16 KiB host-page containment/alignment and never round an arbitrary 4 KiB report outwards.
5. Apply the tested retained-HVA replacement sequence only to sealed private RAM that intersects no ring, pin, DAX or device range. Preserve initial HVF flags. On any failure after mutation starts: no used ACK/resume, terminate the owned worker, persist an uncertain outcome and require the host's verified VM-gone/admission recovery path. Avoid a standalone `munmap` hole.
6. Complete all mappings before used ACK. Release device guards, open device access at the new memory generation, wake deferred completions with revalidation, then resume the exact CPU epoch. Define generation/pin rules so unrelated reclaimed pages do not incorrectly invalidate a still-pinned operation. Stop wins over all phases.

The initial production implementation may terminate the worker on a park/drain timeout before mutation, matching the fixture's fail-closed policy. A later nonfatal cancellation path requires an explicit epoch-cancellation protocol for already parked and late-ACK CPUs; simply clearing a flag and resuming a subset is unsafe. Do not claim timeout recovery until that protocol is tested.

Do not hold `Arc<Mutex<Vmm>>` while waiting on fs/DAX workers or mapping callbacks. Use a single mapping/lifecycle owner and narrow state locks, with queued map-change requests; cancellation and Stop must be able to wake waits. This ownership protects VM memory/disk lifecycle, not user file editing.

An additional current DAX wiring limitation is visible in `src/libkrun/src/lib.rs:3061-3063`: the macOS VMM mapping-message worker is started only when GPU flags are present, while `src/vmm/src/builder.rs:1939` gives fs its mapping sender. A future DAX profile must establish a working mapping owner independently of GPU, as well as fix the drain lock order. The present plan keeps DAX explicitly disabled.

## Crypto-capable kernel and immutable bootstrap

Observed current profile: `../cowork-vm/out/assets/config-apple-6.18.35:1974` disables `CONFIG_MD`; XTS is off at `3221`, block integrity is off at `791`, and AF_ALG skcipher/AEAD userspace interfaces are off at `3302`/`3304`. AES/GCM/HMAC/SHA-256, virtio block, ext4 and page reporting exist. Device-mapper's crypt/integrity targets are beneath the MD configuration menu and require the device-mapper core, so existing cipher symbols alone cannot unlock a LUKS volume. [Linux v6.18 device-mapper Kconfig](https://raw.githubusercontent.com/torvalds/linux/v6.18/drivers/md/Kconfig)

`kernel/crypto-candidate.fragment` now has an offline comparison build, with verified source/toolchain inputs, complete resolved configuration and output hashes recorded in `kernel/README.md` and `kernel/build-result.json`. It has not booted and is not a selected production kernel. The neutral pinned cryptsetup toolset is separately built and checked in `kernel/userspace/README.md`; it is not an unlock initramfs. Security/support review must still determine the production version. Keep essential unlock/storage support built-in so private encrypted disks are not required to load their own unlock modules.

The immutable public initramfs contains a small trusted PID 1, pinned cryptsetup/libcryptsetup and dependencies, mount/device setup and the trusted key receiver. Static versus explicitly bundled dynamic userspace is a build choice pending reproducibility/license evidence. It authenticates the admitted workspace/volume/key-version binding, unlocks only the intended private data/environment disks, then closes the bootstrap transport and drops unlock privileges before agent/tool execution. Do not put keys in argv, environment, kernel command line, host files, guest logs or general-purpose stdin. Keep guest tools away from the raw disk, mapper control, key transport and trusted runtime/config/store paths through real UID/namespace/capability enforcement.

The master remains only in the signed hardened broker. The broker's admitted worker receives only its workspace/volume material through a one-shot inherited capability; a separate reviewed worker-to-trusted-guest bootstrap transport is required. It cannot use the present output-only PL011 fixture channel to unlock a guest. Scoped virtio console/vsock would add RAM consumers and therefore must first pass the access/drain contract above. Authentication derives from the admitted daemon capability plus sealed workspace/volume/key-version records, not plaintext manifests or shared worker code identity. Apply the existing storage-security contract's missing-key, corruption, freshness and recovery rules; do not introduce an encrypted runtime-state DB requirement.

## Block format remains a candidate

Evaluate the already recorded LUKS2 + authenticated dm-integrity candidate inside the isolated guest. Kernel dm-crypt supports authenticated cipher forms and tag storage from dm-integrity; dm-integrity journal mode coordinates data/tag writes and detects modified authenticated sectors as I/O errors. Its direct/bitmap alternatives have different crash guarantees. Plain XTS or an unkeyed CRC is not the selected authenticated-storage guarantee. [dm-crypt](https://www.kernel.org/doc/html/latest/admin-guide/device-mapper/dm-crypt.html), [dm-integrity](https://www.kernel.org/doc/html/latest/admin-guide/device-mapper/dm-integrity.html)

Cryptsetup 2.8.0 explicitly described LUKS2 authenticated encryption as experimental. This versioned statement is a maturity constraint, not a claim about the newest release; choose/pin a currently supported patched userspace version only after checking current security and compatibility evidence. Inline hardware tags in those notes require underlying hardware metadata space and are not established for this raw virtio disk. Cipher, tag size, sector size, key layout, KDF limits, journal mode, header integrity/freshness and growth/recovery semantics need concrete tested defaults before adoption. Bound fixture KDF memory within the existing workload ceiling instead of invoking unconstrained benchmarks/default adaptive allocation. [Cryptsetup 2.8.0 release notes](https://gitlab.com/cryptsetup/cryptsetup/-/raw/v2.8.0/docs/v2.8.0-ReleaseNotes)

Use explicit raw block format; do not probe a guest-writable image and allow it to become a host-file-referencing format. Selected Mac folders and shared instructions/memory/outputs remain plaintext host shares. All private writable environment/data/scratch/SDK stores belong on the encrypted private volume. Public immutable boot artifacts contain no private configuration or secrets. Direct backing reads must show ciphertext; authenticated Winter API requests and running-guest memory remain the existing explicit plaintext residuals. Authenticated sectors do not by themselves prevent replay of old valid snapshots.
